# BGMと環境音の演出注釈（実験計画、2026-10-28）

章の本文が確定した後の「BGM・場面転換の設計」（`music_pipeline._chapter_decisions`）を、環境音を含む形に作り直せるかを試す。効果音は対象外。まだ製品のコードは変えない。

## 1. 背景

### 今の仕組み

- LLMが場面ごとに `play`（新しい曲）・`continue`（今の曲を続ける）・`stop`（無音）を選ぶ。`stop` の場面は、最初から最後までBGMが無い。
- 判断の材料は、作品の文脈と、場面ごとの抜粋（`_scene_excerpt`）。抜粋に入る発話は、最初の3行と最後の3行だけ。場面の途中で何が起きるかは見えない。
- 環境音の仕組みは無い。

### 分かっていること（2026-10-26 の集計）

- 既存12作品・BGM計画103件（再計画を含む）で、`stop` の場面は全体の19%。「鉄と血の叙事詩」「星屑の境界線」「モノノケ・レゾナンス」は約30%で、ほぼ毎章ある。
- `stop` の理由の大半は「場所や空気が変わるので一度止める」。LLMは区切りのつもりで選んでいるが、実際には場面まるごと無音になる。新しい曲には、もともとフェードアウトとフェードインが付いている。
- 理由に「環境音を際立たせる」が多い。LLMは、存在しない環境音を前提にしている。
- 本当に無音を狙った例（祖父の声が届く瞬間、最終的な対峙の対話など）は、場面の中の一瞬を狙ったもの。セリフ単位の手段が無いので、場面全体を `stop` にしていた。
- 選択肢を用意すると、LLMはそれを使いがち。`stop` も、多い作品ではほぼ毎章1つ使われた。

### 環境音の素材（2026-10-27 の試作）

Stable Audio 3.0 Medium（`TrackType: SFX`）で試作した。雨・波・蝉・森の鳥・焚き火・機関室の唸りは使えそう。人の声が入る環境音（雑踏・教室・喫茶店）は外国の雰囲気になる。素材は「人が聞いて選んだもの・ユーザーが生成して確かめたもの・持ち込んだもの」をライブラリにする方針。この実験は注釈だけを扱い、素材の質は問わない。

## 2. 決まりごと（ユーザーの指示）

1. **場面単位で、BGMも環境音も無い状態にはしない。**
2. **演出としての一時的なBGM無しは許す。**（場面の途中で止める）
3. 効果音はまだ扱わない。

## 3. 考え方

- **本文から聞こえる音を見つける判断と、ライブラリから素材を選ぶ判断を分ける。** LLMに環境音の一覧を見せると、一覧に音があること自体が「何か選ぼう」と働く。一覧はライブラリが増えるほど長くもなる。一覧の代わりに、音の出どころの種類だけを示し、本文に根拠があることを求める。
- **作られた音は、素材が無くても害にならない形にする。** 合う素材が無い音は「ライブラリに足りない音」として記録するだけ。どんな素材を用意すべきかの材料になる。
- **「環境音だけ」は、実際に素材がある場面でしか選べないようにする。** 決まりごと1を、答えのチェックではなく選択肢の作り方で守る。
- **件数の上限は書かない。** 数字は目安として受け取られやすい。まず上限なしで、自然な頻度を測る。

## 4. 手順と回答の形

LLMの工程を3つに分ける。どれも章の本文が確定した後のLLMの工程で、同じモデルで続けて行う。

### 工程1: 聞こえる音を書く（章全体で1回）

場面ごとに、場面の間ずっと聞こえている環境の音を書く。環境音の一覧は見せない。

| 欄 | 中身 |
|---|---|
| `scene_id` | 場面ID（場面の数ぴったり・順番どおり） |
| `source` | 音の出どころの種類。`weather`（天候）、`water`（水）、`creatures`（生き物）、`crowd`（人の群れ）、`machine`（機械・乗り物）、`fire`（火）、`none`（なし） |
| `sound` | どんな音か（日本語、短く。`none` なら空） |
| `evidence` | 根拠。その音が聞こえる発話のID、または場所の設定（`location`）。`none` なら空 |

- 基準: その音が本文か場所の設定から、場面の間ずっと聞こえていると言える時だけ書く。気持ちや雰囲気を表す音は書かない。根拠を挙げられなければ `none`。
- 根拠の欄は、発話IDか `location` から選ぶ形にする（自由記述にしない）。

### 工程2: ライブラリと照らし合わせる（章全体で1回）

工程1で音が書かれた場面ごとに、同じ出どころの種類の素材を候補として並べ、合うものを1つ選ぶか「合う素材なし」と答える。

| 欄 | 中身 |
|---|---|
| `scene_id` | 場面ID（工程1で音が書かれた場面だけ） |
| `asset` | 候補の素材ID、または `no_match` |

- 候補は、その場面の出どころの種類で絞る。プロンプトに載るのは、その種類の素材だけ。
- `no_match` の音は、「ライブラリに足りない音」の記録に入る。
- 実験では、試作した音を仮のライブラリにする（下表）。質の良し悪しは問わない。

| 素材ID | 種類 | 説明 |
|---|---|---|
| `rain_light` | weather | しとしと降る雨 |
| `storm` | weather | 嵐（激しい風雨、遠い雷） |
| `waves_calm` | water | 穏やかな波が寄せる浜辺 |
| `cave_drips` | water | 洞窟の水滴と反響 |
| `cicadas` | creatures | 夏の昼の蝉の大合唱 |
| `night_insects` | creatures | 夜の虫の声 |
| `birds_morning` | creatures | 朝の森の鳥のさえずり |
| `crowd_street` | crowd | 街の雑踏、人通り |
| `classroom_chatter` | crowd | 休み時間の教室のざわめき |
| `cafe_chatter` | crowd | 店内の話し声と食器の音 |
| `machinery` | machine | 機械の低い唸り（機関室、宇宙船） |
| `campfire` | fire | 焚き火のはぜる音 |

### 工程3: BGMの設計（章全体で1回。今の設計の置き換え）

#### 場面ごとの音の土台（`scenes`、場面の数ぴったり・順番どおり）

| 欄 | 中身 |
|---|---|
| `scene_id` | 場面ID |
| `arrangement` | 素材のある場面は `bgm` / `bgm_and_ambience` / `ambience_only` から選ぶ。素材の無い場面は `bgm` だけ |
| `new_track` | BGMがある場面で、新しい曲にするか。`false` は「直前の曲を続ける」 |
| `transition` | 場面の切り替えの見せ方（none / dissolve / fade / cut。今と同じ） |
| `reason` | BGMのまとまりと切り替え、環境音の扱いの理由（日本語、短く） |

- 場面ごとに選べる値を、プログラムが工程2の結果から決める。素材の無い場面の選択肢は `bgm` だけなので、BGMも環境音も無い場面は形の上で起きない。
- `new_track: false` の意味は、「直前に鳴っていた曲を続ける。曲がまだ無ければ新しい曲にする」と定める。今の「最初の場面や `stop` の後に `continue` は不可」のような、あり得ない組み合わせが無くなる。環境音だけの場面を挟んで、同じ曲に戻ることもできる。
- 場面ごとに選択肢が変わる形は、Anthropic では文法が大きくなりすぎることがある（`experiments/staging-redesign-test-20261025.md`）。場面は最大8つで欄も少ないので通る見込みだが、他のモデルで確かめる時に最初に見る。

#### BGMを止める瞬間（`music_drops`、0件以上）

| 欄 | 中身 |
|---|---|
| `start_before` | この発話の直前でBGMを止める（章の発話IDから選ぶ）。音楽無しで受け止めさせたい一言・出来事の発話 |
| `resume_before` | この発話の直前でBGMを戻す。`scene_end` なら場面の終わりまで止めたまま |
| `reason` | その発話の何を、音楽無しで受け止めさせたいか（日本語、短く） |

- 件数の上限は、プロンプトにも書かない。0件も正しい答えとして扱う。
  - 回答の形には、暴走を止めるためだけの上限（場面の数）を入れる。ローカルのGemmaでは、回答の形は生成を縛る文法として使われるだけで、モデルが読むことはないはず。APIのモデルにはスキーマが見えるので、他のモデルで確かめる時に効き方の違いを見る。
- 止める場面は `start_before` の発話から決まる。場面IDは答えさせない。
- 止めている間も、環境音は鳴り続ける。環境音がある場面では「環境音だけの瞬間」に、無い場面では本当の無音になる。
- 次の2つは、あり得ない答えとして弾かずに、意味を定めておく。
  - `resume_before` が同じ場面の後ろの発話でなければ、場面の終わりまで止める。
  - 環境音だけの場面で止めても、何も起きない（止めるBGMが無い）。

  どちらも実験で件数を数える。多ければ、回答の形を見直す。

## 5. 指示文の基準

基準は本文に結びつけて書く。特定の作品の例は書かない（失敗例をそのまま写した指示にしない）。要らないものの名前も書かない（試作で、否定の言葉が逆にその音を呼んだ。指示文でも同じことが起きうる）。

- **聞こえる音（工程1）**: 4節のとおり。
- **環境音の扱い（工程3）**: BGMの下に敷くのが基本。環境音だけにするのは、その場の音そのものが場面を支え、音楽を足すとそれを弱める時。場面の切り替わりを示すためには選ばない（新しい曲への切り替えは、アプリがフェードで処理する）。
- **新しい曲**: 場面の劇的な役割や空気が大きく変わる時。続く会話や同じ流れは、同じ曲を続ける。
- **BGMを止める瞬間**: 一言や出来事を、音楽無しで受け止めさせたい瞬間（衝撃、告白、気付き、別れ、笑いの間など）。音楽が鳴っていても成り立つ所には付けない。戻すのは、場面の感情が次に移る所。戻す所が無ければ場面の終わりまで。

## 6. 入力

- 保存済みの `m3_music_plan` の依頼（DBの `job.payload`）を、章ごとに最新の1件ずつ使う。作品の文脈・場所・場面の計画・確定した本文が入っている。
- 場面の本文は、発話の一覧を全行渡す（発話ID、話者、表示テキスト）。重複する `raw_text` は外す。
  - 今の抜粋（最初と最後の3行）では、場面の途中の山場が見えない。
  - 章の長さは2,700〜7,100字。16k の設定に収まる見込み（2026-10-28 の動作確認では、約8,600字の入力が約5,100トークン）。工程ごとに入力トークンを記録する。
- 場所の欄（名前・説明・時間帯・雰囲気）を、場面ごとに添える。

## 9. 見るもの

### 数えるもの

| 項目 | 見たいこと |
|---|---|
| BGMも環境音も無い場面 | 0（形で保証されていることの確認） |
| 聞こえる音が書かれた場面の割合 | 作品・ジャンルごと。日常の静かな場面に付き過ぎないか |
| 聞こえる音の根拠 | 挙げた発話・場所の設定に、本当にその音があるか（読んで確かめる） |
| 出どころの種類の内訳 | どの種類の音が、どのくらい必要とされるか |
| 合う素材なし | 件数と中身。ライブラリに足りない音の一覧になる |
| 照らし合わせの当たり外れ | 書かれた音と選ばれた素材が合っているか |
| 環境音だけの場面の割合 | 今の `stop` の19%（多い作品で30%）から、どれだけ減るか |
| 環境音だけの理由 | 「その場の音が主役」か「区切り」か（理由を読んで分類する） |
| BGMを止める瞬間 | 上限なしでの章ごとの件数と分布、戻し方（途中で戻す・場面の終わりまで） |
| 意味を定めて吸収した答え | 戻す位置が場面の外、環境音だけの場面で止める、の件数 |
| 再実行との一致 | 聞こえる音の有無と種類、音の土台、止める瞬間（前後2行以内）が同じか |
| 入力トークン | 工程ごとに16kに収まるか |

### 読んで判断してもらうもの

章ごとの確認ページを作る。

- 場面ごとに、場所と時間帯、聞こえる音とその根拠（根拠の行を強調）、選ばれた素材、音の土台と理由、今の計画との違い。
- 台本の全行に、BGMを止める・戻す位置の印を入れる。前後の行も読める。
- 章をまたいだ「合う素材なし」の一覧。
- 環境音が場面の途中で変わりそうな所（雨が降り出す等）があれば、記録だけしておく（今回の形では扱わない）。

確認をお願いしたいのは次の3点。全章は多いので、作品ごとに1章ずつ（今の計画に `stop` がある章を優先）を目安にする。

1. 聞こえる音は本文に合っているか。付け過ぎていないか。
2. 環境音だけの場面は、そうする意味があるか。
3. BGMを止める瞬間は効いているか。多すぎないか。

## 10. 終わったら決めること

- この形と基準で製品に入れるか。直すなら、回答の形か、基準の書き方か。
- 止める瞬間が多すぎた場合、どう絞るか（上限を書く以外の方法を含めて）。
- ライブラリに最初から入れる音（「合う素材なし」の記録と、種類の内訳から決める）。
- 実際に鳴らして確かめるか（今あるBGMと試作の環境音を、プレイヤーで何章か流す）。
- 他のモデルでも確かめるか。
- 既存の作品に届ける道（BGMの再設計で付け直す）。
