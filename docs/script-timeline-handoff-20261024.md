## 決めたこと

### 範囲

- 完成後調整の画面に「台本・演出」タブを足す。既存のタブ（表示位置調整・立ち絵・基準音声・BGM）と同じ、下書きの保存 → 調整版を反映 の流れに乗せる。
- 編集だけにする。台詞・地の文の追加・削除・並べ替えはさせない。
  - 理由: 行のIDに BGM の cue、場面転換、イベントCGの区間の端と差分、音声、生成段階の `source_start`/`source_end` が紐づいていて、行を1つ消すとアンカーが宙に浮く。
- 演出は種類で分ける。

  | 扱い | kind | できること |
  |---|---|---|
  | 編集可能 | `expression` | 表情の値を変える、無効にする |
  | 編集可能 | `pause`, `blackout` | 長さを変える、無効にする |
  | 編集不可 | `background`, `enter`, `exit`, `position`, `outfit` | なし（🔒）。状態が後ろの行すべてに効き、`central_cast` などからプログラムで決めているため |

  - 削除はさせず「無効」にする。IDを残すので元に戻せて、アンカーも壊れない。
  - 演出の追加・並べ替えはしない。
  - `focus` はモックに出していない。このタブでは無視する（下の「ローカルのセッションで決めたこと」）。
- BGM と場面転換は既存の BGM タブで編集する。このタブでは区間を表示するだけ。

### 本文と音声

- 編集できるのは、表示テキスト（`display_text`）、読み（`spoken_text`）、声の感情（`voice_emotion`）、話し方（`delivery`）。話者は変えられない。
- 「読みは表示と同じ」のトグルを付ける。表示だけ直して読みが古いまま、という事故を防ぐため。
- 読み・感情・話し方を変えた行は「音声が古い」になる。次のどれかを選ぶまで反映できない。
  - 再生成 → 旧音声と候補を聴き比べ → 「この候補を使う」
  - 「旧音声を使う」
- 表示テキストだけの変更（読みを分けている行）は音声に影響しない。
- 地の文には音声が無い（`script_conversion` で話者のある行にだけ音声を付けている）。

### VN表示プレビュー

- 選んだ行を表示している瞬間の舞台を出す。その行の `before` と `start` の演出を実行した後の状態。
- 再現するもの: 背景、立ち絵、表情差分、衣装、話者以外を暗くする（本番は `talk_focus="brightness"`）、イベントCG、その場にいない声（remote）の顔枠、話者名と本文、ページ数（本文が3行を超えると「1 / 2」）。
- 再現しないもの: アニメーション、フェード、場面転換、暗転、間、BGM、文字送り。
- その行の `after` の演出は、プレビューの下に「後：」としてチップで並べる。
- 本文の編集は画面側ですぐ反映する。演出の編集はサーバーで計算し直す（本番と同じ計算を通すため）。
- ティラノを完全に再現する必要は無い。見た目がイメージできればよい（ユーザーの指示）。

### 画面（モックで合意した形）

- 左: プレビュー、前の行／次の行、その行で流れているBGM名、「後：」の演出チップ、編集パネル。
- 右: 行の一覧。場面ごとの見出し（背景のサムネイル、BGM、場面転換）の下に、台詞と地の文を上演順に並べる。
  - 演出は行の上（前・行頭）と下（後）にチップで付ける。チップの見た目は 編集可能／編集不可（🔒）／無効（点線＋取り消し線）の3種類。
  - 行の左端に2本の帯: 緑が BGM の再生区間、青がイベントCGの区間。始まりの行に「♪ BGM「曲名」」「BGMなし」「イベントCG「題」」と出す。
  - 行の印: 変更あり、音声が古い、候補の選択待ち、読みあり、電話などの声。
  - 検索欄と「変更のみ」で絞り込む。
- 編集パネルのタブは「本文・音声」と「演出（n）」。行の本文をクリックすると「本文・音声」が、演出チップをクリックすると「演出」が開く。
- 上部: 変更の行数、再生成待ちの数、保存済み、「下書きを保存」「調整版を反映」（再生成待ちがあると押せない）。

### 文言

- 説明文は置かない。ユーザーの方針: 既存のUIはくどく、新基盤へ移すときに無駄な説明は全部消す予定。新しく作るUIは最初から最小限にする。
- モックで決めた例: 🔒の演出は「変更できません」だけ、「音声が古い」、「再生成」、「旧音声を使う」、「候補を表示」、「変更済み」、「無効」、「元に戻す」、「変更のみ」、「該当なし」、「N ページに分かれます」。
- 出さないと決めた注意: イベントCG区間の行を直すときの注意、地の文に音声が無いことの説明、演出の追加・並べ替えができないことの説明。

## 内部表現（実装の前提）

- `packages/contracts/script.py` の `Script`:
  - `utterances[]` に台詞と地の文が上演順に並ぶ。地の文は `speaker_id: null`。声の属性（`voice_emotion`、`delivery`、`audio_asset_id`、`remote`）は行が持つ。
  - 演出は `directions[]` に別に置き、各演出が `utterance_id` と `timing`（`before`/`start`/`after`）で行を指す。kind は9種類（background, enter, exit, position, outfit, expression, focus, blackout, pause）。
  - 別リスト: `music_cues[]`（1行に1つまで）、`scene_transitions[]`（1行に1つまで）、`event_cg_segments[]`（開始行〜終了行の半開区間と差分）。
- 実行順は `packages/tyrano_export/compiler.py` の行ごとのループ: ラベル → 場面転換か BGM → `before` → 話者のハイライト → `start` → `[ad_say]` → `after` → クリック待ち。同じ行・同じ timing の演出はリスト順。
- 生成段階（`packages/contracts/m3.py` の `NarrativeScene`）も同じアンカー方式。元の本文 `raw_text` を持ち、各行は `source_start`/`source_end` で本文中の位置を指す。
- LLM が出す演出は focus・pause・blackout・expression だけ（`services/worker/generation/narrative.py` の `_staging`）。登場・退場・移動はプログラム（`_stage_directions`、`_directions`）、場面頭の背景・全員退場・衣装は `packages/narrative/script_conversion.py`。`packages/narrative/staging.py` が重複を消し、`pause` を1行あたり合計1500msまでに収める。

## 実装の足場

- プレビューの土台: `apps/web/src/AdjustmentPreview.tsx`。960×640 の舞台に背景・立ち絵・ダミーのメッセージウインドウを重ねる。座標は `packages/tyrano_export/presentation.py` の `stage_geometry` から来る。今はダミーの台詞が固定なので、話者名と本文を受け取るように広げる。
- 行時点の状態: `compiler.py` の `entry_states()` は、各行が始まる時点（その行の演出の前）の背景・立ち絵・イベントCG・BGMを返す。プレビューには「`start` まで実行した後」が要る。同じ計算の途中でもう一つスナップショットを取る形に広げる。別の関数を書き起こすと本番とずれる。
- 顔枠: `compiler.py` の `remote_frames()` が、その場にいない声の枠に出す切り出し範囲を計算している。
- メッセージウインドウとページ送り: `presentation.py` の `MESSAGE_WINDOW`、本番の見た目は `packages/tyrano_export/player.css`（`#adn-win`、本文3行、`#adn-pages`）。本番は長い本文をページに分ける。モックのページ数は1行約34字の概算なので、実装では本番と同じ測り方にそろえる。
- 下書き: `packages/contracts/adjustments.py` の `AdjustmentSave` は今、人物ごとの設定（`characters`）と場面の BGM（`scene_music`）しか持たない。行と演出の差分を `utterance_id`／`direction_id` をキーにして足す。保存先は `adjustment_draft` の state、反映は `services/coordinator/adjustment_service.py` の `apply`（新しい公開版を作る）。
- 1行の音声の再生成: `m3_voice_clone` ジョブを使える。
  - 生成時の要件（`m3_service.py` の `m3_requirement`）の descriptor に `dialogue_text`・`voice_emotion`・`delivery` が入っている。
  - `adjustment_service._sample` が、descriptor の `dialogue_text` を差し替えてジョブを出す前例。読み・感情・話し方の差し替えも同じ形で渡せるはず。
  - 完了時の照合（`adjustment_service.complete` と `m3_service` で `spoken_text`／`EMOTION_TAGS[voice_emotion] + dialogue_text` を比べている）が、差し替えた値で通るかを確かめる。
  - 今の `apply` は、基準音声の候補が変わった人物の全台詞だけを作り直す。行ごとの候補を採用する道を足す。
- 演出の値の制約: `pause`・`blackout` の `duration_ms` は契約上 1〜10,000。ただし正規化で `pause` は1行あたり合計1500msまで。画面の上限をその行の残りに合わせるか、反映時に正規化を通し直す。
- 無効: `Script` に無効のフラグは無い。下書きには無効として持ち、反映で組み立てる Script からその演出を外す。
- 表情: 絵の無い表情に変えても画面は変わらない（`compiler.py` が絵の有無で飛ばす）。立ち絵タブの表情一覧は本編での使用回数を出しているので、表情を書き換えると数が変わる。
- 長尺化の影響: 章数は3固定でなくなった。章の選択は作品の章一覧から作る。行が数百になる前提で、一覧の仮想スクロールや場面の折りたたみを考える。

## ローカルのセッションで決めたこと（10/24）

- 本文の修正は、公開版の Script だけに反映する。生成段階の narrative や物語の台帳は直さない。
  - 既存の完成後調整も、公開版にしか反映していない。人物設定には書き戻さず、作品の分岐（`fork_service.py`）は STEP2 の下書きと計画から引き継ぐ。分岐で引き継げるのは計画までなので、台本はもともと渡らない。
  - 途中の章から作り直すと、その先の章は全部作り直しになり、調整が消える。ユーザーには予想外に映るかもしれないが、今回の作業とは分ける（ユーザーの判断）。
- ページ数は厳密にしない。本番のページ分けは、鑑賞中にブラウザが文字の幅を測って行う（`player.js` の `paginate`）。結果は見る人の文字サイズや、その場にいない声の顔枠で変わるので、正確な値はもともと一つに決まらない。プレビューの「N ページに分かれます」は目安でよい。
- `focus` は、このタブでは無視する（一覧にもプレビューにも出さない）。ほぼ死に機能だったため（[効かない演出の調査](experiments/dead-directions-20261024.md)）。ユーザーの中では、生成からほぼ削除する方針で固まっている。削除は別のセッションで行う。
  - 同じ調査で、編集できる演出のうち、イベントCG区間の中の表情と場面頭の暗転は、直しても画面が変わらないと分かった。
