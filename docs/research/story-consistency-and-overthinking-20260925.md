# 章間整合性・検査の厳しさ・長考に関する研究調査

調査日：2026-09-25。研究調査と設計上の提案。今回、生成処理の実装変更や実モデルの追加実験は行っていない。

本件の目的は、既に起きた出来事を引き継ぎ、章が進むにつれて状況が変わる物語を生成すること。r9では第1章の状態比較が思考だけで出力枠を使い切り、3章の評価に到達できなかった。検査の精密さと作品の品質を分けて評価する必要がある。

## 1. 最も近い研究：Re³とDOC

**研究結果。** Re³（EMNLP 2022）は、計画、文脈を再提示する執筆、候補の再順位付け、細かな事実矛盾の編集を組み合わせた。§5.1の工程別比較では、計画と候補の再順位付けは筋の一貫性に重要だったが、編集工程の寄与は小さかった。§5.2では、検出・修正の誤りが不要な変更につながる問題も報告している。[原論文・§5.1–5.2](https://aclanthology.org/2022.emnlp-main.296.pdf)

後続のDOC（ACL 2023）は、この時間のかかる編集工程を削除したと§3に明記し、階層的な計画と出来事への追従を強化した。Re³より筋の一貫性・計画との関連性などの人手評価が改善した。ただし複数の変更を含むため、編集の削除だけの効果ではない。[原論文・§3–4](https://aclanthology.org/2023.acl-long.190.pdf)

**本件への適用案。** 細かな状態表の完全な一致を生成の主要な停止条件にする優先度を下げ、既知情報の初出扱い、解決済み問題の再演、出来事の巻き戻りに検査資源を集中する。各章の計画には「既に起きたこと」「今回の新しい変化」「その結果として次に残る問題」を明示する。

**限界。** 英語・旧世代モデルでの結果。当時の編集器の性能不足も影響する。事実検査一般が不要、あるいは検査削除だけで現在の生成が改善する、という証拠ではない。

## 2. 次章の計画は、実際に書かれた内容から更新する：DOME

**研究結果。** DOME（NAACL 2025）は、全体の粗い構成を保持し、既に生成した本文に応じて次の詳細計画を作る。時間付きの知識グラフから必要な記憶を取り出し、計画と本文に渡す。20作品の比較・記憶機構を外した比較で有効性を報告した。矛盾検出器は評価指標として使われており、全ての細部を逐次合格させる生成ゲートとは異なる。[原論文](https://aclanthology.org/2025.naacl-long.63.pdf)

**本件への適用案。** 既存の「予定と実績を分離する」設計を維持し、予定未達なら、成立した出来事を基に後続計画を更新する。本文にない実績を補って帳尻を合わせない。

**限界。** 約7,000語の作品で約200 API呼び出し・約4時間という費用も報告されている。独自の矛盾評価に依存する部分があり、方式全体を導入すれば軽くなるわけではない。

## 3. 文脈は、今書く出来事への依存関係で選ぶ：StoryWriter

**研究結果。** StoryWriter（2025年の確認したプレプリント版）は、因果関係を持つイベントを章に割り当て、現在のイベントに関係する過去の出来事・人物を選んで履歴を圧縮する。構造化したイベント計画を外すと評価が低下した。[原論文・方法と工程別比較](https://arxiv.org/html/2506.16445v1)

**本件への適用案。** コンテキスト長に応じて、今章の前提となる確定イベント、関係人物の知識、必要な原文、直前の本文を優先して渡す。要約は原文への索引として使う。16kは最小目安とし、利用可能な枠が広ければ原文や依存イベントを増やす。

**限界。** GPT-4o-miniによる英語生成の結果。今回の日本語・ローカルモデルでの有効性や最適な圧縮率は分からない。コンテキストの固定上限を決める根拠にもならない。

## 4. 検査役も、重要な問題を見つけるとは限らない

**研究結果。** “Help Me Write a Story: Evaluating LLMs’ Ability to Generate Writing Feedback”（ACL 2025）は、英語短編と破損を加えた版に対する8モデルの批評を評価した。具体的でおおむね正しい指摘を出しても、最大の問題を捉えず、軽微な点に言及することがある。「問題を見つけよ」という指示も、正確さ・問題発見で最良ではなかった。[原論文・§4–6](https://aclanthology.org/2025.acl-long.1254.pdf)

**本件への適用案。** 検査の長さ・指摘数・内部説明の精密さを品質指標にしない。保存済み本文で「重要な破綻を発見したか」「許容できる描写を不必要に止めたか」を測る。

**限界。** この研究は、全ての批評が誤検出であるとは述べていない。未加工の物語にも有効な批判はあり得る。現在使用中のモデルや複数章の検査を直接評価した結果でもない。

## 5. 根拠不足は、矛盾と分ける

**研究結果。** FEVER（NAACL 2018）は、証拠による支持、反証、証拠不足の3分類を採用している。これは、確認できないことを直ちに反証と扱わないための基本的な区別になる。[原論文掲載情報](https://aclanthology.org/N18-1074/)

“When Should LLMs Be Less Specific? Selective Abstraction for Reliable Long-Form Text Generation”（2026年2月、プレプリント）は、不確かな主張を全て削る代わりに、確実性の高い粗い表現へ置き換える方法を提案。事実回答のベンチマークで、保持する情報と誤りの関係を評価した。[原論文・§3–5](https://arxiv.org/html/2602.11908v1)

**本件への適用案。** 原文を保持し、台帳への確定採用の粒度を下げる。今回の写真なら、原文から確認できる「仮止めに着手した」を採用し、「3枚全て完了したか」は未確定として残す。全枚数の完了が次の出来事の必須条件になる時点で、その点を再確認する。

曖昧な数量を勝手に補わず、物語全体を停止させる必要性とは分ける。心情の解釈や登場人物自身の主張も、語り手が確定した事実とは区別する。

**限界。** FEVERは事実検証用のデータセットであり、物語の停止方針を検証した研究ではない。Selective Abstractionの定量評価は事実回答が対象で、日本語創作の台帳への適用は本件向けの提案。本文を曖昧に書き換える案ではない。LLMの自己申告の自信だけを確実性の判定根拠にもしない。

## 6. 「短く考えよ」は上限にならない：s1とOverthinking研究

**研究結果。** s1（2025）のTable 13では、AIME24で短く考えるよう指示した場合、平均思考量が8,033トークンとなり、無指定の6,109を上回った。思考終了を強制して回答へ移るbudget forcingも扱うが、小さい予算では精度低下の例もある。[原論文・§3.1、Tables 11–13](https://arxiv.org/html/2501.19393v1)

“Do NOT Think That Much for 2+3=?”（ICML 2025）は、数学問題で結論が繰り返され、追加の推論が精度にあまり寄与しない過剰思考を分析した。効率化の実験には追加学習を含む。[正式論文](https://proceedings.mlr.press/v267/chen25bx.html)

**本件への適用案。** lowへの期待だけに頼らず、検査対象と「判断不能で終えてよい条件」を定義する。JSONの完全な形をモデルが読むプロンプトにも提示する。その上で思考予算と最終回答の余地を分け、同じ資料で比較する。形式提示は今回の実装監査から得た対策であり、これらの論文の直接の結論ではない。

**限界。** 数学問題・別モデルの結果。Qwen3.8の最適な思考トークン数は決まらない。思考を打ち切っても最終回答や再試行が増える可能性があるため、総トークン・時間・判定取得率を測る。

## 7. 反対側の証拠：検証が役立つ場合もある

**研究結果。** “Large Language Models Can Self-Correct with Key Condition Verification”（EMNLP 2024）のProCoは、質問の重要条件を隠し、候補回答からその条件を復元して検証する。QA・算術・常識推論で、単純な自己修正より改善した。[原論文掲載情報](https://aclanthology.org/2024.emnlp-main.714/)

**本件への適用案。** 検査を一括廃止する根拠はない。何を確かめるのかを限定し、その検査が実際に役立つかを個別に測る。本文修復へ渡すのも、対象箇所、以前の根拠、成立しない条件を特定できた指摘を中心にする。

**限界。** 質問応答の正解復元と創作の整合性は異なる。ProCoをそのまま物語に移植すれば改善するという結果ではない。

## 8. 本件で試す変更案と順序

以下は上記の知見とr9の観察に基づく提案であり、論文が直接実証した停止基準ではない。既存の計画・台帳・引用追跡を生かし、検査結果をどう扱うかから見直す。

| 対象 | 提案する扱い |
| --- | --- |
| 過去の確定事項の巻き戻り、既知情報の再発見、解決済み導入の再演 | 重要な因果・章の進行に影響し、原文の根拠を特定できる場合に修復対象とする。回想、嘘、明示的な変化は考慮する |
| 今章で何も変わらない、次章が前章の結果を使わない | 章単位で進展と接続を検査し、必要なら計画へ戻す |
| 感情の細かな分類、重要でない数量・完了範囲の曖昧さ | 確認できる範囲だけ記録し、残りは未確定。後続の必須条件にならない限り生成を続ける |
| 引用ID、原文一致、版・hash、JSON形式 | コードで厳密に検証する。意味判断と分離する |
| 思考打ち切り、空回答、壊れたJSON | 検査未完了として記録する。意味上の「不明」や合格へ置換しない。再試行は対象縮小など原因に応じたものに限定する |

実験は次の順がよい。

1. r8/r9などの保存本文から、明白な章間矛盾、正常な継続、許容できる曖昧さ、修正版を含む小さな固定評価セットを作る。期待判定と根拠はモデル入力とは分ける。
2. 同じモデル・予算で、現行方式と「重要条件に限定し、根拠不足を区別する方式」を比較する。出力形式の提示は両条件でそろえ、検査方針の差と混同しない。
3. 選んだ検査方式を固定して、思考なし／low、必要なら思考上限の差を比較する。方式・モデル・予算を一度に変更しない。
4. 固定資料で重大矛盾の見逃しと不要停止を確認してから、3章通しで進展・接続・読後感を人が読む。同じ入力とseedを使っても呼出回数の変更で本文は変わるため、単一作品だけで改善を断定しない。

主指標は、重大矛盾の検出率、許容できる本文を止める率、完遂率、章間の進展の人手評価。補助指標として思考・回答を合わせた総トークン、時間、再試行数、モデル切替時間、最終判定を取得できた割合を残す。完遂だけを成功とせず、検査を厳しくしたこと自体も成功としない。

研究全体からは、計画・必要な記憶・重要条件の確認を重視する方向が妥当と考える。停止基準と推論予算の具体値は、今回の日本語作品と使用モデルで決める必要がある。
