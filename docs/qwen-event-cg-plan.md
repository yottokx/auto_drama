# Qwen-Image-2.1によるイベントCGの実装計画

作成日: 2026-10-04（日本時間）

本文確定後にLLMがCGを使う区間と描写内容を決め、採用済み立ち絵を参照してQwen-Image-2.1で生成する。CGの表示中は背景・立ち絵を隠し、台詞・音声・BGMは既存の進行を使う。既存の独立実験を、本編制作・公開・再生へ接続する計画である。

2026-10-04更新: 初期実装を追加した。以下は実装前に合意した計画を残したもので、実際の利用手順・検証結果・制限は [イベントCGの利用と検証](setup/event-cg.md) を参照。完成後調整でのCG追加・範囲編集と立ち絵差分は対象外のまま。

## 1. 合意済みの範囲

- 標準はAnimaによる立ち絵1枚。Qwen-Imageの導入を必須にしない。
- イベントCGの自動生成は既定で無効。設定した上限以内でLLMが必要なCGを選び、上限を使い切ることは目標にしない。
- 同じCGの差分もLLMが判断し、追加差分の上限を設ける。差分を作るために台本の内容を変更しない。
- 内部ではシーン全体への指定ではなく、台詞IDに結び付けた表示区間を持つ。
- 完成後調整でのCG追加・表示範囲編集、台本編集、タイムラインUIは今回実装しない。
- 立ち絵の表情・衣装差分、Qwenによる通常のt2iも別機能とする。これらが未実装でもイベントCGを利用できるようにする。

## 2. 今回提案する初期仕様

上限の適用範囲・初期値・失敗時の扱いは、この計画で具体化する提案である。

| 項目 | 初期仕様案 |
| --- | --- |
| 自動CG上限 `N` | **作品の制作版全体**での基本CG件数。既定0 |
| 追加差分上限 `D` | CG1件あたりの追加画像枚数。既定0 |
| 生成枚数の上限 | 基本画像と差分を合わせて `N × (1 + D)`。再試行の計算量とは区別 |
| 1件の意味 | 一つの基本構図と、その表示区間。大きな構図・カメラ変更は別CGとして数える |
| 区間 | 初期版は同一場面内。シーン途中の開始・終了を許し、重複と章またぎは禁止 |
| 差分 | 表情・視線・小さな動作など。同じ基本CGから個別に生成 |
| 参照 | 採用済みの人物立ち絵。初期版は各人物の標準立ち絵を使用 |
| 実行条件 | 実験で使用した専用Diffusers環境、BF16・CPUオフロード・KVキャッシュ・40ステップ |
| 初期解像度 | 960×640。既存プレイヤーの3:2に合わせる。実験の1024×576とは異なるため実機検証対象 |
| 公開画像 | 背景込みの不透明画像。生成原本も別途保存 |

例として `N=3、D=2` なら、作品全体で基本CGは最大3件、各CGは基本1枚＋差分最大2枚、合計最大9枚になる。CG数0の作品では、CG用LLM・Qwen環境検査・モデルロードを一切追加しない。

作品全体の上限にするのは、章数に応じて想定外に生成枚数が増えるのを避けるためである。設定は制作版の開始時に固定し、共通設定の変更を進行中・公開済みの作品へ遡及適用しない。

## 3. 再利用できるものと未検証のもの

[Qwen画像テストの記録](setup/qwen-image-edit.md)には、2人の立ち絵からのCG生成と、LLMによる台本から画像指示への変換がある。RTX 5090での一例はLLM終了・GPU解放まで20.3秒、画像推論40.4秒、検証・ロードを含む画像処理79.9秒だった。最低VRAM・RAM要件や全場面での速度を示す値ではない。

| 既存実装 | 再利用・変更方針 |
| --- | --- |
| `scripts/image_edit/engine.py` | 固定モデル検証、参照の正規化、Qwen推論、進捗・停止・生成記録を共有backendへ分離 |
| `scripts/image_edit/llm_prompts.py` | 台本を一瞬の情景へ変換する方針を再利用。選択区間と基本CG／人物の参照役割へ対応 |
| `scripts/image_edit/prepare.py`、`setup_runtime.py` | 専用環境と固定済みモデルの準備を再利用 |
| `services/coordinator/music_service.py` | 本文採用後の計画、素材生成、公開時のScript合成の構成を参考にする |
| `packages/tyrano_export/compiler.py`、`transitions.js` | 背景・人物の状態計算と場面切替へCGを追加 |

公開モデルは複数画像の参照に対応し、現行実験も参照を最大10枚に制限している。これは10人の一貫性を保証する意味ではない。差分生成では基本CGも1枚として数える。[公式モデル仕様](https://huggingface.co/Qwen/Qwen-Image-2.1)、[Diffusers公式API](https://huggingface.co/docs/diffusers/main/en/api/pipelines/qwenimage21)

初期版は既存の固定モデルrevision `d26bb61231c349cf6b7896fa83353113880e1ba3` と専用環境を使う。3人以上、基本CGからの複数差分、量子化、RAMピークは未検証。実験のSeed違い3枚は候補比較であり、表情や動作を変えたイベントCG差分の検証とは区別する。

## 4. 制作工程への組み込み

### 4.1 作品全体の配分と章内の選定

現行は前章を公開してから次章本文を制作するため、全章の完成本文を比較してCGを選ぶ方式にはしない。

1. `N > 0` の場合だけ、構成承認後・第1章本文生成前に承認済み全体構成を読み、LLMが全章のCG枠を配分する。正常な配分は合計をNと一致させ、独立した予算artifactとして保存する。利用可能枠を全章へ配り切るが、実生成での使い切りは強制しない。配分採用まで本文生成を待機し、配分完了時点で未着手の章を含む全章の枠を表示する。本文・構成自体は変更しない。
2. 各章の本文・演出注釈の確定後、その章に枠がある場合だけCG計画を実行する。
3. LLMは既存台詞から開始・終了、描く瞬間、登場人物、構図、差分の切替位置を選ぶ。適切な箇所がなければ0件を返せる。
4. 検証した選定結果ごとに、基本画像と差分の英語プロンプト、日本語の短い場面解釈を作る。
5. 参照立ち絵が揃った後に画像生成し、採用結果を公開Scriptへ追加する。

章配分を先に固定して、序盤だけで全枠を消費することを避ける。初期版では未使用枠の自動繰越・公開済み章への再配分は行わない。これは上限の割当であり、その章にCGを必ず出す義務ではない。

LLM処理は、作品単位の配分1回、枠のある章ごとの選定1回、選定CGごとのプロンプト作成1回を基本とする。基本画像と差分の指示は同じCGの問い合わせにまとめる。入力が収まらない章は場面単位に分割してから上限内へ選別し、台詞を黙って切り落とさない。各段階で形式不良の修正は最大1回とする。

CGを既存の台詞単位の感情・演出注釈へ混ぜない。CGだけの再試行で本文・TTS向け感情・基礎演出を作り直さず、BGMの有効・無効にも依存させない。

### 4.2 ジョブと依存関係

新しいジョブ種別は、全体配分 `m3_event_cg_budget`、章の選定・指示作成 `m3_event_cg_plan`、画像1枚の生成 `m3_event_cg` を提案する。

```text
承認済み全体構成 ── CGの章別枠
章本文・注釈確定 ── CG区間と基本／差分の指示を確定
                           ↓
人物の立ち絵採用 ── 基本CG生成・採用
                           ↓
                    各差分を個別生成・採用
                           ↓
既存の背景・立ち絵・音声・BGMと合わせて章を公開
```

通常の背景・立ち絵はCG区間でも生成対象に残す。CGの省略や読み込み失敗、終了後の復帰に使用する。

既存のジョブ取得SQLはメディア順序を種別の列挙で制御している。CGの依存関係に加え、各章で「LLM計画 → Anima素材 → Qwen CG → 音声・BGM」のまとまりを保つよう更新する。GPUを使う工程は共有ロックで逐次実行し、CG用の全プロンプトを確定してからQwenを読み込む。

## 5. 計画・画像・表示データを分離する

`packages/contracts/event_cg.py`を追加し、次を別の契約とする。

| データ | 保存する内容 |
| --- | --- |
| `EventCgPolicy` | N、D、解決済み生成profile、設定の版 |
| `EventCgBudget` | storyline、構成の承認ID/hash、章別枠、配分理由 |
| `EventCgPlan` | production、本文artifact/hash、scene、CG ID、台詞区間、差分ID・切替位置、人物、構図、プロンプト |
| `EventCgResult` | 基本／差分ID、画像artifact、原本・表示用のhash、実行条件と元参照 |
| `EventCgOmission` | 省略した対象、理由、試行記録。成功画像とは区別 |
| `EventCgSegment` | 公開用の区間と採用画像のみ。LLMの未検証結果や実行設定は含めない |

区間は公開Script上で **`[開始台詞の直前, 終了境界の台詞の直前)`** とする。章末までの場合だけ終了境界をnullにできる。LLMには「最後にCGで見せる台詞」を選ばせ、コード側で次の台詞IDへ変換する。文字数・秒数・配列番号を永続アンカーにはしない。

たとえば台詞10〜15をCGにするとき、開始は台詞10、終了境界は台詞16。差分を台詞13で切り替えるなら、台詞13を表示する直前に反映する。台詞15のクリック待ち中もCGを保持する。現在の `timing=after` はクリック待ちより前に実行されるため、CG終了にはそのまま流用しない。

採用時に、IDの所属、本文hash、順序、区間重複、場面境界、差分アンカー、人物と素材の対応、章枠と全体枠を検証する。同一場面の検証は開始台詞と最後に表示する台詞に適用し、場面末まで表示する場合の終了境界には次場面の先頭台詞を許可する。CGと差分のIDは計画採用時に確定し、再試行でも変えない。画像成功数や試行回数で枠を数え直さない。

`Script.event_cg_segments`は空配列を既定とし、空なら保存時に省略する。`AssetReference.kind`へ `event_cg` を追加し、`script.schema.json`も更新する。既存のCGなしScriptや保存位置の識別が不用意に変わらないことを検証する。

## 6. プロンプトと参照画像

- 選定は章の流れを参照し、描画用プロンプトは選択区間と直前直後の必要な文脈から作る。後の展開や別の瞬間を一枚へ混在させない。
- 台本は出典として保存しても、画像モデルへ本文・台詞を転載しない。人物の動作、表情、視線、配置、場所、光、カメラを描画指示へ変換する。台詞の文字・字幕・吹き出しは描かせない。
- 画面下のメッセージ欄を考慮して主要人物の顔を配置する。採用済み参照にない人物を、画像指示の都合で追加しない。
- 参照manifestに `reference_index`、`role=character|base_cg`、`character_id`、将来用の `outfit_id`、`artifact_id`、`sha256` を持たせる。初期版の衣装は標準立ち絵として明示する。
- 参照順と人物対応を固定し、Workerはartifactから取得・hash照合する。Coordinator側のローカルパスを他Workerへ渡さない。人物参照を減らした際に番号だけを黙って詰め直さない。
- 基本CGは人物立ち絵を参照する。各差分は同じ基本CGと必要な人物立ち絵を参照し、構図・背景・衣装を維持して変更点を指示する。差分Aを差分Bの元にしない。
- 差分用の参照では基本CGを「人物画像1」と説明しない。既存の人物参照専用テンプレートを拡張する。
- 必要な人物参照が用意できない場合、その人物をテキストだけで作り直す代替は行わず、対象CGを省略する。

LLMの有効な指示が得られなければ、そのCGを省略する。台本の直接投入や定型文による画像生成には戻さない。

## 7. Qwenの実行と再開

### 7.1 共有backendとGPU所有

実験GUIを本体から操作する構成にはしない。推論・参照正規化・モデル検証を共有backendへ切り出し、実験GUIとWorkerから呼び出す。専用環境は `services/worker/runtimes/qwen_image_edit/` を維持し、Qwen用依存をCoordinatorやAnima環境へ追加しない。

現在の実験engineは子プロセス内でGPUロックを取得する。一方、本体は親Workerが保持するため、単純に既存runnerを起動すると二重ロック待ちになる。共有推論部分からロック所有を分離し、本体ではQwen専用sessionが一箇所で所有、実験では既存adapterが所有する。

画像1枚を1ジョブ・1採用単位とし、Qwen専用session／runnerで同じCGの連続ジョブ間だけモデルを短期再利用する。基本CGの採用後、その画像を参照する差分ジョブを実行する。モデル検証とロードもsession内で共有し、1枚ごとに約33GBの全ファイル検証とロードを繰り返さない。

Anima・LLM・TTS・音楽の常駐モデルを解放してからQwenをロードする。別工程への切替、待機上限、キャンセル、例外では子プロセスの終了を確認してロックを返す。単体ジョブでの正しさを先に検証し、短期再利用を加えても採用・再開の粒度を変えない。

### 7.2 停止・再試行・省略

- 各画像に固定入力のfingerprintを持たせ、同じ依頼の再送では保存済み結果を再アップロードする。別Workerでの再開も採用済みartifactを利用する。
- Workerは途中完了画像と記録をatomicに保存する。採用済み基本CGを、後の差分失敗で作り直さない。
- 画像のモデル／データ由来の失敗は初期版で自動再試行しない。LLMの形式修正は最大1回。OOM時も解像度・精度・Seedを黙って変更しない。
- 有限回の処理で失敗が確定した対象には `EventCgOmission` を保存する。基本CGが省略なら子差分も省略、差分だけが省略なら直前の正常画像を表示し続ける。
- 全体配分・章内計画が修正後も無効なら、理由付きの0件計画として確定する。
- ユーザー中断、通信障害、lease失効、Workerの一時不在は生成品質の失敗と混同せず、既存の停止・再送・再開経路で扱う。
- 省略は制作詳細へ件数と理由を表示する。成功と偽装せず、章の公開条件上は処理済みにする。

現行の公開条件は全requirementのartifact採用を要求する。単にCGジョブをfailedにするだけでは章が永久に止まるため、省略artifactの採用まで含めて実装する。認証・所属・hash不整合のある結果は省略への近道にせず、不正な採用として拒否する。

公開された章は固定する。省略して公開したCGを後から自動再試行して差し替える機能は、今回の範囲に含めない。明示的な中断からの再開と、確定した省略からの再生成を区別する。

### 7.3 出力と性能記録

実験のCGにはアルファ250〜255が含まれたため、生成原本は保持し、表示用に不透明画像を作る。ほぼ不透明な出力はRGBへ正規化し、大きな透明領域や破損・寸法不正は不適合として扱う。背景除去は行わない。

prompt、参照順とhash、基本CG／差分の親子関係、Seed、モデル・runtime・schemaの版、ロード／推論／解放時間、GPU割当・予約ピーク、プロセスRAMピークを記録する。量子化は計算dtypeとは別のprofile項目として拡張できる形に留め、初期版では選択肢として提供しない。

## 8. 再生・書き出し・履歴

CG表示は独立した状態として扱う。CG中も通常の背景、人物の登退場・位置変更を論理状態へ反映するが、その描画命令を抑止する。終了時は開始時の画面ではなく、終了境界の時点の通常状態を復元する。

`compiler.py`の `scene_stage_data()` をCGの開始・差分・終了境界にも拡張し、`transitions.js`で先読み・切替・復帰を一括実行する。台詞・音声・BGMをCG切替だけで再開始・停止しない。暗転・間の既存演出は表示モードと組み合わせ、背景や人物を漏らさない。

CG表示中の保存・ロード、スキップ、リスタート、章切替を実装範囲に含める。表示中のCG ID・差分IDと台詞アンカーから状態を復元し、DOMだけに状態を持たせない。画像読み込み失敗時は該当時点の通常表示へ戻す。

エクスポートの素材ディレクトリとmanifestへCGを追加し、単体ZIPでも同じ表示を行う。公開前に全参照とhashを検証する。

履歴・公開版にはCG設定、計画、採用画像、省略結果を固定する。履歴閲覧・復元ではCG生成を開始しない。既存の立ち絵やBGMの完成後調整による再出版でも、採用済みCGを保持する。立ち絵を変更しただけでCGを自動再生成せず、CGが参照した画像の版を記録しておく。

## 9. 設定と進捗UI

- 作品側のN・DはSTEP4の構成承認前に編集できるようにする。現行は構成承認で制作が始まるため、STEP5にだけ設定を置かない。
- 設定画面にQwenの実行profileと準備状態を追加する。画像モデルの設定をLLMのGGUF一覧へ混ぜない。
- 初期版の環境・モデル準備は既存のセットアップ機能を再利用する。新しい汎用画像モデル管理・ダウンロードUIは今回増やさない。
- Nが0なら準備不要。Nが正の場合だけ、対応Worker・runtime・モデルの準備状態を確認する。不足時は理由を設定欄に表示し、CGを有効にしたままの承認・制作開始を止める。ユーザーは準備を完了するか、Nを0にして通常制作を選べる。開始後の一時的なWorker不在は待機として扱う。
- 制作開始時にpolicyと解決済みprofileを保存する。N・D・profileを変える場合は次の制作版に適用する。
- 制作画面に「CG選定」「基本CG」「差分」の進捗、採用数／上限、省略数と理由を表示する。内容に触れる解釈・プロンプトは制作詳細に置く。
- 完成後調整へCG編集ボタンやタイムラインを追加しない。

| 段階 | 主な変更箇所 | 完了条件 |

| 2. 設定・保存・制作への接続 | `services/coordinator/event_cg_service.py`（新規）、migration、`m3_service.py`、`m4_service.py`、`planning_service.py`、`project_history.py` | N=0の旧動作維持、設定固定、予算・ジョブ・省略・再開を模擬Workerで確認 |
| 3. LLM計画 | `services/worker/generation/event_cg_pipeline.py`（新規）、共有prompt処理、LLM profile/schema | 本文を変えず、実在する区間と参照人物を選択し、上限内の画像指示を生成 |
| 4. Qwen生成 | 共有Qwen backend、`event_cg_session.py`／`event_cg_runner.py`（新規）、`client.py`、`m3_pipeline.py`、session分類・ジョブ取得順序 | 参照取得、基本→差分、画像ごとの採用、停止・GPU解放・短期再利用を確認 |
| 5. 設定・進捗画面 | `SettingsDialog.tsx`、`PlanningReviewPanel.tsx`、`ProductionPanel.tsx`、`productionState.ts`、API型 | 承認前のN・D設定、optional環境の準備状態、進捗と省略理由を操作できる |
| 6. 実機評価と文書化 | integration/browserテスト、実生成記録、setup文書 | 品質・VRAM・RAM・時間を確認し、利用条件と未解決点を記録 |

Coordinatorの新serviceで計画と結果をまとめ、公開時に `add_to_script()` で合成する。本文生成の `NarrativeResult` はCGのために改変しない。新ジョブの追加は、contractsの列挙、claimの依存SQL、`uses_llm`、Worker capability、各モデルsessionの切替、bundle検証、API進捗型まで通して行う。

## 11. 受け入れ条件

1. **無効時の互換性**: Qwen未導入で従来どおり制作・再生できる。N=0ではCG用LLM・環境検査・追加ジョブなし。旧作品にCGが後付けされない。
2. **上限と入力の固定**: N・D・章枠、別章／別版ID、未知人物、不正区間、重複採用を検査。再送・再開で枠を二重消費しない。
3. **表示**: シーン途中の台詞境界でのCG開始・差分・終了、隣接CG、シーン先頭・章末、CG中の登退場、音声・BGM継続、最終台詞のクリック待ちを確認。
4. **復元**: CG途中の保存・再開、スキップ、章切替、画像読み込み失敗、履歴復元、立ち絵／BGM調整後の再出版、ZIP再生を確認。
5. **失敗と停止**: 計画失敗・基本画像失敗・差分失敗がそれぞれ決めた表示へ解決され、公開待ちで止まらない。ユーザー中断や通信障害は省略確定にしない。二重GPUロック・他工程との同時常駐がない。
6. **実画像**: 1人・2人の基本CG、同じ基本CGからの2差分を少数Seedで評価。顔・髪・衣装・人数・構図・差分間の一貫性と、台本の文字画像にならないことを目視確認。3人は別の品質確認項目とし、未評価を保証に変えない。
7. **負荷**: モデル切替、初回ロードと再利用、推論、VRAM、RAMを計測する。GPU実行が完了しただけで品質や最低動作要件を確定しない。
