## 分かったこと（要点）

### 長尺化そのもの

- 5章・6章・8章とも、STEP4からSTEP5の台本まで破綻なく完走した。32kで8章も溢れない。64kにすると章の境目のつながりと章の長さのそろい方が良くなり、生成時間はほぼ変わらなかった。
- 製品の今の計画（キャスト計画 → 出来事の連鎖 → 章への配分）は、章数を増やしても連鎖の出来事が増えない。章が薄まり、同じ主題の繰り返しと次の章の先取りが起きる。
- 2段の計画（今の連鎖を骨組みにし、章ごとに手順を足す「肉付け」）で、章数に比例して中身が増えた。そのうえで次を足すと章の長さがそろう。
  - 配分のバランス化（`--balanced`）: 出来事の切れ目での区切り方を、手順数のばらつきが小さい順に30通りコードが挙げ、モデルが製品の `sized_allocation` の指示文で選ぶ。
  - 肉付けの上限（`--expansion-steps 6`）。
  - 骨組みの言い換え・前振りの禁止（`--distinct-steps`）。
  - 前の章と同じ役回りの禁止（`--fresh-roles`。作品の例は外した一般的な言い方）。
- 残る問題（どれもコンテキストの量ではない）:
  - 主題の語り直し（同じ決意を章をまたいで言い直す）。
  - 途中で消える糸（鉄と血の「近隣の村との食料契約」は64kでも拾われない。プロットが後の章に手順を持っていない）。
  - 肉付けで足した手順を本文が広げ、次の章の予定と食い違う（ひだまりの結衣が誘いに乗ったのに来ない）。
  - 語彙と、地の文での主題の解説の繰り返し（ひだまりの「心地よい」）。
- 3章で肉付けすると章が目安の1.7倍に伸びる（手順が多いと場面計画が場面を増やす）。
- 16kの2章（コンビニ）は収まるが、最終章の場面計画の入力が9,207（上限9,728）でぎりぎり。ユーザーは「元は3章・16kで普通に生成できていた」と気にしている。

### 章数の判定

- キャスト計画の後、連鎖の前に「1話約10分で何話が適切か」を判定させる案。STEP3の確定時に目安の章数を示し、それを可変章数の元にする考え。
- 持続力・構造・個性で見立てさせる依頼（`--prompt criteria --cap 8`）は、調整に使った5作品では Gemma 推論なしが5作品とも目安に入った。調整に使っていない5作品では2作品だけで、ほぼ+1〜2話長い（生成されたサブを全員「見せ場を持てる人物」に数える）。
- ユーザーはこの長めの判定を「そういう解釈があってもおかしくはない」と受け入れた。ただし16kでは長いと厳しくなる点は考慮が要る。
- 実際に台本まで書いた章数: 鉄と血6章、ひだまり4章、コンビニ2章（いずれも判定どおり）。

### 最終章の締め

- コンビニの2章版で、最終章の場面計画が骨組みの最後の2手順を落とし、落ちが無いまま終わった。場面と手順の照合（9月の r7〜r8 の `placements`）は初期に失敗して外した経緯があり、ユーザーは入れたくない。照合ではなく指示で直す方向。
- 案B（`--closure-plan`）: 場面計画に、核心の外的な決着と人物・関係の着地の文を渡して最後の場面をそれで終わらせる。コンビニは直ったが、締めが元々できていた作品で、前の章で済んだ決着の演じ直し（鉄と血5章のゼノス）や、章の中での着地の重複が出た。
- 案1（`--closure-end`、今の第一候補）: 核心の文を渡さず、「最終章です。最後の場面の終了状態を、当章の予定の最後の手順の結果にします。」だけを伝える。
  - コンビニは2シードとも落ちが入った。
  - ひだまりは副作用なし。
  - 鉄と血5章は、ゼノスとの言い合いが案Bの半分ほどの量で残った。第4章が最終章の手順を先取りしていて、残った最後の手順がゼノスのものだった。古い作り方（バランス化・肉付けなし）の実行でだけ出ている。
  - 鉄と血6章は、エレナの着地が2回のまま。指示なしでシードを変えると1回だったので、指示の側から来ている（締めの場面に着地が集まり、冒頭でも一度着地させる）。
- 肉付けで締めの後ろに手順を足させない制限（`--final-closure` の①）は、コンビニでは結果に影響しなかった（足した手順は元から締めより前に置かれていた）。
  - 訂正（2026-10-21）: コンビニだけの話だった。言い換え禁止ありの5本のうち4本（ひだまり4章、鉄と血6章・8章）は、最終章の肉付けが締めの後ろに手順を足していた。案1のひだまりと鉄と血6章は、その足した手順で章を終えていた。①＋案1（`--closing-step-last --closure-end`）をひだまり4章で試すと、最後の場面が骨組みの締めで終わり、着地の重複も出なかった（実験記録の「締めの手順を最後に固定した案1」）。
- 前のセッションの最後に私が勧めたのは、案1で締めの対策を決め、ゼノスの件は先取り（章の境目）の問題として保留、エレナの重複は軽い副作用として扱うこと。ユーザーはまだ決めていない。

## 実験の足場

- `scripts/story/check_text_long.py`: 製品の流れを N 章にして台本まで書く。主なオプション:
  - `--chapters N`、`--context-size`、`--skip-staging`、`--model-id`、`--seed`、`--chapter-limit`、`--plot-only`、`--resume`。
  - 計画: `--expand`、`--balanced`、`--expansion-steps`、`--distinct-steps`、`--fresh-roles`。
  - 締め: `--final-closure`（①＋案B）、`--closure-plan`（案Bだけ）、`--closure-end`（案1）、`--closing-step-last`（①だけ。`--closure-end` と一緒に使う）。
  - 再利用: `--plot-from DIR`（キャスト計画・連鎖・配分・肉付けの採用済みの回答を読み込み、プロットを完全に一致させる）、`--cast-from DIR`（その `cast-plan.json` をキャストにする）。
- `scripts/story/drop_last_chapter.py SRC TARGET [--shift N]`: 書き終えた実行から最終章の分だけを消した複製を作る。依頼の通し番号を最終章の最初の依頼の手前に戻すので、同じオプションで `--resume` すると最終章が同じシードで書き直される（シードは入力のシード＋依頼の通し番号）。`--shift` でずらすと最終章だけ別のシード。`--seed` を変えた再開は、製品の来歴の確認で拒まれる。
- `scripts/story/probe_chapter_count.py`: 章数の判定。`--prompt plain|fewshot|capacity|criteria`、`--cap`、条件 gemma / gemma-thinking / qwen / qwen-medium、`--works DIR`（`inputs/<作品>.json` と `<作品>-open/cast-plan.json`）。Gemma の推論ありは製品の `RoutedLLM` が止めるので、その条件だけ `LocalLLM._chat_request` で回避している。
- 入力:
  - 鉄と血: `outputs/cast-size-20261017/inputs/tetsu-qat-product.json`。
  - ひだまり: `outputs/long-form-20261020/inputs/hidamari.json`。
  - コンビニ16k: `outputs/long-form-20261020/inputs/konbini-16k.json`（キャストは `outputs/variable-chapters-20261019/konbini-open`）。
- 出力: `outputs/long-form-20261019/`、`outputs/long-form-20261020/`（各実行の `story.html` で読める）。締めの比較は `*-closureplan`（案B）、`*-closureend`（案1）、`konbini-ud-2ch-16k-closureend-s2` と `tetsu-ud-6ch-distinct-s2`（別シード）。

## 作業上の注意

- ユーザーとのやり取りの決まり（メモリにもある）:
  - 説明・途中経過・wrap_up はすべて日本語。wrap_up は recap だけで、質問やボタンは使わない。質問は本文に書く。
  - 設計の相談中は、実装を提案して終わらない。
  - 頼まれた範囲だけを回す。モデル・推論の有無・腕を足すときは、先に一行で聞く。
  - 失敗した作品の例をそのまま指示文に書く直し方はしない。一般的な規則にして、他の作品で確かめる。
  - 長い生成では、章が終わるたびに短く報告する（ユーザーが進み具合を見たい）。
  - 日常ものの遅い流れは意図どおり。出来事の少なさではなく、遅さをどう書けているかで見る。
- 実行: 生成は1本ずつ順番に（GPUは1つ）。長いものはバックグラウンドで回し、終わりを待つのは Monitor か `run_in_background`。`sleep` を前に置いたコマンドは拒まれる。
- Bash のヒアドキュメントで Python を書くとバックスラッシュが消えるので、Edit か Write を使う。
- テストと実データの扱いは前の引き継ぎの「作業上の注意」のとおり。
