# 効かない演出の調査: focus を中心に（2026-10-24）

完成後調整の「台本・演出」タブ（[引き継ぎ](../script-timeline-handoff-20261024.md)）の設計中に、focus 演出の扱いを決めるために調べた。focus は画面にほとんど効いていないのに、演出付けの出力トークンの約4分の1を占めている。ほかの演出についても、外しても見た目が変わらないものを数えた。コード・設定は変えていない。新しい推論もしていない。

対応は別のセッションで行う。focus は、ユーザーの中で生成からほぼ削除する方針で固まっている。台本・演出タブでは focus を無視する。ほかの演出の対応方針は決めていない。

## 結論

- **focus は種類ごと、実質的に死に機能になっている。** 保存済みの台本にある 7,781 件のうち、画面に効いているのは 53 件（1%未満）。残りはほぼ全部、話者自身を指している。話者は毎行自動で明るくなるので、効果が無い。
- 効いている 53 件は、ほぼすべて「その場にいない声」の行で、舞台にいる聞き手を明るくする使い方。ほとんどが1作品（「凪の島の電波塔、嵐の夜のささやき」）に集中している。
- **focus は演出付け（`script-staging`）の出力トークンの約25%を占める。** 演出付けは章の制作の LLM 出力の55〜63%を占めるので、章の制作全体の LLM 出力では約14〜16%にあたる。
- LLM が出すほかの演出にも、効かないものがまとまってある。
  - イベントCG の区間の中の表情: 378件。CG が立ち絵を隠しているあいだに変わり、CG が終わる前に上書きされる。
  - 舞台にいない人物の表情: 66件。次の登場で表情が初期値に戻る。
  - 場面頭の暗転: 98件。コンパイラが捨てている。
  - pause はすべて効いている。
- 表情の絵が無いので今は効かない表情が 1,644 件ある。立ち絵タブで絵を足せば効くので、死に機能ではない。
- プログラムが入れる演出にも重複がある（`exit` 1,990件、`background` 181件）。場面頭で全員を退場させてから登場し直させる処理と、前の場面と同じ背景を指定し直す処理によるもので、害は無い。

## focus の仕組み

focus は `[chara_ptext name="ad_<人物>"]` を出す演出。`[chara_config talk_focus="brightness"]` により、指定した人物が明るくなり、ほかの人物は暗くなる。

`packages/tyrano_export/compiler.py` の行ごとのループは、次の順で進む。

`before` の演出 → 話者の自動ハイライト → `start` の演出 → 本文 → `after` の演出

自動ハイライトは、ふつうの行では話者を明るくし、その場にいない声の行と地の文の行では全員を暗くする。このため、focus の効き方は timing で決まる。

| timing | 効き方 |
|---|---|
| `before` | 直後の自動ハイライトに上書きされる。どの人物を指しても効かない |
| `start` | その行のあいだ、自動ハイライトの代わりに指定した人物が明るくなる。話者を指すと自動ハイライトと同じ結果になる |
| `after` | 本文を出し終えた後に、明るい人物が切り替わる |

次の行では、また自動ハイライトが入る。focus はその行で完結する演出で、後ろの行に状態を残さない。

### 生成での扱い

- LLM が出す演出は focus・pause・blackout・expression の4種類（`services/worker/generation/narrative.py` の `_staging`）。
- 指示文には「focusのcharacter_idは必ず登場人物IDで空文字禁止」「NARRATORの行にはfocusを付けません」とあるが、focus を何に使うかは書いていない。
- `FocusAnnotation` は `duration_ms` を必須にしている。しかし台本への変換（`packages/narrative/script_conversion.py`）で、focus の `duration_ms` は捨てている。
- 演出の検証では、舞台にいない人物への focus と、その場にいない声の話者自身への focus を落としている。
- 話者の自動ハイライトと focus は、どちらも最初のスナップショット（`333614d`、2026-09-27）から存在する。

## 調べ方

### 台本の演出

- 対象は `data/` に保存されている `script.json` 192件（39作品）。同じ章の作り直し版も含む。中身が同じものは1件として数えた。
- `scripts/story/dead_directions_report.py` で、演出を1つずつ外した台本を作り、見た目が変わるかを比べた。
  - 見た目を取るのは、各行の本文を表示している間（`before` と `start` の後）と、`after` の後の2か所。
  - 比べるもの: 背景、舞台にいる人物と位置、衣装、表情の絵、明るい人物。CG の区間では CG だけを比べる。その場にいない声の行では、顔枠の衣装も比べる。
- 表情は2通りで判定した。
  - 作品にある表情の絵だけで変わらなければ「絵が無いので今は効かない」。
  - すべての表情に絵があると仮定しても変わらなければ「効かない」。
- pause と blackout は時間の演出なので、コンパイラが捨てる場合だけを「効かない」とした。pause は長さが0のとき、blackout は場面転換の行の `before`・`start` のとき（`compiler.py` の `scene_entries` の条件）。

### 出力トークン

- 対象は `outputs/` と `tmp/` に残っている演出付けの LLM 応答（`*-staging-*.json`）1,702件。推論ありの応答は除いた。
- 手元に Gemma の tokenizer が無いため、応答ごとの実際の出力トークン数を、英数字の字数と、それ以外の字数で当てはめて推定した（`scripts/story/focus_output_tokens.py`）。
  - 当てはめの結果は、英数字1字あたり 0.357 トークン、それ以外の1字あたり 0.988 トークン。誤差は応答ごとの平均で5.4%。
  - focus の注釈はすべて英数字なので、その字数から focus のトークン数を出した。
- 章の制作全体に占める割合には、`outputs/cast-size-20261017` のうち製品と同じ設定で章を作った2回（`e2e-hidamari-ud-product`、`e2e-tetsu-qat-product`）の工程別の出力トークンを使った。
- 測ったのは出力トークンだけ。指示文の中の focus の説明（入力トークン）と、focus が原因で弾かれたときの再試行は含めていない。

## 結果

### focus

| 使われ方 | 件数 | 画面への効果 |
|---|---:|---|
| `start` で話者自身 | 6,600 | なし |
| `before` で話者自身 | 1,113 | なし |
| `after` で話者自身 | 4 | なし |
| `before` で話者以外 | 8 | なし（自動ハイライトに上書き） |
| `start` で話者以外 | 56 | 53件で効いている。3件は、指定した人物が舞台にいない |
| 地の文の行 | 0 | — |

`start` で話者以外を指す 56 件のうち、54 件はその場にいない声（無線・留守電）の行だった。51 件が「凪の島の電波塔、嵐の夜のささやき」、3 件が「鉄と血の叙事詩」。たとえば、無線で湊が話しているあいだ、舞台にいる海斗を明るくしている。こうした行は自動ハイライトで全員が暗くなるので、聞き手を明るくするには focus しか手段が無い。

残りの2件は、ふつうの会話の行（「ひだまり1年1組」）。話しかけている凛花ではなく、話しかけられた側が明るくなっていて、付け間違いに見える。

## 台本・演出タブへの影響

- focus をチップで出すと、ほぼ全行に効果の無いチップが付く。タブでは focus を無視する。
- 編集できる expression と blackout のうち、CG の区間の中の表情と、場面頭の暗転は、直しても画面が変わらない。

## 別の場所で検討すること

- focus の削除（ほぼ削除する方針）。削除にあたって考えること:
  - 効いている使い方は「その場にいない声の行で、舞台にいる聞き手を明るくする」だけ。この使い方はプログラムで決められる可能性がある。ただし、誰を聞き手とするか（舞台にいる人物が複数のとき）は決める必要がある。
  - 決まりに置き換えてコンパイラで処理する場合、既存の作品にも「調整版を反映」（今のプレイヤーで全章を組み立て直す）を通して入れられる。
  - 生成をやめても、既存の台本に残っている focus は、ほぼ画面に効かないので、残したままでも害は無い。
- `FocusAnnotation` の `duration_ms` は、使わないのに必須になっている。
- 場面頭の無意味な退場（`script_conversion.py` が場面ごとに全員を退場させ、直後に同じ人物を登場し直させる分と、もともと舞台にいない人物の退場）。focus の削除と一緒に対応するかもしれない（ユーザー、10/24）。台本・演出タブでは、同じ行・同じ timing の退場を1つのチップにまとめて表示している。
- CG の区間の中の表情。演出付けの時点で CG の区間が決まっているかは確かめていない。
- 場面頭の暗転を LLM に出させないか、場面転換の指定に生かすか。
- 測り直すときは、上の2本のスクリプトをそのまま使える。判断の基準は Gemma 4 31B UD の推論なしの結果とする。
