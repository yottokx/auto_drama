# 外部LLMの推論の有無と、演出をツール呼び出しで答えさせた場合（2026-10-25）

Phase 2（`external-llm-phase2-20261025.md`）では、推論なしの GPT-6 Luna と Haiku 5.5 の台本が物足りず、とくに演出（`directions`）がほとんど付かなかった。原因が「推論なし」か「構造化出力の形（ツール呼び出しでない）」かを見るため、保存済みの依頼を条件を変えて送り直した。

## 条件

- 入力: Phase 2 で完成した2本（GPT-6 Luna・ひだまり、Haiku・鉄と血）の保存済みの依頼から、演出4件・場面の本文2件・場面計画2件。両モデルに同じ依頼を送った（`outputs/external-llm-20261025/reasoning-probe/`）。
- 条件: 推論 `none` / `low` / `medium`。演出だけ、推論なしで「回答を1つの関数の引数として渡す」形（OpenAI は strict な関数、Anthropic はツールを指定して呼ばせる）も加えた。
- 出力上限は、依頼に保存されていた値のまま（16kの段の値）。
- 費用: $0.10（上限$0.10で止めたため、Haiku の鉄と血の場面計画の `low` / `medium` は未実行）。
- 各条件1回ずつで、件数は少ない。

## 演出

| | GPT-6 Luna | Haiku 5.5 |
|---|---|---|
| 発話1件あたりの演出（構造化出力・none / low / medium） | 0 / 0 / 0（4件すべて） | 0.15 / 0.13 / 0.10 |
| 同じ・関数の引数で答えさせた場合（none） | 0.78（ほとんど focus） | 0.45（表情・間・focus） |
| 表情・声の調子・言い方の記入 | 条件で差はほぼ無い | 条件で差はほぼ無い |

- 推論を入れても、演出は増えなかった。
- 関数の引数で答えさせると、演出が増えた。ただし GPT-6 Luna で増えたのは、画面にほとんど効かない focus（`dead-directions-20261024.md`）が中心。
- 「ツールの形でないと反応しない」わけではない。発話ごとの感情・表情・言い方は、どの形でも同じように埋まっていた。差が出たのは、空でもよい配列（`directions`）にどれだけ書くか。
- GPT-6 Luna は推論なしの演出1件で、JSONの前に英語の考えごと（"We need output schema. Need annotate narrator rows neutral, …"）を書き、JSONとして読めなかった。strict の形式を指定していても防げていない。Phase 2 の「終わりの印を書いてJSONを繰り返した」崩れも、同じ種類の漏れと見られる。推論 `low` / `medium` ではこの漏れは無かった。

## 場面の本文

| 依頼 | 条件 | GPT-6 Luna | Haiku 5.5 |
|---|---|---|---|
| ひだまり（上限2,048） | none / low / medium | 1,393 / 1,225 / 1,113字 | 1,393字 / 上限到達（1,672字で途中）/ 推論で上限を使い切り本文0字 |
| 鉄と血（上限6,144前後） | none / low / medium | 2,547 / 612 / 1,550字 | 1,429 / 2,864 / 2,532字 |

- Haiku は推論ありで、場面の中身が具体的になった。鉄と血では、エレナが図面を巻き取って補修班に号令をかける行動や、東門に残す人数・本城まで抜かれる時間のやり取りが入り、長さも約2倍。
- 推論は出力上限を消費する。16kの段の上限のままでは、Haiku の短い場面は推論 `medium` で本文が書けなかった。推論を使うなら32k以上の段（出力上限が増える）が前提になる。
- GPT-6 Luna は、推論で本文が良くなる傾向は、この2件では見えなかった（鉄と血の `low` は612字と短い）。

- 構造化出力の違反はどの条件でも0。

## 出力トークン

推論 `medium` は、推論なしの約2倍の出力トークンを使った（演出で約1.5〜2.3倍、場面計画で約2〜5倍）。

## 分かったこと

- 物足りなさの主な原因は、推論なしで動かしていたこと。とくに Haiku の本文と計画は、推論を入れると密度が上がった。
- GPT-6 Luna の推論なしは、考えごとや終わりの印が回答に漏れることがあり、不安定。推論 `low` 以上なら漏れは見られなかった。
- 演出の少なさは推論では変わらない。回答の形（空でもよい配列を、構造化出力では最小限にする）による。ツール呼び出しで増える分は focus が中心で、効く演出はあまり増えない。
- 推論を使うには、出力上限に余裕がある32k以上の段が要る。

## 32kの段・推論 `low` で作品を通しで生成

Phase 2 と同じ2作品を、`--context-size 32768 --cast-limit 8 --product`、推論 `low`、3章、シード1で生成した（入力は `outputs/external-llm-20261025/inputs/*-32k-low.json`、出力は `*-32k-low` と `*-32k-low-v3`）。

### 途中で直したこと

最初の4本のうち、GPT-6 Luna・ひだまりと Haiku・鉄と血が、場面の本文で、その場面の登場人物でない人物（それぞれ `c5`、`character-ecb39aa7…`）に台詞を与えて失敗した。場面の本文の指示文は「各行は『人物ID: 本文』」と書くだけで、話せるのが場面の登場人物だけとは書いていない。Gemma では grammar が話者を限っていた。外部モデルには、grammar が許す話者を、今の本文の再試行と同じ文面（「このシーンで発話できる人物IDは次の一覧のみです…」）で伝えるようにした（コミット `931da8f`）。直した後に作り直した2本は完成した。

### 読んだ印象（第2章の冒頭）

- Haiku・鉄と血: 避難してきた娘とまだ若い見張りの場面で、騎士への怒りと炊事場の人たちへの迷いが、行動とやり取りで描けている。
- Haiku・ひだまり: 席の配置をめぐる言い合いを陽葵がまとめる場面。紬の「読んでる途中で声がすると、本の中の人の声が遠くなるの」など、人物らしい台詞がある。
- GPT-6 Luna・鉄と血: 報告と復唱が中心（「場所、時刻、負傷者の有無」の確認が続く）で、劇としての起伏が弱い。
- GPT-6 Luna・ひだまり: 自然だが、予定の段取りの相談が長く、起伏が小さい。

### 演出の指示文

演出の指示文（`narrative._staging`）は、演出について「演出は任意の focus/pause/blackout/expression のみ」「演出が不要なら directions=[]」と形式と禁止を書くだけで、間や暗転を何のために、どんな時に使うかを書いていない。表情も「変わるときだけ」と絞る書き方。外部モデルの少ない演出は、この文面に素直に従った結果と見られ、Gemma の多い演出（ほとんどが効かない focus）は Gemma の癖だった可能性が高い。
