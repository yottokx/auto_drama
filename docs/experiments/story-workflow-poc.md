# ストーリー再設計のPoC記録

2026-09-25。初期状態は Git `386130d` に保存し、実装は `codex/story-workflow-poc` で行う。既存作品の本文・DB・公開buildは変更しない。

## 実装の範囲

新方式は `story_workflow_version=2` の別経路。画像・音声なしの実験CLIから同じ `m3_narrative` workerを呼ぶ。通常UIの制作は旧方式のまま維持し、本文の品質成立を確認してから素材・公開制御へ統合する。

- 全体の因果設計 → 章の意図 → 場面計画 → 本文 → 原文に基づく差分 → 独立検査 → 章採用。
- 承認設定、作者の秘密、予定、実際の出来事、人物の知識・信念を区別。
- 章内でも採用候補の実績から次の場面を調整。未実施の予定を終了状態へ転写しない。
- 場面ごとの人物・場所需要を作り、必要なサブキャラを後の章でも追加可能。
- 場所の名前・恒久構造は作品全体の累積台帳に保存。時刻・雰囲気・配置を当章の場所記述へ分け、離れた章からの再訪でも同じ場所を参照。
- 元本文へ戻れる根拠ID、現在状態、過去差分、約束・初紹介の記録を保存。
- 直前の会話・動作は1場面の原文全文で引き継ぎ、それ以前は台帳と取得可能な根拠を使う。同じ原文を引用欄にも重複投入しない。
- 可変コンテキスト設定、実際のトークン数と回答枠の事前検査、用途別の資料取得。
- 入力・版で識別する工程cache、再開後も共通の修復予算、検査対象hashと全場面coverageの照合。
- 章と作品で永続する入力・出力tokenと実行時間の予算。cacheを二重計上せず、失敗時の実測も保存し、計測不能を0として採用しない。
- 過去の根拠を取得して不合格とした場合は、指摘と取得済み原文を修復入力にも引き継ぐ。

機械的な参照整合性と、物語が自然に進むことは別に評価する。自動検査に通っても品質受入にはしない。

## 試行1：関係劇 seed 1

入力は `tests/fixtures/story-debug-relationship.json`。3章、メイン2人、16,384 context、最大出力3,072、Gemma 4 31Bの既存ローカル設定。出力は `tmp/story-causal-poc-seed1`。

第1章は自動検査を通過したが、本文と記録の読み合わせでは不合格だった。第1章採用後に実験プロセスを止め、失敗した出力を保存して設計を修正した。seed交換で成功扱いにはしない。

| 問題 | 根拠 | 見直す処理 |
| --- | --- | --- |
| 既知情報を初開示へ戻す | s1で写真の年代に確証がないことを話し、相手も応答済み。s2でも同じ情報を開示し直し、相手が初めて理由を知ったように反応 | 情報交換と紹介済情報を別工程で抽出し、次場面の予定へ反映 |
| 本文にない時刻を実績にする | s2の「時計を見る」だけを18:30の根拠にした。計画に指定した時刻が記録へ混入 | 抽出へ予定の絶対時刻を渡さず、本文に明記された時刻だけ更新 |
| 検索に必要な索引が空 | eventの人物・場所・原因、knowledgeとintroductionが空のまま検査合格 | 出来事の索引項目を明示的に出力させ、情報交換を独立点検 |
| 終盤の結論に早期到達 | 第1章で「不明を共有し、来場者が考える余白を残す」に到達。第3章の固有進展として予定した内容と重なる | 未採用章の役割も場面計画で参照し、全体計画由来の不備はblueprintへ戻す |

第1章の実測は538.953秒、38リクエスト、入力147,526・出力25,816 tokens。prompt処理51.645秒、token生成455.909秒。これらは全リクエストの合計であり、単一コンテキストの長さではない。章間ロードの除去だけでは推論・検査時間は減らない。

## 試行2：関係劇 seed 1、情報開示の独立抽出

出力は `tmp/story-causal-poc-seed1-r2`、protocol implementation 3、第1章までを対象とした。18リクエスト・310.063秒で情報抽出が形式・参照不備により停止し、章は採用しなかった。

通常抽出の人物・場所・原因は記録されるようになった。一方、独立情報抽出が「誰が知ったか」の判定理由だけを書き、対応するknowledge/introductions本体を省略した。構造化schemaで省略可能だった配列が原因候補で、再試行でも未定義ID参照が残ったため採用検査が拒否した。本文で作業が完了しているのに、通常抽出が状態差分を省略する問題も残った。

省略を意味のある「更新なし」と区別するため、必要な抽出配列をrequiredにし、空なら明示的な `[]` を返させる。情報抽出を結合した後の参照・総数・差分適用まで検査してから工程cacheへ保存する。過去情報の入力は索引と現在値へ分け、本文原文を毎回すべて再投入しない。これらをimplementation 4の別実験として評価する。

この試行のロード8.719秒・解放2.235秒に対し、token生成271.9秒だった。今回の短縮対象は主に生成・検査の回数と入出力量で、モデル常駐化は依然として別の最適化とする。

## 試行3と抽出単体の再現

`tmp/story-causal-poc-seed1-r3` はimplementation 4。同じ設定・seedで16リクエスト、230.375秒。必須化した配列に状態差分と知識が記録されるようになったが、新しいthreadに誤った変更前状態を付けたため停止し、章は採用していない。`expected_status` はLLMの出力DTOから外し、正確な入力台帳を使ってプログラム側で付けるようにした。

生成済みのs1本文を不変入力にした抽出単体の実験を `tmp/story-extraction-probe-v5` で実施した。情報の受け手の知識は記録され、開始前から知る開場時刻も独立情報抽出が「既知の再確認」へ補正した。ただし情報抽出が既存の出来事を追加分として再掲し、既存イベントの変更として検査が拒否した。配列名を追加分と明示し、IDを入力の候補・新規prefixに制約する改善へ進む。単体実験は章の完成や採用として数えない。

`tmp/story-extraction-probe-v6` では作者の初期情報も通常抽出へ渡したが、状態差分の `before` に本文から推測した値を入れ、入力台帳の未登録値 `null` と一致せず停止した。2回の抽出とも同じ問題が残った。変更後の状態は本文から抽出し、現在状態の変更前の値は台帳から厳密に取得する形へ変更する。回想で語られる過去の変化は別途扱い、現在の台帳で過去の値を置き換えない。検査を緩めて採用した結果ではない。

`tmp/story-extraction-probe-v8` では通常抽出が1回で通過したが、情報抽出が人物紹介と場所紹介へ同じIDを付け、2回とも拒否された。また、本文では店舗の営業時期の記録違いしか話していないのに、作者設定にあった人物名の記録不足まで相手の知識へ混入した。元の知識候補を別のモデル呼出へ見せる方式には、同じ誤りをコピーする問題もある。implementation 9では通常抽出を出来事・現在状態・約束へ限定し、情報抽出は本文に基づく独立した観測行へ簡素化する。レコードの採番と訂正対象の参照はコードで確定する。

implementation 8時点の単体・統合テストは966件成功（既存依存の非推奨警告2件）。これはプログラムの参照・採用・回帰検証の結果であり、失敗した実モデル試行を合格へ置き換えるものではない。

`tmp/story-extraction-probe-v9` は3リクエストで通常抽出・独立情報抽出・意味検査を通過した。入力合計9,901・出力2,943 tokens、token生成52.608秒。蓮の知識は実際に聞いた店舗営業期間の食い違いに限定され、終了状態も一枚目固定済み・二枚目配置中へ具体化した。ただし独立照合ではevent `c1-s1-e1` に未発話の人物名不足が残り、意味検査が見逃した。知識への直接混入は解消したが、イベント側で作者設定を無条件に原文観測へ移す問題は未解決である。implementation 9を固定した3章の試行を `tmp/story-causal-poc-seed1-r4` で続行する。

`tmp/story-causal-poc-seed1-r4` は第1章の場所計画で停止し、本文を採用しなかった。設定には登場するが台帳未登録の場所について、モデルが新規登録一覧を空にした。implementation 10では別の新規登録一覧を出力させず、当章で使う場所のIDと既存台帳の差分からコードで登録する。恒久構造は場所の定義に含め、既存台帳はそのまま保持する。また、独立情報抽出へは初期の既知情報を渡す一方、通常の出来事抽出へは作者事実の本文を渡さない形にする。次の同題材・seedの試行は `tmp/story-causal-poc-seed1-r5`。

`tmp/story-causal-poc-seed1-r5` は場所計画・本文・通常抽出を通過したが、独立情報抽出が有効な人物の知識更新へ `fact_id=null` を返し、形式修復でも残ったため停止した。17リクエスト、268.812秒、入力55,483・出力13,134 tokens、token生成232.203秒、ロード8.235秒・解放2.203秒。採用0章。知識更新のある観測行とない行をschemaで分け、更新がある場合はfact IDを必須にする。本文や受け手をコードで意味補正しない。本文と通常抽出の独立照合では大きな未発話情報の混入はなかったが、貼付作業中の描写を三枚すべて完了と読む抽出の過剰な確定が疑われ、品質合格とはしていない。

修復経路の点検でも、抽出の意味検査が再試行後に失敗すると本文や章計画まで再生成してしまう経路を確認した。抽出だけの不備なら本文を保持して停止し、再試行には指摘と取得済みの過去原文を渡すようにする。形式・参照のテスト成功と通読による品質評価は引き続き分ける。

implementation 11では、上記の修復に加え、計画段階で未採用event・解決済みthreadを参照した場合の検査、章・作品共通の永続使用量予算を実装した。単体・統合テスト1,006件が成功（既存依存の非推奨警告2件、114.45秒）、Ruffも成功。固定したコードで `tmp/story-causal-poc-seed1-r6` の3章実験を開始した。第1場面は通常抽出・独立情報抽出・意味検査を通過し、第2場面へ進んだが、この時点では章の採用・品質受入には数えない。

r6は第2場面の独立照合で不合格となり、開発側で実験プロセスを停止した。採用0章。s1-u9の「貸主の記憶と名簿の日付の不一致」がs2-u13では「貸主が忘れ、名簿にも記載なし」へ変わり、新たな調査や訂正がないまま合意の前提になった。さらにs2-u27は二枚の再配置への依頼、u29は手を伸ばした段階なのに、抽出は再配置済みとした。既存レビューは両方を見逃した。s2抽出レビューには原文29発話を含む4,672入力tokensが入り、入力切捨てはないが、190出力tokensの総評だけで合意と完了をまとめて承認していた。停止時の保存原文・比較記録は同実験の `independent-review.json` に残し、未計測の中断リクエストを0扱いにする予算変更は行っていない。

固定したr6本文に対する `tmp/story-fact-comparison-probe-v1` では、書き手役から原文照合役へ切り替え、前後の逐語引用→命題の比較→判定の順にした。記録不一致の変質は `unexplained_change` と検出し、該当する一文だけを整合させた正例は `consistent` となった。三枚の仮配置という先行事実も両方で比較した。これは2条件・各2事実の局所試験であり、場面全体の合格ではない。比較理由には再配置の実行段階を過剰に読む記述がなお残ったため、その説明を実績へ転写しない。状態については原文だけの観測表を先に作り、差分候補を別に照合する方式を実装・検証する。

## 通し生成の再試行：r7と検査の限定的な緩和

ユーザーの指定により、`tmp/story-causal-poc-seed1-r7` で3章の通し生成を一度実行した。implementation 12、同じ関係劇・seed 1・16k。開発側の判断による中断はせず、処理自身の停止まで進めた。440.657秒、22リクエスト、入力80,373・出力22,232 tokensで、第1章s1の状態検査が1回の抽出修復後も不合格となり終了。採用0/3章。停止後には修正・再実行をせず、ユーザーへ報告した。

本文に白紙とある説明札について、観測が「記入を試みたが動かなかった（attempted/denied）」、状態候補が「未記入（completed/denied）」となり、分類差だけで拒否した。また、抗議や腕を組む態度から反発・不信感を記録した候補を、発言・動作と心情の分類差で拒否した。前者は誤検出、後者も自然な解釈と強すぎる断定を分けず一律に止める問題がある。

「多少検査を緩めて3章まで試す」という追加指示を受け、implementation 13 / state audit 2ではこの2点に限定して警告付きで許容する。否定の状態は、同じ人物・対象・動作・数量、観測性と時制が一致し、比較が支持と判定した場合だけ未遂と否定結果の段階差を許す。肯定の未完了を完了へ上げたり、部分記入を未記入にしたりしない。心情は同じ人物の実際の発言・態度による解釈を警告として保持し、人物スコープではその人物が観測の行為者に含まれることも確認する。原文根拠・検査範囲・明確な矛盾・資料不足の検査は維持する。

関連110テストとRuffが成功。これは分類許容の境界と修復・採用経路の検証であり、通し生成の成功を意味しない。次の1回は `tmp/story-causal-poc-seed1-r8` に独立して保存し、停止または完遂時に結果を返す。

r8は554.531秒、31リクエスト、入力107,041・出力27,845 tokensで終了。第1場面の状態検査と抽出レビューを通過し、第2場面の本文まで生成したが、既知情報の比較が形式修復後も根拠ID不一致となり停止した。採用0/3章。検査は過去引用の短縮ID `q3` / `q8` を要求する一方、モデルは元発話ID `s1-u3` / `s1-u13` を返した。引用本文自体は各事実に許可された原文の部分文字列と一致しており、この停止は内容の矛盾を検出した結果ではない。実行前後のコードhashが一致することも確認した。指定どおり停止時点で報告し、ID処理の修正や再実行へは進んでいない。

## 検査の思考OFF／ON比較

ユーザーの指定により、`tmp/story-thinking-ab-v1` でr6の固定原文を使った局所比較を行った。既知情報の根拠のすり替わりと、未実行の動作を完了扱いする誤りについて、それぞれ誤例・正例の計4条件、OFF／ON各1回の8リクエスト。入力・schema・seedは各ペアで同一、16,384 context、総出力上限4,096、思考上限1,024。モデルを1回ロードし、呼出順を交互にした。通常コードや既存作品は変更していない。

両モードとも4/4で期待判定と一致し、JSON形式・引用ID・逐語引用も通過。最終理由にも対象の違いが説明されており、思考ONによる精度優位は今回確認できなかった。case-c/ONは未完了の根拠を一つ多く引用した一方、「写真の横に貼った」を「残り一枚に貼った」と言い換える軽微な粗さもあり、理由の忠実性が一律に上がるとは評価しない。

| HTTP生成時間（モデルのロード・解放を除く） | 27.328秒 | 87.174秒 |
| 出力tokens（思考を含む実測） | 1,264 | 4,804 |

時間は約3.19倍、出力は約3.80倍で、1回平均の増分は約15.0秒・885出力tokens。ONでは全4回に思考本文が出力され、独立して再tokenizeした概算は723〜1,023 tokensだった。分離した本文のtoken数は概算で、実測総数とは厳密には加算一致しない。起動引数 `--reasoning-budget 1024` を明示したが、ログから予算による強制終了までは確認できていない。全8回と準備・解放の計測は126.031秒。再修復や出力上限停止はなかった。

開発に使った4条件・各1 seedのため、未知題材への一般化、長い検査入力、章間の品質は未評価。知識の比較では元発話IDを一貫して使い、r8の短縮IDとの不一致は対象外。状態の比較も原文と候補を直接照合するもので、通常経路の観測抽出Aを含まない。これを通し生成や通常の検査経路の成功とは数えず、既定の思考設定も変更しない。

## r8失敗時の実リクエストを使った思考比較
