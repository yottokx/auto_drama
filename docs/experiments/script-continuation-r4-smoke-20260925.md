## 実装

- 詳細プロットは核心と章ごとの開始条件・試み・結果・選択・次の状態・核心への進展を持つ。`plot.json` を保存し、既存 `outline.json` は同じデータから機械的に投影する。8章超は同じ核心で最大8章ずつ計画する。
- 章計画を `current_facts` → `destination` → `bridge` → 人物の行動 → 後続経路の変更・未達 → 場面一覧へ変更。過去の整理と未来の依頼を別区画で執筆へ渡し、保存済み原文を過去の一次資料とする。
- 後続経路の変更は計画した章の完了後に採用し、次の計画には最新版だけを入力する。元プロットは上書きせず、計画・元プロット・入力した過去章のhashを保存する。核心の大幅な自動改訂は対象外。
- 容量不足では遠い未来の経路を先に外し、その後に既存の過去本文・履歴メモの調整を行う。核心と当章の経路は必須。設定したコンテキストの容量が増えれば保持量も増える。
- 意味判定・修復ループは追加しない。未知の人物ID、変更先の章番号などの技術的な参照不備だけを既存の有限再試行で扱う。未達の懸念は停止条件にしない。

関連131テスト成功、変更したPythonファイルのRuff成功。新規テストは経路変更の採用時期と再開、過去の経路変更の拒否、保存計画の改変検出、9章の分割計画、コンテキスト容量による未来資料の保持量を確認した。既存の台本・演出・Tyrano変換も同じテスト群で確認した。
