# 台本継続・履歴と章計画の分離（revision 3）

2026-09-25。[revision 2の通読レビュー](script-continuation-r2-review-20260925.md)に対する実装と小規模確認。Gemma単独、16k、reasoningなし。3章通し生成は実施していない。

## 実装

- 履歴メモを `context.brief`（作業依頼）へ入れる処理を削除。全文が収まる要求では実台本を使い、省略が必要な過去章についてだけ補助メモを入れる。入力・省略範囲の記録は維持する。
- メモの生成対象を直前章の全文に限定。全体構成・古いメモ・次章計画を生成入力から外し、次章の提案を出す欄も削除した。対象原稿は必須入力とし、抜粋から章全体を要約したことにはしない。長過ぎる等でメモが取得できない場合は既存の任意メモ失敗処理で記録する。
- 全体構成の `ending` に外的な課題の決着と人物・関係の着地を分け、`character_arcs.change` に開始時の行動・守る価値観・結末の具体的な行動を記す指示を追加。既存の構成出力契約を維持する。
- 章計画に `progression`（既決事項、残る問題、試みと結果、次の選択）と `character_actions`（人物ID、具体的な行動ときっかけ）を追加。計画資料として各場面の執筆へ渡し、既存のrequired_eventsへ具体化する。
- 予定外の言動は実績として保ち、その反応・影響を未執筆部分で扱う方針を計画と執筆へ追加。作業の完了を合意と同一視せず、予定した結末のために過去の行動を肯定的に読み替えない。全員の成長や和解は必須としない。
- 場面計画を先に出してから理由を後付けする流れを避けるため、JSONスキーマの項目順も `progression` → `character_actions` → 新規人物・場所 → 場面一覧とした。

最終版のprotocolはprompt 3、implementation 4、contract_revision 2。小規模確認の途中で計画の項目順を変更したため、変更前のimplementation 3からも再開を拒否する。既存の作品・実験成果物は変更していない。全体構成の8章超の分割経路にも人物の具体的な着地の指示を渡す。

意味の合否検査、修復ループ、追加のLLM工程は導入しない。履歴メモは将来の容量調整用に従来と同じ章境界で保存するため、メモ生成の呼び出し自体は残る。人物・場所・話者・発話・演出の参照、Script・Tyrano出力は維持する。新しい計画データの検証も形式・人物参照に限定する。

## 技術確認

最終版で関連125テストとRuffが成功。

- 原文が収まる場合、生成したメモが次章計画・執筆に混ざらず、保存原文を全文渡す。
- 容量不足でメモを使う場合は、作業依頼と異なる履歴の区画に置く。実際の入力・回答枠で予算を計算し、話者行・直前場面を保つ既存処理を維持する。
- メモ作成要求に全体構成や未来の作業依頼がなく、対象章の全文が入る。
- 章の進展と人物の行動が各場面へ渡り、途中再開でも計画・完成場面・出力を再生成しない。
- モデルへ渡すJSONスキーマで進展と人物の行動が場面一覧より先に来る。
- 話者ID・原文・演出を維持してScriptとTyranoへ変換できる。参照不正は技術不備として扱い、意味的不整合を新たな生成停止条件にしない。
- 旧protocolからの再開を拒否する。

最初のテスト実行ではOSの一時ディレクトリへのアクセスでfixtureの準備が失敗したため、workspace内の新規basetempを指定して実行した。最終実行は125件成功。

## 保存済み本文からのメモ・次章計画の確認

revision 2の第1・第2章と全体構成を固定し、メモと第3章計画だけを独立した診断出力へ生成した。元の実験を再開・上書きせず、新しい本文・演出・章成果物は生成していない。旧構成からの立て直しの確認であり、新しい全体構成からの通し生成とは条件が異なる。

最終の項目順修正前の出力：`outputs/script-r3-handoff-plan-probe-20260925/`。2呼び出し、39.547秒、入力9,837／出力1,402 tokens。メモに「廃棄＝非展示」の混同や次章の提案は見られなかった。しかし章計画は、極端な二択によって葵を変え、蓮は最後に待てばよいという解決を再び採用した。また、本文で確定していない配置への同意を既決事項にした。

## 評価上の限界

資料の役割分離と、新しい計画項目の受け渡しは動作している。ただし、指示・項目・出力順を変えれば、人物の変化を適切に描けると保証できるわけではない。過去本文が全文入る場合でも、モデルは圧力を人物の成長の契機と解釈できてしまう。既に悪化した展開からの回復を確認したとは扱わない。

初めから新しい全体構成・章計画で作る場合に問題を減らせるかは、まだ未確認である。追加の合否検査や再生成を繰り返して今回の例を通すことはせず、3章通し生成の前に結果を報告する。
