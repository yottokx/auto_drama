# その場にいない声の判定用の検証場面

電話・通信・録音などの「その場にいない人の声」を、枠付きの胸像と声の効果で表示する案のための検証データ。
台詞ごとに、その場の声か、通信か、回想かを正しく判定できるかを確かめる。
通信の場合は、どの効果（電話・無線など）を掛けるべきかも判定できるかを確かめる。
アプリのコードはまだ変更していない。

## ファイル

| ファイル | 内容 |
| --- | --- |
| `real.json` | 生成済みの作品から抜き出した14場面。演出付けが実際に受け取った入力（設定・計画・全発話）と期待する答え |
| `synthetic-source.json` | 生成済みの場面に無い型を補う、手書きの15場面の原稿 |
| `synthetic.json` | 手書きの場面を `real.json` と同じ形に展開したもの |

作り直すときは次を実行する。生成済みの場面はジョブのキャッシュから読む。キャッシュが無い環境では `--synthetic-only` で手書きの場面だけ展開できる。

```bash
.venv/Scripts/python scripts/story/build_remote_voice_cases.py
```

判定は `scripts/story/probe_remote_voice.py` で行う。製品の演出付けの指示とスキーマに、台詞ごとの `voice_source`（声の出どころ）と `voice_channel`（通信の種類）を足して実行し、ここの期待する答えと比べる。

## 場面の形

各場面は `setting`・`hints`・`plan`・`lines` を持つ。演出付けの入力と同じ形なので、そのまま判定に掛けられる。
`batches` は製品と同じ10行ごとの区切り。区切りをまたぐと手がかりが失われる場面がある。

`expected` が期待する答え。

- `lines`: 台詞ごとの答え。`voice` と `channel` は認める答えの一覧で、先頭が最も望ましい答え。一覧に無い台詞は「その場の声」が正解。
  - `voice`: `present`（その場の声）/ `remote`（通信）/ `recollection`（回想。効果はエコーを想定）
  - `channel`: `phone`（電話）/ `voicemail`（留守電・録音の再生）/ `radio`（無線・通信機）/ `speaker`（スピーカー・モニター越し）/ `telepathy`（念話）/ `message`（文面のメッセージ）
- `absent`: 計画の登場人物のうち、一度もその場に来ない人物。立ち絵で登場させてはいけない。`absent_optional` がある場面は、登場させても誤りとしない。
- `arrives`: 声が先に聞こえ、途中から姿を現す人物。最初の対面の台詞として認める行。`start` は、場面の最初から登場していても誤りとしない意味。

| 場面 | 確かめること |

## 答えの数

台詞に付けた期待する答えは、生成済みと手書きを合わせて次の通り。一覧に無い台詞（その場の声）は数えていない。

| 答え | 台詞数 |
| --- | ---: |
| 通信・無線 | 33 |
| 通信・スピーカー／モニター | 30 |
| 通信・電話 | 13 |
| 通信・留守電／録音 | 7 |
| 通信・念話 | 7 |
| 通信・メッセージ | 7 |
| 回想 | 3 |
| その場の声（紛らわしいもの） | 25 |

## 判断が分かれうる点

- 機体同士や同じ格納庫での通信機越しの会話は、通信ともその場の声とも取れる。どちらも正解として扱う。
- ホログラムは姿が見えている。期待する答えは通信にしてあるが、立ち絵で出す案もありうる。
- 計画の登場人物（最大3人）には、通信の相手が含まれる。登場人物の一覧だけでは、その場にいるかを判断できない。
- 製品の演出付けは10行ずつ処理する。通信の手がかりが前のまとまりにしか無い場面では、直前の発話を渡すかどうかで結果が変わりうる。
