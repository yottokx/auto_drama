# 長尺化の構成を3章・16kで（2026-10-21）

長尺化の構成（2段の計画と締めの対策）を、元の製品の基本の条件だった3章・16kで書けるかを確かめた。長い作品（鉄と血の叙事詩）と、以前16kの3章でコンテキストが溢れた作品（ひだまり1年1組）の2本。あわせて、コンテキストの段と推論の扱いを決めるために、既存の記録とコードから入力・回答の枠を整理した。

## 条件

- モデル: gemma-4-31B-it-UD-Q4_K_XL、推論なし、16,384、演出注釈なし（`--skip-staging`）、シードは入力のまま。
- 計画: `--expand --balanced --expansion-steps 6 --distinct-steps --fresh-roles --closing-step-last --closure-end`（2段の計画、配分のバランス化、肉付けの上限6、言い換え禁止、役回りの禁止、①＋案1）。
- スクリプト: `scripts/story/check_text_long.py`。キャラ上限は `--cast-limit`（入力の `script_options.cast_limit` を上書き）で指定した。
- 入力の量は `scripts/story/input_budgets.py RUN` で、各依頼の `requests/<key>-<attempt>.json` から読んだ（入力トークン数と入力の上限、作例の有無、先の章の予定の圧縮、前の章の表し方）。
- 出力: `outputs/long-form-20261021/tetsu-ud-3ch-16k/`、`outputs/long-form-20261021/hidamari-ud-3ch-16k/`。

### 内容（本文を読んで）

鉄と血:

- 話として成立している。第1章で予算が削られ、禁忌の低級魔石を使うと決め、ひび割れた盾が出る。第2章で泥濘への誘い込みと罠を仕掛ける。第3章でその罠と魔石の障壁が効き、ゼノスとの一騎打ちを経て撤退させる。第1章の材料が第3章で回収される。
- エレナは「騎士の誇り」から「命を守ることが騎士道」へ移り、カイルは型に固執する新兵から、泥にまみれても生き残ると決める。核心の外的な決着、エレナとの対等な結託、ゼノスがアルリックを「競うべき真の強者」と認め直すことは、すべて本文にある。
- 第3章の地の文の71%は、急襲・崩落・魔導障壁・一騎打ちの描写で、要約で流してはいない。
- 先取り: 第1章の場面計画が、第2章の予定の最初の4手順（カイルの稽古、ガラムの装備の報告、アルリックが生存戦略への協力を頼む、エレナの同意）を第1章に入れた。第1章の予定にあった「カイルが兵たちの不満を伝える」は落ちた。第2章は残りの材料で、罠の計画と、廊下でアルリックがカイルにもう一度「泥を啜れ」と説く場面を書き、カイルの決意とエレナの「誇りとは命を守ること」が2章にわたって2回ずつ描かれる。第1章の場面計画の入力は 7,567 で、第2章の予定は詳細のまま見えていた。容量ではなく、予定が見えていたことで起きた先取り。

ひだまり:

- 話として成立している。第1章は凛花の誘いを紬が断り、陽葵の「静かな席」という妥協案も紬の「構造的に不可能です」で崩れる。第2章は高城先生の「大人の贅沢」をきっかけに、紬が裏通りの古本屋カフェを明かし、凛花が「静かにする努力を全力で」と約束する。第3章は休日に私服で出かけ、人混みで凛花が紬の歩幅に合わせ、カフェで静けさを楽しみ、月一回の定例会を決める。章ごとに前の章の結果から始まり、鉄と血のような先取りはない。

### この2本から言えること

- 長尺化の構成でも、16kの3章は2作品とも書き切れ、話として成立した。章の長さは肉付けの上限で目安に収まる。
- 16kの余裕は、最終章の場面計画で数百トークン以下。16kの上限は「3章・キャラ4人・衣装違いあり（メインに1着ずつ）」が基準になる。キャラ5人は衣装違いなしでもほぼ限界。
- 残った問題（章の境目の先取り、主題の語り直し、地の文での主題の解説、語彙の繰り返し）は、どれも32kの実行でも出ていたもので、16kや3章で新しく出たものではない。

## コンテキストの段と推論（既存の記録とコードから）

### 入力の上限と回答の枠

共通設定では、16,384を超えた分の半分が回答の枠に足される（`services/worker/generation/context_budget.py` の `OutputTokenPolicy.resolve`、`extension = (context - 16384) // 2`）。上限に張り付く章の場面計画（基本の回答の枠 6,144、余裕 512）では:

| コンテキスト | 回答の枠 | 入力の上限 |
|---|---|---|
| 16,384 | 6,144 | 9,728 |
| 24,576 | 10,240 | 13,824 |
| 32,768 | 14,336 | 17,920 |
| 65,536 | 30,720 | 34,304 |

32kの8章（`long-form-expand-20261020.md`）で場面計画の入力上限が約17,900だったのは、この計算どおり。8章（キャラ6人・衣装違いなし）の第7章で 17,748 / 17,920 だった。

### メモリ

`cast-size-20261017.md` の実測（RTX 5090、llama-server の分）では、16kから32kに増やして増えるのは約1.3GiB（IQ4_XS 18,834→20,138MiB、QAT 19,717→21,014MiB、UD 21,178→22,474MiB）。24kは32kより約0.65GiB少ないだけで、24GBのGPUでUDの32kが厳しいなら、QAT版にするほうが約1.4GiB空く。64kは測っていない。

### 推論

- 推論の思考は回答の枠（`max_tokens`）の中で生成され、次の依頼の入力には入らない。入力の量と、溢れの判定（入力＋回答の枠＋余裕）は、推論の有無で変わらない。推論ありで心配なのは、思考と回答が回答の枠を超えて回答が切れること。章数・キャラ・衣装違いの上限を下げても、思考に使える量は増えない。
- `gemma31b-stage-timings-20260930.json` の1回あたりの出力の平均（推論ありは思考を含む）:

| 工程 | UD・推論なし・16k | UD・推論 medium・32k |
|---|---|---|
| 場面計画 | 1,820 | 4,461 |
| 全体構成 | 1,835 | 3,176 |
| 場面の本文 | 1,182 | 1,781 |
| 演出注釈 | 934 | 2,141 |

- 32kの場面計画の枠（14,336）に対し、推論ありの平均は3分の1以下。推論ありの全74依頼が正常に終わっている（`gemma31b-reasoning-complete-review-20260929.md`）。16kでは、場面計画の枠 6,144 に平均 4,461 が入るが余裕は小さく、場面の本文の枠（場面の長さの目安、今回の16kで2,560前後）には長い場面で収まらないおそれがある。
- 回答が切れたとき: 計画の工程は、回答が最後まで終わっていないとその依頼を失敗として扱う（`services/worker/generation/draft_story.py:74`）。場面の本文は切れても受け付け、続筆で補う。黙って壊れた台本が残ることはない。
