# 前の章の場所を再利用した場面計画の差し戻しと、章ごとに描き直される背景（2026-10-18）

場面の人数上限の実験（[cast-size-20261017.md](cast-size-20261017.md)）で、シンクロ・パトロールの第3章の場面計画が2回とも差し戻されて生成が止まった。人数とは関係のない場所の登録漏れだったので、保存済みの生成（今回の実験と過去作）を集計して原因を調べた記録。製品のコードは変更していない。

## 何が起きたか

- 章の場面計画は、その章で使う場所を、前の章で登録済みのものも含めて `locations` に定義する決まり（指示「locationsには当章で使う全ての場所を、既存の場所も含めて定義します」）。資料には前の章の場所が「以前に使用した場所のIDと名前」として IDと名前だけで載る。
- 第3章の最後の場面（ガストンが上層部を告発する）が第1・2章のブリーフィング室（loc_briefing_room）を使ったが、`locations` には工房・コクピット・罠の宙域の3つしか定義しなかった。検査が「Scene s5 references an unknown location」で差し戻し、作り直した2回目も場面の組み立てごと変わったうえで同じ場所を漏らし、生成が止まった。
- 保存済みの生成（今回の実験と過去作）にある同じ差し戻しは6回で、すべて前の章で登録済みの場所の再利用。

| 生成 | 章 | 漏れた場所 | 結果 |
|---|---|---|---|
| シンクロ UD（3人枠） | 第2章 | コクピット | 2回目で通過 |
| シンクロ UD（3人枠） | 第3章 | ガストンの執務室 | 2回目で通過 |
| シンクロ QAT（3人枠） | 第3章 | 執務室 | 2回目で通過 |
| シンクロ UD（上限なし） | 第3章 | ブリーフィング室 | 2回とも失敗して停止 |
| 過去作（城の物語） | 第3章 | 城門 | 2回目で通過 |

- 漏れた回答の5件は、4か所を使って3か所だけ定義していた。通過した計画195件のうち4か所以上を使うのは14件（7%）。
- 差し戻しの文言はエラー文だけで、前の章の場所なので定義を一覧に入れればよい、という直し方は伝わらない。
- 前の章の場所の定義（名前・説明・時間帯・雰囲気・背景の描写）は `state["locations"]` に全部保存されている。背景は章ごとの定義の `image_prompt` から毎回描くので、同じ場所でも章ごとに別の絵になる（自室の間取りが第1章と第3章で違う、など）。
- 2026-10-18、場所の引き継ぎ（同じ場所の見た目を保ちつつ、作中の出来事による変化は許す）と合わせて後で対応することにした。
