# LLM入力の冗長表現: 削減効果と副作用の評価（2026-10-13）

[第3章の場面計画がコンテキストを超えた原因の分析](script-plan-context-overflow-20261012.md) の続き。保存済みの入力とコードを読み、削減できる冗長表現ごとに、効果・副作用・優先度を評価した。コード・設定は変更していない。新規推論も行っていない。

## 結論

| 優先度 | 冗長表現 | 主な工程 | 効果 | 良い副作用 | 悪い副作用・リスク |
| --- | --- | --- | --- | --- | --- |

| 高 | 3. 同じ本文を1つの入力に2回入れている | 演出付け、BGM | 中 | BGMで切り詰められる本文が減る | ほぼ無い |
| 中 | 4. 決めさせたい欄の既定値と、文字位置 | 演出付け | 小〜中 | 無難な値への引っ張りを除ける可能性 | ほぼ無い |

最初に手を付けるなら 3 と 4。効果は中程度だが副作用がほぼ無く、変更箇所も演出付けの入力の1か所にまとまっている。2 は効果が最大だが、対応づけの実装に注意が要る。

1 は実生成で確かめた（[演出付けに渡す資料を絞る実験](staging-context-probe-20261013.md)）。入力は33%減ったが、時間は1割弱しか縮まず、品質にはっきりした差は無かった。この表の 1 の行は実験後の評価で、下の「1.」の節は実験前の見立てのまま残している。

3 と 4 も実生成で確かめた（[発話の渡し方とBGM入力の重複を減らす実験](staging-lines-probe-20261013.md)）。3 は副作用が無いことを確認したが、演出付けでの効果は小さい（入力7%減）。4 は見立てが外れた。既定値を外すと声の感情の付き方が大きく変わり、英語の応答が増え、読み比べでは良くならなかった。4 は保留とし、上の「最初に手を付けるなら 3 と 4」は 3 だけに改める。表の 3 と 4 の行は実験前の見立てのまま残している。

2 も実生成で確かめた（[長い人物IDを短い別名に置き換える実験](id-alias-probe-20261013.md)）。場面本文で入力16%・出力21%・時間21%が減り、品質の低下は見つからなかった。評価は変えていない。

## 調べた範囲

- 保存済みの要求は30作品あまり・127ジョブ分。工程別に入力量を合計すると、演出付け（`script-staging`。発話ごとに感情・声・表情を付ける工程）が全LLM入力の約27%で最大、場面本文が約20%、場面計画が約7.5%。
- 入力の文面を読んだのは、場面計画・場面本文・演出付け・BGM・イベントCG選定・要件照合・設計の候補選びの各1件（計4作品）。
- どの冗長表現も、入力を組み立てる共通のコードから出ていることを確認した。作品ごとに量は変わるが、出ること自体は作品に依らない。
- 効果は「その工程の量」と「その工程の入力に占める割合」からの見立てで、大・中・小で示す。トークン数を数えたのは場面計画の1件だけ。

## 高: 先に進める価値があるもの

### 1. 演出付けに、使わない資料を丸ごと渡している

**現状。** 演出付けは発話を10件ずつに分け、まとまりごとに1回LLMを呼ぶ（[narrative.py:494](../../services/worker/generation/narrative.py)）。毎回渡しているのは次のとおり。

- 場面の設定の全体: 世界設定の全文、登場人物の設定と声、関係、予定のつながり、人物IDの一覧、場所（背景画像用の英語プロンプトを含む）
- 場面計画の全文
- 対象の10発話だけ。同じ場面のそれより前の発話は渡していない
- システム指示は脚本家向けの執筆規則と、保存済み台本・引き継ぎメモの扱い。どちらも演出付けの入力には無い

読んだ1件では、入力の6割以上が設定だった。1場面で3〜4回呼ぶので、同じ設定を何度も読ませている。同じ資料の再送がサーバー側で再利用された割合は、演出付けの入力全体の約9%にとどまる。

**削減案。** 登場人物の設定と声、場面計画の目的・雰囲気・必須の出来事は残す。世界設定の長文、予定のつながり、人物IDの一覧、背景の英語プロンプトは外す。システム指示は演出付け用の短いものにする。

**効果: 大。** 最も量の多い工程で、入力の大半が対象になる。

**良い副作用。** 空いた枠で、直前の発話と、前のまとまりで付けた表情を渡せる。表情は「次に変わるまで続く」指定なのに、今はまとまりの境目で前の状態が見えない。感情を決める材料としても、世界設定より直前の発話のほうが効く。

**悪い副作用・リスク。**

- 世界観や関係に基づく読み（敵対する相手への皮肉など）が弱まる可能性がある。関係は登場人物同士の分だけ残すのが無難。
- 感情・声・表情の出力の傾向が変わる。同じ場面で新旧の結果を比べる確認が要る。今回は比較していない。

### 2. 長い人物ID

**現状。** 後から追加した人物のIDは `character-` に36文字の識別子が続く形で、全工程の入力に出る。メイン3人のうち2人が長いIDの「ひだまり1年1組」では、保存済みの台本の約4分の1がこのIDだった（3章とも同程度）。台本は執筆の出力でもあるので、出力側にも同じ割合で出る。先の分析では、他作品25件のうち17件が長いIDを使っていた。

**削減案。** LLMに渡すときだけ `character-2` のような短い別名に置き換え、応答で元に戻す。保存物は実IDのままにする。

**効果: 大。** 入力・出力の両方に、全工程で効く。

**良い副作用。**

- 写し間違いの余地が減る。IDの写し間違いは実際に起きていて、修復の仕組みがある（[script_cast.py:106](../../services/worker/generation/script_cast.py)）。
- 執筆の出力が短くなり、生成が速くなる。
- 出力枠の見積もりが、人物の構成に左右されにくくなる。

**悪い副作用・リスク。**

- 対応づけを誤ると、人物の取り違えという重い誤りになる。作品内の実IDと衝突しない別名にする、語の境界を見て置き換える、応答の自由文（履歴メモの引用など）も戻す、の3点が要る。
- IDはメッセージ本文だけでなく、話者を制約する文法（[narrative.py:300](../../services/worker/generation/narrative.py)）と、スキーマの列挙にも入っている。同じ対応で置き換える必要がある。

### 3. 同じ本文を1つの入力に2回入れている

**現状。**

- 演出付けに渡す各発話には、表示用の本文と読み上げ用の本文の2欄がある。保存済みの12,761発話すべてで、2つは同文だった。
- BGMの入力には、場面の台本全文と、発話の一覧の両方が入っている（[music_pipeline.py:158](../../services/worker/generation/music_pipeline.py)）。

**削減案。** 演出付けには本文を1欄だけ渡す。読み上げ用が異なるときだけ添える形は、別の箇所で既に使っている（[continuity.py:66](../../services/worker/generation/continuity.py)）。BGMは台本全文か発話一覧のどちらかにする。

**効果: 中。** 演出付けでは発話の部分がほぼ半分になる。

**良い副作用。** BGMの入力は長さの上限で本文を切り詰めている。重複が無くなれば、切り詰められる本文が減る。

**悪い副作用・リスク。** 演出付けにはほぼ無い。BGMはどちらを残すかで失うものが違う。発話一覧は感情・声の指定を持つが、1行を120文字で切っている。台本全文は行を切らないが、指定を持たない。発話一覧を残すなら、行の切り詰めを緩める必要がある。

## 中: 副作用は小さいが、効果も大きくはないもの

### 4. 決めさせたい欄の既定値と、文字位置

**現状。** 演出付けに渡す各発話に、内心が「未指定」、声の感情が「neutral」、声の出し方が空、という既定値が入っている。これらはモデルに決めさせたい欄そのもの。台本内の文字位置（開始・終了）も入っている。

**削減案。** 発話は、ID・話者・本文だけにする。

**効果: 小〜中。** 1発話ごとの量は小さいが、全発話に付く。3 と同じ箇所の変更なので、同時に行える。

**良い副作用。** 「neutral」が先に見えていることで、無難な値に寄っている可能性がある。外せばその懸念が消える。実際に寄っているかは確かめていない。

**悪い副作用・リスク。** ほぼ無い。

### 5. 別の工程向けの指示が残っている

**現状と削減案。**

| 残っている指示 | 出ている工程 | 削減案 |
| --- | --- | --- |
| 「この場面の本文約N文字…水増しはしない」。場面計画の目的欄に埋め込まれている（[script_chapter_plan.py:64](../../services/worker/generation/script_chapter_plan.py)） | 演出付け、BGM、イベントCG選定 | 分量は別に保存済みなので、執筆の入力でだけ添える |
| 自己紹介・代表台詞の扱い。台本の工程には代表台詞を渡していない（[script_cast.py:168](../../services/worker/generation/script_cast.py)） | 台本の全工程 | 削除 |
| 「各話約4000文字」と「この場面約N文字」の同居 | 場面本文 | 場面の分量だけにする |

**効果: 小〜中。** 1件ずつは短いが、出る箇所が多い。

**良い副作用。**

- 文字を書かない工程が、文字数の指示を読まなくて済む。場面計画の目的欄が内容だけになる。
- 場面本文で、章の分量と場面の分量を取り違える余地が無くなる。取り違えが実際に起きているかは確かめていない。

**悪い副作用・リスク。**

- 分量の目安を目的欄から外すと、場面計画の保存形が変わる。保存済みの計画には文言が残るので、新しい計画から切り替わる。
- 章の分量を外すと、執筆側が章全体の規模を知る手がかりは減る。場面の分量は章の分量から配分済みなので、影響は小さいと見ている。

### 6. 機械用の記録

**現状。** プロットの sha256、章ごとの版番号、作例の sha256 が入力の文面に入っている。現在の章番号は、指示文と資料の両方にある。

**削減案。** 入力の文面からは外す。

**効果: 小。** 1件あたりは小さいが、台本の全工程に出る。

**良い副作用。** 特に無い。意味の無い文字列が減るだけ。

**悪い副作用・リスク。** 保存済みの要求の文面から版を読めなくなる。同じ情報は要求と一緒に保存している選択記録に残っているので、調査には困らない。

## 低: 単独では勧めないもの

### 7. 設定の書式

**現状。** 設定とプロットは、キーと値を別の行に書く形で渡している（[script_context.py:25](../../services/worker/generation/script_context.py)）。リストの項目には区切りの印が無い。

**削減案。** `キー: 値` の1行にし、項目の区切りを明示する。

**効果: 小。** 場面計画の1件では、設定とプロットの部分が数%短くなった。

**良い副作用。** 人物や関係の区切りが読み取りやすくなる。

**悪い副作用・リスク。** 台本の全工程で入力の文面が変わり、応答が全体に揺れる。良くなる保証も悪くなる保証も無く、確認の範囲がこの一覧で最も広い。1 や 2 と同時に行い、まとめて確認するのがよい。

### 8. 場面計画に渡す声の説明

**現状。** 人物ごとの声の説明（音声合成向けの記述）を、場面計画にも渡している。

**削減案。** 場面計画でだけ外す。

**効果: 小。**

**悪い副作用・リスク。** 声の説明には話し方の癖も含まれる。場面計画が、それを踏まえた会話材料を作る余地が少し減る。執筆では地の文に使われた例があるので、執筆からは外さない。

### 9. 細かな重複

- **同文の開始条件**: プロットの2つ目以降の出来事の開始条件は、前の出来事の最後の結果と同文になる。
- **空の項目**: 中身の無い欄も、キーだけ出している。
- **衣装の書き方**: 人物名の再掲と、欄ごとの改行。内容は変えずに詰められる。

どれも効果は小さく、副作用もほぼ無い。7 の書式を直すときに一緒に片付く。

設計の工程（人物・世界の候補選び）にも空の入力欄が並ぶが、そこでは空欄が「ユーザーは未指定」を表している。外すと未指定の扱いが変わりうるので、この一覧には含めない。

## 削減しないと判断したもの

| 候補 | 理由 |
| --- | --- |
| 場面計画で、その章に割り当てのない衣装を省く | 場面計画は姿を選ぶ工程。割り当てのない章で別の姿が使われた実例がある |
| 指示文の重複（同じ趣旨が3〜5回） | 合計しても小さい。守らせたい点の念押しとして働いている可能性がある |
| 関係の要約欄 | 双方向の記述と重なるが、承認済みの内容。機械的に削ると事実が落ちうる |
| 執筆・イベントCG選定での背景の英語プロンプト | 背景画像の内容を伝える唯一の記述。地の文や構図を画像に合わせる助けになりうる |

## 進め方の注意

- **工程の同一性**: 保存済みの工程は、資料・指示・スキーマから計算した値で照合している（[script_continuation.py:532](../../services/worker/generation/script_continuation.py)）。
  - 2、6、7、9 は、要求を組み立てる最後の段での置き換えとして実装できる。そうすればこの値は変わらず、書きかけの作品の再開に影響しない。
  - 資料や指示そのものを変えるもの（1、3、4、5、8）は値が変わる。書きかけの章を再開すると、再実行や不一致のエラーになりうる。新しい章・新しい実行から適用する切り替えが要る。
- **確認の単位**: 1・2・7 は出力の傾向が変わる。同じ作品・同じ場面で新旧を比べる。3・4・6・9 は情報を減らさないので、通常のテストで足りる。

## 未確認

- 演出付けの資料を絞ったときの品質。新旧の比較はしていない。
- 「neutral」の既定値と、章・場面の分量の同居が、実際に出力へ影響しているか。
- 読んでいない工程: キャスト計画、出来事の連鎖、章配分、音声分離、品質レビュー、関係の設計。
- 効果の大きさ。場面計画の1件を除き、トークン数は数えていない。
