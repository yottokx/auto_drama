# 長尺化の章の開始条件をつなぎ直す（2026-10-24）

長尺化のプロットでは、第2章以降の「開始:」が前の章の最後の手順ではなく、骨組みの最後の手順の結果になっている（`scope-guard-20261022.md` の「章の開始条件が古い」）。`script_expansion.expanded_events` が、肉付けした章の開始条件に骨組みの連鎖の `events[0].start_condition` を使い、前の章で骨組みの最後の手順より後に足された手順を反映していないため。修正案は「第N章の開始条件を、第N−1章の肉付け後の最後の手順の結果にする」。本体のコードは変えず、ひだまりと鉄と血の叙事詩で修正の前後を比べた。

## 方法

- 作品: 「ひだまり1年1組fix」（4章、ストーリーライン `f45e753b`、ガード付きで10/23に本体で第1章から作り直したもの）。第1章は本体のものをそのまま使い、第2〜4章を書き直した。
- `scripts/story/rerun_product_chapters.py` に `--chain-starts` を足した。承認した全体計画のプロットで、各章の最初の出来事の開始条件を前の章の最後の手順の結果に差し替える。計画のハッシュと、引き継ぐチェックポイントの計画も同じものにそろえる。手順・題名・役割・会話の材料は変えない。章の要約（outline）には開始条件が入らないので変わらない。
- 2条件とも同じ道具で、本体のチェックポイントから書き直した。
  - 修正前: `--option skip_staging`
  - 修正後: `--option skip_staging --chain-starts`
- 演出注釈は作らない（`skip_staging`）。画像・音声は章ジョブでは作らない。シードは本体から引き継ぐ。条件は本体のまま（gemma-4-31B-it-UD-Q4_K_XL、推論なし、32k、`long_form`・`chapter_scope_guard`・`planned_cast_appears`・`open_scene_cast`・`cast_limit`）。
- 修正前の条件は、同じシード・同じコードでも本体の第2〜4章とは別の本文になった。各条件1本ずつの比較になる。
- 出力: `outputs/chapter-starts-20261024/before`、`outputs/chapter-starts-20261024/after`。

### 第2章の書き出し（差が出た）

- 修正前: 第1場の開始状態が「凛花が反発し、陽葵がなだめ、氷室が離れた直後のホームルーム」。本文の冒頭で、陽葵が凛花をなだめ、氷室が溜息をついて席へ戻る流れをもう一度描く。第1章の最後（先生の仲裁、チャイム、授業の準備）より前の状態に戻っている。本体（10/23）で見た言い直しと同じ。
- 修正後: 第1場の開始状態が「授業開始直後。生徒たちが席に着き、高岡先生が教卓に立っている」。本文は「チャイムの余韻が消え」から始まり、第1章の最後のチャイムから続く。第1章のやり取りは繰り返さない。

### 第3章の書き出し（どちらも問題なし）

- 修正前は開始条件が古い（勉強会への同意）が、場面計画も本文も第2章の最後（図書室で勉強中）から始まり、同意の場面は繰り返さない。古い開始条件は第2章の途中の状態で、第2章の本文はその後の勉強の開始まで進んでいる。場面計画が「予定の開始条件が実台本と違えば実台本から始める」という指示どおり、保存済み台本の到達点を選んだと見られる。
- 修正後は第2章の最後の続き（第4章の結末から逆算する解き方）から始まる。

### 第4章の書き出し（小さな差）

- 修正前: 本文の最初の一文が、第3章の最後（重ねた手の温もりで氷室が微笑む）をもう一度なぞり、図書室でのやり取りを少し続けてから教室へ移る。場面計画の第1場の開始状態は「教室に戻って着替えている」で、本文が計画より前から始めている。本体（10/23）で見た、氷室を誘って断られるやり取りの2回目は、この書き直しでは起きなかった（誘いは1回）。
- 修正後: 教室での着替えから始まり、第3章の場面は繰り返さない。

### 修正に関係なさそうな差

- 修正後の第3章は2場面・6,234字で、修正前（4場面・7,704字）より短い。本体の第3章も2場面・5,810字で、開始条件が古くても短くなっている。開始条件より、場面計画のぶれと見られる。
- 修正後の第3章の終わりで氷室が勉強会に加わるが、第4章では氷室を除いた3人で出かけ、駅前で偶然会う。プロットの第4章の手順のままで、開始条件とは関係しない。

## ひだまりのまとめ

- 開始条件をつなぎ直すと、第2章の冒頭で第1章の途中を言い直すことはなくなった。第4章の冒頭のなぞり直しも消えた。
- 開始条件が古くても、場面計画が保存済み台本の到達点から始めた章（この書き直しの第3章）では、言い直しは起きなかった。古い開始条件が冒頭の言い直しにつながるのは、場面計画がその開始条件を第1場の開始状態にそのまま使った章（第2章）。
- 各条件1本ずつで、同じシードでも本文は毎回変わる。第2章の言い直しは本体と修正前の両方で起き、修正後では起きなかった。

## 2作品を通して

- 古い開始条件が言い直しを生んだのは、ひだまりの第2章だけだった（本体と修正前の両方）。開始条件が場面の状況を書いていて、場面計画がそれを第1場の開始状態にそのまま使った章。
- 開始条件が人物の認識を書いている場合（鉄と血）や、場面計画が保存済み台本の到達点を選んだ場合（ひだまりの第3章）は、古くても害が出なかった。
- 修正後は、2作品の8つの境目すべてで前の章の最後から続き、修正で悪くなった境目は無かった。
- 各条件1本ずつ。同じシードでも本文は毎回変わるので、言い直しが起きる頻度までは分からない。

## 本体への実装（10/24）

結果を受けて本体に入れた。`expanded_events` が前の章の肉付け後の最後の結果を受け取り、`expand_plot` が第2章以降でそれを渡す。テストは `tests/unit/test_long_form_plan.py` の `test_a_chapter_starts_after_the_steps_added_to_the_previous_one`。

- これから作る長尺化の全体計画（STEP4）は、肉付けの段階で開始条件がつながる。肉付けの途中で止まった計画を再開したときも、保存済みの肉付けの答えをそのまま使い、開始条件だけつなぎ直したプロットになる（肉付けの依頼には開始条件が入らないので、答えは読み直される）。
- 既存の作品（修正前に作った長尺化の計画）は、STEP4で承認（承認し直し）するときに直す（`planning_service.py`、`script_expansion.chained_starts`）。開始条件が前の章の途中の手順の結果と同じ章だけを、前の章の最後の結果に置き換える。STEP4で手で書き直した開始条件は残す。STEP4の画面の計画も、承認した計画と同じものに保存し直す。その承認から始まる制作は、第1章から直った開始条件で書かれる。開始条件のほかのプロットは変わらない。ひだまり・鉄と血の計画でも、古い開始条件がすべて置き換わることを確かめた。
- 制作の途中の章からは付けられない。前の章の引き継ぎ（チェックポイント）が、承認した計画のハッシュ込みで検査されるため。ガード（`ef92507`）と同じく、承認し直して第1章から作り直す。
- `rerun_product_chapters.py --chain-starts` も同じ `chained_starts` を使う。
- 計画の識別子・プロトコルは変えていない。既存の計画の検査は今までどおり通る。
- `PlotChapter.route` は肉付けの後も骨組みのままだが、計画の検査（`validate_plan_content`）で出来事から作り直されるので、承認する計画では開始条件も含めて出来事と同じになる。別に直していない。
- `check_text_long.py` が持つ実験用の `expanded_events` の写しは、過去の実験を再現できるよう変えていない（`--product` は本体の処理を使う）。
