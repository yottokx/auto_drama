# STEP4のキャスト計画でサブキャラが少ない原因と、指示を変えた再生成（2026-10-17）

サブキャラは、ほとんどの作品で0〜2人しか作られない。メイン1人なら1〜2人、メイン2人以上なら0〜1人で、メインとサブを合わせた人数が3人前後に収まる。STEP1のこだわりに「キャラ数多め」と書いても変わらなかった。
学園物なのに追加されるのは生徒1人か教師のどちらか、バトル物なのに敵キャラが出ない、と全体にこぢんまりしている。
キャスト計画の指示の何が人数を抑えているかを、過去作品のキャスト計画の再生成で確かめた記録。LLMだけを動かし、画像と音声は生成していない。製品のコードは変更していない。

## 結論

- 人数を抑えていたのは、キャスト計画の指示の「全3章では1〜2人を目安に世界・メイン人数へ合わせます」。保存済みの依頼をそのまま再生成すると、保存済みと同じ人数になる。
- この目安を「この世界でメインの身近にいる人、出会う人、対立する人から決める」に置き換えると、サブはメインの人数によらず平均2人になった。人数の目標を書かない指示でも、少人数の作品は少ないまま。
- 学園物には担任と級友の両方が出る。バトル物には敵側の人物が出る。店員・店長・常連客のような脇役も人物として作られる。「キャラ数多め」の作品は0人から1〜2人になった。
- 目安を外しただけの案は、多くの作品でちょうど2人になる。新しい目安のように見える。先に周りの人を挙げさせる案（surroundings）は、人の多い世界で3〜4人に増え、2人への集中が少し崩れる。
- 人数が増えると、後の工程の入力が増える。メイン3人の作品はプラン確認での修正（コンテキスト16,384）で超過する見込みで、入力の渡し方の見直しとセットで扱う必要がある。

## 保存済みのキャスト計画の人数

| ---: | ---: | --- |

| 3人 | 18 | 0人が6作品、1人が8作品、2人が3作品、実行ごとに0・1・3人と変わる作品が1つ |

「キャラ数多め」は世界観のnotesに原文のまま残り、キャスト計画の依頼に届いていた（瑠璃色の境界線）。それでも7回の実行がすべてサブ0人。指示には「登場人物を限定するユーザー設定は優先し、空配列も可能」はあるが、増やす希望を優先する文は無い。

## 実験

各作品の最新の保存済みキャスト計画の依頼を、指示だけ変えて再生成した。シードは保存時のものと固定の追加シード（20261017）の2回。モデルは `gemma-4-31B-it-UD-Q4_K_XL`、推論なし、コンテキスト16,384。推論ありで保存された作品も、製品と同じく推論なしで再生成した。

| 版 | 変更 |
| --- | --- |
| current | 保存済みの依頼のまま |
| unanchored | 「全N章では1〜2人を目安に〜」を、目安なしで「メインの身近にいる人、出会う人、対立する人をこの世界から考え、台詞と出番がある人を作る」に置き換える。少人数の密な関係の作品は少なく、人が集まる場や敵がいる物語はそれに見合う顔ぶれにする。台詞のある脇役（店員・兵士・級友）も作れる。人数についてのユーザー設定は、増やす場合も限定する場合も優先する |
| surroundings | unanchoredに加え、回答の先頭に `surroundings`（メインの周りにいる人を、立場と物語での関わりで短く列挙する）を置き、その中から台詞と出番がある人を選ばせる |

対象は代表的な12作品。学園4、戦い・対立4、少人数・閉じた舞台4。

### 顔ぶれの変化

- **学園**: ひだまり1年1組は、currentでは委員長かムードメーカーの1人だけ。unanchoredとsurroundingsでは担任と級友2人がそろう。共鳴する放課後の境界線と瑠璃色の境界線も、0人から級友・先輩と、司書や教師の組み合わせになった。
- **戦い**: 鋼鉄と血の叙事詩は、currentでは味方側（副官・魔導技師）だけ。unanchoredとsurroundingsでは、敵側の側近・執行官・傭兵団首領が加わる。シンクロ・パトロールとモノノケ・レゾナンスにも、敵対者やライバルが加わった。
- **脇役**: コンビニの店員・店長、深夜の常連客、喫茶店の店主が人物として作られる。

- **surroundingsの列挙**: 3〜6件の立場を挙げ、そのうち半分ほどを人物にする。挙げたが人物にしなかった立場（母親、役所の職員、酔っ払いの客など）は、世界の背景として妥当な内容。

### 章の場面計画で人物を絞った再生成

場面の本文の工程は、以前から当場面の人物と言及された人物だけを詳しく渡している（`scene_material`）。毎回全員を詳しく渡していたのは、章の場面計画だけだった。そこで実験用の設定 `focused_plan_cast` を足し、章の場面計画では、メイン・その章の予定に名前が出る人・前章の最後の場面にいた人だけを詳しく渡すことにした。他の人は id・名前・役割だけになる。つながりと日常の接点も同じ基準で絞る（`plan_material`）。この設定を有効にした作品だけに効き、既存の作品の依頼は変わらない。

同じ入力・シード・キャスト・32kで生成し直した。全体プロットまでは前回と完全に一致したので、比べているのは第1章の場面計画から先の違い。

| 第1章の場面計画の入力 | 7,917 | 7,407（ヴァルガス・バルドールを名前だけに） |
| 第2章の場面計画の入力 | 10,136 | 10,306（全員が予定に出るので絞らない） |
| 第3章の場面計画の入力 | 12,611 | 12,044（ヴァルガス・バルドールを名前だけに） |

| 入力の合計 | 280,381 | 284,830 |

- 減ったのは、章の場面計画1回あたり約500トークン（4〜6%）。第3章の場面計画は12,044で、16kの上限9,728を超えたまま。入力の多くは過去の章の原文（第1・2章で約9,400文字）で、人物の情報ではない。
- 入力の合計が減っていないのは、本文の長さが変わったことと、下記の声の人物を作る呼び出し（11,186）が1回増えたため。
- 第3章の場面計画は、名前だけになったヴァルガスを配役しなかった。前回は彼が主砲を撃ったが、今回はゼノス自身が撃つ。予定に名前の無いサブは、出番が減りやすい。1回の比較なので傾向とまでは言えない。

- 台本の質は全体に同程度。マルクスが第1章のアルリックの台詞を引用して第2章でエレナを説得するなど、つながりが良い箇所もある。バルドールの強襲が場面にならない点、ゼノスが遠くの陣地から次の場面で斬り合いになる点は、前回と同じ。アルリックの一人称が「私」から「俺」に変わったが、メインの設定は両方で全文を渡しているので、絞り込みとは無関係。

人物の絞り込みで減るのは、章の場面計画の入力の数%だけだった。第3章の場面計画を16kに収めるのは、過去の章の圧縮（既存の `fit_context`）の役目のまま。人物を絞ると、予定に名前の無いサブの出番が減るおそれもある。

## コンテキスト長とVRAM（Gemma 4 31B）

製品と同じ起動引数（`--ctx-size`、全層GPU、`--parallel 1`）でllama-serverを起動し、読み込み後のGPU使用量を `nvidia-smi` で測った。値は起動前の使用量（約1,450MiB、デスクトップ等）を引いたllama-serverの分。RTX 5090で計測。コンテキストの約85%を埋める入力を送っても、増えたのは約20MiBだった。

| 量子化 | 16,384 | 32,768 |
| --- | ---: | ---: |
| IQ4_XS（16.4GB） | 18,834MiB | 20,138MiB |
| UD-Q4_K_XL（18.8GB） | 21,178MiB | 22,474MiB |

16kから32kに増やしても、増えるのは約1.3GiBだけ。24GBのGPU（24,564MiB）なら、IQ4_XS・32kは約20.1GiBで、デスクトップ等の分を足しても2GiB以上の余裕がある。UD-Q4_K_XL・32kは約21.9GiBで、残りは約0.6〜2GiBと、他に何が動いているか次第になる。RTX 5090以外のGPUやドライバーでは、計算用バッファの大きさが多少変わる可能性がある。

### IQ4_XS・32kでの生成

元のコード（人物の絞り込みなし）に戻し、モデルだけを `gemma-4-31B-it-IQ4_XS` にして、同じ入力・キャスト・32kで生成した。モデルが違うので、全体プロットから別物になる。

2回目の台本の内容（UD・32kの1回目との比較）:

- 良い点: カイルの成長が3章を通して完結する（第1章で独断の追撃から救われ、第2章で訓練の列を守り、第3章で側面を突いて道を開く）。エレナの「断続的な障壁」の陣形が第2章で提案され、第3章の決戦で使われる。バルドールは第3章で傭兵団を率いて1場面を持つ。計画が門番・要塞の兵士たち・名もなき兵士の3人を新しく作り、本文で実際に話している（脇役の自然な追加）。

物語の組み立ては同等かそれ以上だが、IQ4_XSは本文の崩壊（停止）と、話者の取り違え・語の誤りといった細部の崩れが出た。1作品2回の比較なので、頻度は確定しない。

## 4人以上の場面で立ち絵に出す人物を演出注釈で選ぶ

立ち絵は3人までで、立ち絵にしない人は話す行だけメッセージウィンドウに顔を出す、という表示を想定し、誰を立ち絵にするかを演出注釈に選ばせた（`scripts/story/probe_scene_portraits.py`）。

- 演出注釈の directions に `portraits` を足した。「この行から立ち絵で見せる人物」を1〜3人と、短い理由（reason）。場面の最初の行には必ず付け、中心の人物が入れ替わる行でだけ足す。3人に揃えなくてよい（二人の口論ならその二人、教師の授業なら教師一人）、遠くの声や回想の声の人は選ばない、と指示した。他は製品の演出注釈（`narrative._staging`）と同じ依頼・10行ずつの分割・検査。4人以上の場面にだけ足す。
- 材料は保存済みの場面（ひだまり UD の open・acting、IQ4_XS・QAT の open、モノノケ UD の open）の4人以上の場面17個。設定は保存済みの本文の依頼から取った。演出はその台本を作ったモデルで付けた。製品のコードは変えていない。結果は `outputs/cast-size-20261017/scene-portraits-20261018/`。

結果:

- 17場面中16場面で完了。1場面（ひだまり UD open 第3章の「お疲れ様会」）は、同じ人物を1つの指定に2回入れる誤りが再試行でも直らず失敗した。
- 選ばれた人数は3人53回、2人52回、1人9回で、3人に揃えはしない。
- 選び方は本文に沿っている。
  - QAT 第1章、凛花が結衣の席へ行って作戦を練る場面（配役4人、遠くの陽葵と紬は黙っている）: 最後まで凛花・結衣の2人。
  - QAT 第2章、先生と陽葵の教卓での会話（凛花・冴子は黙っている）: 最初は「教卓で一人ため息をつく」先生1人、陽葵が来てから先生・陽葵。
  - モノノケ第3章の決戦（拓海は台詞なし、厳山は遠くからの声）: 蓮・結衣のみ。
  - IQ4_XS 第1章、紬が本の世界に閉じこもる行: 紬1人。
- 立ち絵の入れ替えが多い。565行で80回、約7行に1回入れ替わる。直前と同じ顔ぶれを指定し直したものも18回あり、多くは10行ずつの分割の境目。分割ごとに顔ぶれを決め直す形になっている。
- reason が英語になったものが2件（acting 第3章の図書室）。reason と顔ぶれが合わないものが1件（モノノケ第1章「蓮と、観測する朧へ切り替え」で、指定は蓮・結衣）。

## 立ち絵の方針の決定と、中心キャラの判定（入退場のみ）

立ち絵の選び方を3通り試した（`scene-portraits-20261019-scene/viewer.html` で比較）。
- 場面の中心に合わせて変える: 会話の中心が移るたびに入れ替わり、忙しない。
- 話者で機械的に入れ替える（顔枠なし）: 退場が分からず、来る前の人も立つ。外す人を「次に話すのが一番遅い人」にすると入れ替えは減る（モノノケ 6→3回）。
- 入退場のみ: 採用。

2026-10-18 に決めた方針: 4人以上の場面では、場面ごとに中心キャラ（1〜3人）を一度判定する。中心キャラは本文でその場に来る行で立ち絵に加え、去る行で外す。それ以外の人は、その場にいても、話していても、場面を通して顔枠。入場した順に枠を埋めるのではなく、途中で中心を選び直さず、移動などの別の条件でも変えない。

これに合わせて、演出注釈の場面単位の呼び出しで「中心キャラと、各人が来る行・去る行（最初からいる・最後までいるなら空）」だけを答えさせ、立ち絵の顔ぶれはプログラムで組み立てた（`probe_scene_portraits.py --mode central`）。ひだまり以外の場面を増やすため、モノノケ（IQ4_XS・QAT）と鉄と血（IQ4_XS・QAT）も上限なしで生成したが、4人以上の場面ができたのは鉄と血の QAT だけだった（4人1、5人2、6人1）。

- 21場面（ひだまり14、モノノケ3、鉄と血4）すべて1回目で回答。中心キャラは1人0回、2人8回、3人13回。立ち絵の入れ替えは21場面で計10回（場面あたり0〜2回）。
- 来る・去るの行は本文と合っている: モノノケの朧は2場面とも、暗がりから現れる行で加わり、霧になって消える行で外れる。QAT の先生の場面は陽葵が教卓へ歩いてくる5行目。鉄と血では、エレナが「部屋の入り口で」口を開く行、アルリックが盾でゼノスの行く手を阻む行で加わる。
- 遠くからの声（モノノケの厳山）、台詞の無い人（拓海）、名前の無い兵士は中心にならない。
- ずれ: ひだまり UD 第2章で、教室にいた冴子を、最初に口を開く行で「来る」とした（本文に歩み寄る記述は無い）。IQ4_XS 第1章の結衣は、場面の最初の行を来る行として答えた（最初からいるのと同じ扱いになる）。
- 判断が分かれそうな選択: 鉄と血 QAT 第2章の要塞の攻防（6人）は、中心をアルリックとカイルにし、それぞれ4行話すバルドールとヴァルガス（敵側）を顔枠にした。罠を仕掛けるアルリックと、恐怖から立ち上がるカイルが場面の軸、という理由。

## 製品への実装と通しの確認（2026-10-18）

この記録の結論を製品に入れた。新しく計画を始める作品だけに効き、既存の作品の依頼は変わらない。

- STEP3の承認ダイアログで「登場キャラの上限（メイン含む）」を選ぶ。初期値は今のモデル設定での目安（16kで5人、32kで8人、推論ありならそれぞれ1人少なく、`script_cast.cast_limit_guide`）。上限は11人。計画の台本設定に `cast_limit` と `open_scene_cast` が入る。
- キャスト計画: 上限のある作品では「1〜2人を目安」をなくし、先にメインの周りの人（surroundings）を挙げてからサブを作る。サブは「上限 − メイン人数」まで。
- 場面の人数上限: 契約は16人まで受け付け、生成する出力形式は従来どおり3人を求める。`open_scene_cast` の作品だけ、章の場面計画の「最大3人」を消して出力形式を広げ、聞こえる声の配役上限も広げる。
- 4人以上の場面: 演出の後に場面単位で中心キャラ（1〜3人）と来る行・去る行を答えさせ（`narrative.central_cast`）、中心キャラだけが入退場する。残る人は位置を変えない。それ以外の人の台詞は `RemoteVoice(source="offstage")` で、プレイヤーは明るい縁取りの顔枠に出し、声は加工しない。
- イベントCGは3人まで。超えたらその時点で立ち絵に出ている人を優先する。

通しの確認（キャスト計画も新しい指示で生成、演出あり、上限8）:

| 作品 | サブ（surroundings） | 4人以上の場面 |
|---|---|---|
| ひだまり（UD） | 2人: 担任、トレンドリーダーの級友（周りに3人を挙げた） | 第1章に2場面。中心はメイン3人、級友と担任は顔枠（各4行） |

ティラノのプレイヤー（鉄と血 第3章の書き出し）で、立ち絵の無い新兵の台詞が顔枠に出て、舞台の3人は誰も強調されないことを確かめた。単体3,242件、結合424件、Web の型チェックと199件のテストが通る。

## 台詞の無い配役への対応と、鉄と血の再生成で見えたこと（2026-10-19）

再生成したひだまり（project `adfa01e4814c45d3881b131c919b0527`）の第1章3つ目の場面（配役: 陽葵・紬・真壁先生）で、本文に一度も出てこない先生の立ち絵が最初から出ていた。3人以下の場面は従来の入退場（配役全員を最初に登場させる）のままだったため。

- 中心キャラの判定を、4人以上の場面に加えて「台詞の無い配役がいる場面」でも使うようにした。全員が話す3人以下の場面は従来どおり。
- 台詞が1つも無く、名前のどの部分（空白・中黒で分け、読みを除く）も場面の本文に出てこない人は、モデルが選んでも中心キャラにしない。
- 検査は、台詞の無い人には人数に関係なく登場の演出を求めない。
- 同じ場面を製品と同じモデル設定で3シード判定し直した。3回とも中心は陽葵と紬で、先生は立ち絵に出ない。この場面の本文には「真壁」「先生」とも0回なので、モデルが選んでも外れる。4つ目の場面（先生の名前が5回出る）は従来どおり陽葵・凛花・紬が立ち絵、先生は顔枠。
