# ローカルAIのメモリー使用量のピーク（2026-11-02）

各工程で最もメモリーを使う経路について、VRAMとRAMのピークを測りました。方針は「LLM以外はVRAM 12GBを最低要件、24GBがなければLLMは外部API推奨」です。画像編集とTTS Largeは、余裕のあるPC向けの追加機能として扱います。8GBのVRAMには対応をうたいません。

## 測り方

- このPC（RTX 5090 32GB、Windows・WDDM）で、本番と同じ実行経路・引数を使いました。稼働中のWorkerと重ならないよう、本体と同じGPUロックを取ってから1件ずつ実行しています。
- **VRAM**：`nvidia-smi` のデバイス全体の使用量を100msごとに読み、実行前の常駐分（デスクトップなど、約2.0GiB）を引いた増分のピークです。CUDAの管理分とPyTorchが確保したまま持つ分を含みます。
- **RAM**：PC全体の使用メモリー（総量−利用可能量）の増分のピークです。プロセスごとの確保量（コミット）は、WDDMではVRAMの確保分まで含んで大きく出るため使っていません。
- 測定スクリプトと各条件の記録（`memory.json`、VRAM・RAMの推移）は `outputs/memory-peak-20261102/` にあります。

## 結果

| 工程 | 条件 | VRAMピーク | RAMピーク |
| --- | --- | ---: | ---: |
| LLM Gemma 4 31B UD-Q4_K_XL | 32k / 16k | 22.0 / 20.7GiB | 19.3 / 19.8GiB |
| LLM Gemma 4 31B QAT | 32k / 16k | 20.5 / 19.3GiB | 18.3 / 18.4GiB |
| LLM Gemma 4 31B IQ4_XS | 32k / 16k | 19.7 / 18.4GiB | 17.5 / 17.5GiB |
| 立ち絵 Anima | 1152×1536・30ステップ・背景除去まで | 6.5GiB | 4.2GiB |
| TTS Small fp32 | ボイスデザイン / クローン | 7.7 / 7.7GiB | 6.8 / 6.8GiB |
| TTS Small bf16 | ボイスデザイン / クローン | 6.8 / 7.3GiB | 6.8 / 6.8GiB |
| TTS Large fp32 | ボイスデザイン / クローン | 18.1 / 17.0GiB | 23.1 / 23.2GiB |
| BGM Stable Audio 3.0 Medium | float32 / float16、120秒 | 10.8 / 5.9GiB | 6.4 / 8.7GiB |
| 画像編集 Qwen-Image-2.1 Turbo | 12GB設定・参照3人・1536×1024 | 10.3GiB | 約38GiB（生成中17〜25GiB） |

- **LLM**：llama-serverを本番と同じ引数で起動し、コンテキストをほぼ満杯にした入力（31,704 / 15,320トークン）で1,024トークンを出力させました。VRAMは読み込み直後にほぼピークに達し、推論中の増加は0.02GiB以下です。32kと16kの差は約1.3GiBです。RAMは、開いたままのモデルファイルの分で、OSが回収できる種類のメモリーです。IQ4_XS・16kは2回測り、2回とも同じ値でした。
- **TTS**：約22秒の長い台詞で測りました。Small bf16のクローンは、読み込み後の待機が3.7GiBで、音声への変換と透かしの埋め込みのところで7.3GiBに達します。ピークの大半は音声の長さに比例する作業領域なので、重みが半分になってもあまり下がりません。参照音声も約22秒です。
- **BGM**：精度の比較と設定については [Stable Audio 3.0の設定](../setup/stable-audio3.md#ワーカーのvramに合わせた設定2026-11-02) にあります。
- **画像編集**：読み込み時にパイプライン全体をbf16のままメインメモリーに載せ、その後で描画本体を8ビットに変換するため、読み込み中に一時的に約38GiBになります。生成中はテキストエンコーダーをメインメモリーに置いたままにし、仕上げのときは描画本体も戻すので17〜25GiBです。設定一覧の「12GB・9.2GiB」はPyTorchの割り当てで、今回も9.2GiBでした。

## 見えたこと

- 12GBのGPUでは、立ち絵・TTS Small・BGMのfloat16は収まります。BGMのfloat32とTTS Large fp32は収まりません。
- 8GBのGPUでは、外部APIと画像編集なしの構成でも、立ち絵6.5GiB・TTS Small bf16 6.8〜7.3GiB・BGM float16 5.9GiBで、入るかどうかの境目です。実機でも、使えるVRAMを制限した状態でも試していません。
- RAMを最も使うのは画像編集で、次がLLMを手元で動かす場合です。外部APIを使い画像編集を使わなければ、各工程のRAMの増分は4〜9GiBです。
