# その場にいない声を演出付けで判定する実験（2026-10-15）

電話・通信・録音などの「その場にいない人の声」を、枠付きの胸像と声の効果で表示する案のための実験。
演出付けの指示とスキーマに台詞ごとの2項目を足し、どこまで正しく判定できるかを確かめた。アプリのコードは変更していない。

## 結論

- 通信の台詞97行はすべて「その場にいない声」と判定できた。種類（電話・無線など）も全行で認める答えに入った。
- 回想の台詞3行もすべて正解。留守電を再生した声と、同じ人物がその場で呟く台詞の区別もできた。
- 立ち絵で出さない人物（29場面）と、声が先に聞こえて途中から現れる人物（5人）も、判定から導いた結果がすべて正解だった。
- 誤りは3つの型に限られる。1つは期待する答えの付け方の問題（無線で話す視点人物の側）。
- 直前の発話を参考として足しても、はっきりした改善は無い。
- 指示を足しても、既存の注釈（声の感情・表情・演出）に揺れを超える変化は見られなかった。

## 方法

検証データは [remote-voice-cases](assets/remote-voice-cases/README.md)。生成済みの10作品から14場面、生成済みの作品に無い型を補う手書きの15場面。
判定は `scripts/story/probe_remote_voice.py`。製品の指示とスキーマに、台詞ごとの次の2項目と、判定基準の一段落を足した。

- `voice_source`: present（その場の声）/ remote（その場にいない声）/ recollection（回想）
- `voice_channel`: none / phone / voicemail / radio / speaker / telepathy / message

- モデル: `gemma-4-31B-it-UD-Q4_K_XL`、reasoning none、コンテキスト 16,384、temperature 0.65
- 製品と同じ10行ずつのまとまりで、製品と同じ形式の検査と1回の再試行
- batch: 製品と同じ入力。preceding: その前の10行を参考として足した入力

### 誤りの型

1. 無線で話す視点人物の側も「その場にいない声」とされる（機体同士の通信、格納庫の通信機。batch で7行）。二人とも機器越しに話しているので、判定にも筋は通る。期待する答えの付け方の問題として扱う。
2. 頭に響くシステムの声を【】で書いた地の文2行を「念話」とする。地の文はその場の声と指示しているが、内容としては的確。
3. 留守電の文面の直後の台詞（`voicemail-murmured` の s1-u13）を「留守電」とする。batch のみ。手がかりの乏しい行で、preceding では正解した。

## 既存の注釈への副作用

通信の声がほぼ無い9場面・18まとまり（172行、うち台詞89行）を、指示を足さない現行の製品のまま同じシードで実行し、batch の回答と比べた。

| 項目 | 現行 | 指示を追加 |
| --- | ---: | ---: |
| 声の感情の一致（台詞） | 基準 | 75% |
| 表情の一致（台詞） | 基準 | 82% |
| 内心が英語の行 | 136 | 136 |
| 演出 focus / pause / blackout | 76 / 33 / 8 | 78 / 37 / 7 |
| 演出 expression | 26 | 36 |
| 出力トークン（1回平均） | 940 | 1,106 |

一致率は、シードだけ変えた場合の揺れ（声の感情75%・表情84%、[演出付けに渡す資料を絞る実験](staging-context-probe-20261013.md)）と同程度。
聞き手の表情の演出がやや増えたが、この規模では揺れと区別できない。出力の増加は2項目の分。
内心がほぼ英語で返るのは現行でも同じで、この追加とは関係が無い（内心と声の出し方は画面にも音声合成にも使われていない）。
