追記：小規模確認後、同じ新プロットと第1章から再開して3章を完遂した。[通読レビュー](script-continuation-r5-review-20260925.md)を参照。以下は小規模確認時点の記録。

2026-09-25。実験用 `script_continuation_v1`、prompt 5 / implementation 6 / contract revision 4。revision 4の通読レビューを受けた変更。可変章数や長編の展開密度は今回の対象外。

## 実装した流れ

1. 最初から3章に収まる規模を条件に、核心と主要な出来事の連鎖を作る。核心では結末で本人が取る行動を定め、出来事では試み・結果・選択・次の状態と、主要人物本人の行動を記す。`story-chain.json` に保存する。
2. 保存した連鎖を次のLLM要求へ渡し、各章の題名・役割・最後に担当する出来事の位置だけを決める。`chapter-allocation.json` に保存する。全出来事を順番どおり一度ずつ、空の章なしで配分する参照チェックを行う。
3. 配分から `plot.json` と既存互換の `outline.json` を機械的に作る。配分のLLMに出来事や結末を再生成させない。複数の出来事を含む章の互換要約も、出来事ごとの因果の順を保つ。
4. 章計画・場面執筆には、その章の出来事と本人の行動を渡す。過去は実台本から判断する。既に達成した予定はその結果を使い、同じ合意の再演や、章末用の例外の追加を避けるよう指示する。

3〜9個の主要出来事という範囲は今回の小規模実験の出力を制限するもので、場面数や将来の長編の密度を規定するものではない。章への配分も均等にする必要はない。

この方式を適用するのは承認済み3章の実験。3章以外の従来経路は保持した。話者ID、台本、発話分離、演出、Script・Tyranoの出力契約は維持している。

全体計画は従来1回から2回へ増える。独立した意味検査・修復工程は追加せず、構造や参照の不備だけを既存の有限再試行で扱う。計画の連鎖・配分と、既存の版・hash・入力選択を保存する。後続経路が調整された場合は、その章の元の出来事を入力から外し、変更前後の計画を同時に指示しない。

## 技術確認

関連139テスト成功、対象PythonファイルのRuff成功。新方式のテストは、3章の模擬生成から実際のTyranoソースまで確認した。出来事の順番と欠落・重複、人物行動の入力、中断した配分の再開、保存した配分の変更検出、調整後の経路から旧出来事が外れることも確認した。

模擬試験は複数の出来事を同じ章へ割り当てるケースを含む。これは構造と受け渡しの検証であり、実モデルによる章間品質の証明ではない。

## 読めた範囲の結果と限界

新プロットは、対立から方針決定を経て、合意した方法を実行して完成する流れになった。revision 4にあった「方針に合意した後、最後の一枚だけを例外にして再び迷う」という筋は今回はない。最後の出来事には、葵が説明札を書き、蓮が葵の判断を待ってから固定するという本人の行動が入っている。

一方、出来事の内容にはまだ抽象的な説明がある。第2の出来事は依然として蓮の説得と葵の納得が中心で、試した結果から両者の判断が変わる描写が十分かは未確認。第1の出来事内でも「理由をぶつける」と「問いかけを無視する」の関係は粗く、場面へ落とす段階で整理が必要になっている。

実際の第1章は、配置の提案・独断の仮置きと撤去・価値観の衝突という3場面になり、先の章の合意までは進んでいない。ただし、口論が長く、同じ主張を繰り返す傾向は残っている。計画上の改善を、完成した3章の品質向上と同一視しない。

追加の調整や再生成で成功例を選ぶことはせず、この小規模確認で停止した。次の通し生成では同じ新プロットと第1章を引き継ぎ、第2章の選択が第3章の行動として使われるか、蓮が実際に相談・確認の方法を変えるかを読む。通し生成前にユーザーへ報告する。
