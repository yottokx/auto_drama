[r13の通しレビュー](script-continuation-r13-review-20260926.md)を受けた修正。既存作品・旧実験は書き換えず、同じ「境界線のエクリプス」・seed 1を比較対象とした。3章の通し生成は、この実装確認では実行しない。

## 実装した内容

### 章の冒頭へ新しい行動を直接渡す

第2章以降の`continuation`を、章全体の抽象的な接続方針から「前章の最後の反応を受け、誰が最初に何を新しく行うか」へ変更した。1〜2文・最大240文字とし、最初のScenePlanの最初のrequired_eventへ機械的に組み込む。元の出来事とIDを残すため、イベント数の上限8も変わらない。

最初の行動を章全体への指示として繰り返さず、後続場面へ再掲しない。場面計画の生成指示では、その行動を受けた次の応答からrequired_eventsを書くよう求める。入力末尾は保存台本・作例で終わらせず、今回の作業依頼を最後に置く。履歴の原文や必須資料はこの並べ替えで削らない。

これは入力の改善であり、生成された行動が意味的に新しいことを合否判定する検査ではない。

### 長い完全一致の転載だけを除く

第2章以降の第1場面に限り、前章末尾と新しい冒頭が**6発話以上かつ本文300文字以上**完全一致する場合に、その冒頭部分だけを除く。話者・本文・句読点・空白は完全一致を要求し、空行とLF/CRLFの違いだけを許容する。短い台詞、意味の似た反復、章内の途中にある一致、不正な台本は変更しない。

原応答は`.raw.txt`とLLM記録に保持する。除去後は`.effective.txt`、除去範囲・前後のhash・除去量・残った本文量は`.overlap.json`と`report.chapter_boundary_corrections`へ保存する。発話分離・演出・normalized・章履歴・Tyrano出力・本文量の集計には除去後を渡す。

出力上限による続筆は、元原稿のanchorで連結し終えてから重複を除く。全量がコピーなら証跡を保存して停止する。再開でも同じ保存応答から停止し、品質による再生成を繰り返さない。短く残った本文を水増し・自動再生成しないため、分量不足は集計とレビューにそのまま現れる。

### プロットの下書きを「先の経験 → 後の利用」にする

`resolution_basis`を`earlier_experience`と`later_application`の2欄へ置換した。各180文字以内、最大2組、不要なら空を許す。先に誰が何を試し、具体的に何を得るか、その結果の何を後で使うかを対にする。「限界になる」「危機が深まる」だけで成立根拠を代用しないよう指示する。

外的な決着では、本人の決意だけでなく障害側の条件がどう変わったかを具体化する。下書きは同じプロット応答内だけで使い、保存済みの主要な出来事列を引き続き正本とする。別のLLM工程・意味検査・参照ID・台帳は追加しない。

### 会話の起点を具体化する

`topic`と`exchange`は、本人がその場で済ませたい用事と、相手の都合・好みが表れる返答から作る。場面計画のobjectivesとrequired_eventsへ引き渡し、抽象的な人物評の言い直しを減らす。作例のプロット・会話計画をversion 2へ更新した。作例は容量不足なら先に外す任意資料のまま。

人物ID付き台本、NARRATOR、発話分離、演出、Script/Tyrano、各話本文約4,000字・台詞約2,000字の目安は維持する。Gemma reasoning none / 実16kを使い、32k・64k等へ設定を拡張する仕組みも維持する。文字数から再生時間は保証しない。

- 完全一致の境界、閾値未満、話者違い、部分一致、途中一致、空行/改行差、全コピーを確認。
