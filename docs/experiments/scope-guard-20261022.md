# 長尺化で章の範囲を守る設定を試す（2026-10-22）

製品で書いた長尺化の作品2本で、章の場面計画が次の章の予定を先に演じ、次の章がそれを言い直していた。10/17 に作った実験用の設定 `chapter_scope_guard`（`cast-size-20261017.md` の「章の範囲を守る対策を入れた再生成」）が、製品の長尺化では有効になっていなかった。本体のジョブから後半の章だけを、この設定を有効にして書き直して比べた。結果を受けて、新しい長尺化の計画では既定で有効にした。

## 見つかった問題

- ひだまり1年1組（4章、32k、ストーリーライン `34d6d476`）: 第3章の場面計画が、全体プロットでは第4章の手順だった6つのうち5つ（先生の送り出し、私服での待ち合わせ、氷室との出会い、パフェの写真、次のテストへの宣言）を取り込み、終了状態を「物語が締めくくられる」にした。第4章に残ったのは写真の構図の1手順だけで、場面計画は服のほめ合いと宣言を言い直し、プロットに無い駅のホームの場面を足した。第4章は2場面・3,102字（第3章は6,728字）。
- 鉄と血の叙事詩（6章、ストーリーライン `7a37abf2`。前の実験の鉄と血とは別の作品）: 第5章の最後の場面の終了状態が「撤退を決意する」で、本文でもヴァレリウスが撤退を承諾して号令をかけた。撤退の同意は第6章の手順3。第6章は第1場面でもう一度撤退を号令し、第3場面で最後通牒と撤退の承諾を演じ直した。

## なぜ製品で無効だったか

- 10/17〜18 のキャラ数の実験でこの設定を作り、先取りと再演が止まることを確かめた。製品にはキャラ上限と4人以上の場面だけを入れ、この設定と `sized_allocation` は既定で無効の実験用の設定として残った。採否の記録は無い。
- 10/19〜21 の長尺化の実験は、入力に「製品と同じ計画オプション」（`planned_cast_appears`・`open_scene_cast`・`cast_limit`）を付けて走らせた。この設定は無効のままだった。`sized_allocation` は `--balanced` として実験に取り込まれた。
- 製品への実装の計画（`long-form-plan.md`、10/21）は「実験用スクリプトが差し替えていた部分を、製品のコードとして書き直す」範囲で組んだ。この設定は差し替えの対象ではなかったので、範囲に入らなかった。実装したセッションは計画を書く直前にこの設定をgrepで見ているが、採否は検討していない。章の境目の先取りは「後で決めること」に残っていた。

## 方法

- `scripts/story/rerun_product_chapters.py`: 製品の章ジョブの依頼（`services/worker/cache/m2/jobs/<namespace>/<job>/job-request.json`）を読み、指定した設定を有効にして、同じ章ジョブのコード（`m3_pipeline.generate_job`）で新しい作業フォルダに書き直す。最初の章は製品のチェックポイント（前の章までの台本と状態）から始め、設定が変わる分だけ識別子を付け直す。後の章は、書き直した前の章から続ける。承認、承認した全体計画、シードは製品のまま。
- 有効にした設定: `chapter_scope_guard`、`skip_staging`（演出注釈を作らない。次の場面と章は本文だけを読むので、本文には影響しない）。
- 依頼の番号は製品から引き継ぐ。章の最初の依頼（前の章の履歴メモ）は製品と同じシード・同じ入力で、照合がその後に入るので、場面計画のシードは製品より1つ後になる。
- 条件は製品のまま（gemma-4-31B-it-UD-Q4_K_XL、推論なし、32k、`long_form`・`planned_cast_appears`・`open_scene_cast`・`cast_limit`）。
- 出力: `outputs/scope-guard-20261022/hidamari`（第3・4章）、`outputs/scope-guard-20261022/tetsu`（第5・6章）。

## 言えること

- 2作品とも、有効にすると、章の場面計画が次の章の予定を取り込むことは無くなり、先取りから来る言い直しも消えた。本文が先へ進んだ場合も、次の章の照合と計画がそれを受けて、演じ直さずに続けた。章の長さは2作品ともそろう方向に動いた。
- 製品の長尺化の新しい計画で既定にした（`planning_service.py` の `script_options`）。`check_text_long.py --product` も同じく有効にした。
- 10/22 より前に始めた長尺化の計画は、STEP4で承認（再承認）すると承認の設定に入り、その承認から始まる制作は第1章から有効になる。プロットはそのまま。すでに始まっている制作は、章の引き継ぎがその設定で検査されるので、途中の章から有効にはしない。

### 章の開始条件が古い（長尺化の肉付けの不具合）

プロットの各章の「開始:」が、前の章の最後の手順ではなく、骨組みの最後の手順の結果になっている。ひだまりでは、第2章が第1章の6手順の4番目、第3章が第2章の5手順の3番目、第4章が第3章の6手順の5番目の結果。`script_expansion.expanded_events` が、肉付けした章の出来事の開始条件に骨組みの連鎖の `events[0].start_condition` を使い、前の章で骨組みの最後の手順の後ろに足された手順を反映していない。場面計画はこれを予定の開始条件として受け取り、前の章の途中から書き始める。10/22 のひだまりの書き直しで見た第4章冒頭の言い直しもこれと見られる。未修正。
