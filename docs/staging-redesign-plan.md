# 演出付けの回答の形と指示文の見直し（設計案、2026-10-25）

演出付け（`narrative._staging`）の指示文と回答の形を見直す。目的は、モデルが変わってもある程度同じ付き方になり、画面と声に効く演出が必要なだけ付くこと。focus は廃止する。まだ実装しない。

## 1. 今の形と、分かっていること

### 今の回答の形

- `emotions`（発話ごとに1件、件数ぴったり）: `utterance_id`、`inner_emotion`（内心、自由記述）、`voice_emotion`（声の感情、7種）、`delivery`（言い方、自由記述）、`expression`（話者の表情、12種）、`voice_source` / `voice_channel`（声の出どころ）。
- `directions`（任意の配列、最大50件）: `focus`、`pause` / `blackout`（`timing` は before / start / after、長さ ms）、`expression`（話者以外の表情の変化）。
- 指示文は、演出について形式と禁止だけを書く。「演出は任意の focus/pause/blackout/expression のみ」「演出が不要なら directions=[]」。間や暗転を何のために、どんな時に使うかは書いていない。

### 各項目の使われ方

| 項目 | 使われる所 |
|---|---|
| `voice_emotion` | 音声合成の感情タグ（😊😢😠😮😟）。`neutral` と `calm` はタグが無く、声は同じ |
| `expression`（話者） | 立ち絵の表情 |
| `directions` の `expression` | 聞き手の立ち絵の表情 |
| `pause` / `blackout` | プレイヤーの間と暗転 |
| `voice_source` / `voice_channel` | その場にいない声の表示（顔枠、声の加工） |
| `inner_emotion`、`delivery` | イベントCG・音楽の依頼の材料、完成後の調整画面。音声合成には渡らない |
| `focus` | ほぼ効いていない（7,781件中53件。`dead-directions-20261024.md`） |

### モデルによる付き方の違い

保存済みの演出の応答から数えた（Gemma 31B UD 推論なし3,022件、GPT-6 Luna 184件、Haiku 5.5 137件）。

| | Gemma 31B | GPT-6 Luna | Haiku 5.5 |
|---|---|---|---|
| 話者の表情で一番多い値 | neutral 62% | serious 44〜47% | serious 52〜64% |
| 声の感情で一番多い値 | neutral 38% | calm 40% | neutral 48〜68% |
| 間（1行あたり） | 0.23（75%が地の文の行） | 0 | 0.01〜0.07 |
| 暗転（1行あたり） | 0.044（場面頭の98件は効かない） | 0 | 0 |
| 聞き手の表情（1行あたり） | 0.09 | 0.01〜0.03 | 0.09〜0.10 |
| focus（1行あたり） | 0.49 | 0.03 | 0.03〜0.04 |
| 内心・言い方が英語 | 47%（QATは71%） | 0% | 0% |

- 任意の配列は、モデルの癖でほぼ空にも、ほぼ全行にもなる。Gemma の多い演出は、ほとんどが効かない focus と、地の文の行の前の間だった。
- 話者の表情と声の感情の「ふつう」の値が、モデルで違う（neutral か serious か、neutral か calm か）。
- 演出の暴走（同じ注釈の反復、JSONの繰り返し）は、どれも発話ごとの似た項目を並べる配列で起きた（`external-llm-phase2-20261025.md`）。
- 発話ごとに既定値（「未指定」「neutral」「空」）を入力に渡すと、それに引きずられる。ただ、外すと英語が増えた（`staging-lines-probe-20261013.md`）。

## 2. 方針

1. **プログラムで決められるものは、LLMに出させない。** 話者を明るくする（今も自動）、場面頭の暗転（場面転換が処理する）、登退場・背景（今もプログラム）、その場にいない声の行の聞き手を明るくすること（focus の代わり）。
2. **残りは、行ごとの必須の欄にして、「なし」も含む決まった選択肢から選ばせる。** 任意の配列に「足すかどうか」を任せない。どのモデルも全行で判断することになり、空になる癖と全行に付ける癖の両方を抑えられる。
3. **選択肢ごとに、使う場面を本文に結びつけて書く。** 「本文にこう書かれている行」という基準にすると、モデルごとの解釈の幅が狭くなる。
4. **回答の形で件数と順番を決める。** 発話IDをキーにした object にすれば、行の数・順番・行ごとの欄（地の文か台詞か）が形だけで決まる。同じ行を繰り返すこともできなくなる。
5. **自由記述は日本語と明記し、短くする。**

## 3. 新しい回答の形

まとまり（今と同じ最大10発話）ごとに、発話IDをキーにした object を返す。キーと順番、行ごとの欄はプログラムがスキーマで決める。

> 2026-10-25 のテスト（`experiments/staging-redesign-test-20261025.md`）で、この形は Anthropic では「文法が大きすぎる」で通らないと分かった（行ごとに形を変えると、行の数だけ文法が増える）。共通の行の形を配列で並べる形（`lines`、件数ぴったり、各行に `utterance_id`、地の文の行の声・表情は neutral・空文字でプログラムが無視）にする。欄と基準は以下のまま。

```json
{
  "s2-u1": {"before": "none", "reactions": [], "arrives": [], "leaves": []},
  "s2-u2": {"inner_emotion": "言い出しにくい後ろめたさ", "voice_emotion": "sad",
            "delivery": "目をそらし、小さな声で", "expression": "sad",
            "voice_source": "present", "voice_channel": "none",
            "before": "pause_short",
            "reactions": [{"character_id": "character-2", "expression": "surprised"}],
            "arrives": [], "leaves": []},
  "s2-u3": {"before": "none", "reactions": [], "arrives": [], "leaves": ["character-2"]}
}
```

- 地の文の行（`s2-u1`、`s2-u3`）は `before`・`reactions`・`arrives`・`leaves` だけ。声と話者の表情は、プログラムが neutral を入れる。
- 台詞の行（`s2-u2`）は、今の `emotions` の欄に同じ4つが加わる。`arrives` / `leaves` は「3a」を参照。
- `directions` 配列はなくす。focus は出させない。

### 欄の定義と選ぶ基準

| 欄 | 値 | 基準（指示文に書くこと） |
|---|---|---|
| `before` | `none` / `pause_short` / `pause_long` / `blackout` | この行の前に置く間。`pause_short`: 言いよどみ、返事に詰まる、ためらいが本文にある行。`pause_long`: 沈黙・重い告白・大きな出来事の直後で、読み手に余韻を残したい行。`blackout`: 場面の途中で時間が飛ぶ、気を失う、明かりが消えることが本文にある行。それ以外は `none` |
| `reactions` | 聞き手（場面の登場人物から話者を除く）の `character_id` と表情、最大2件 | 本文（この行か、この行の地の文）に、その人物の表情や反応が書かれているときだけ。表情は次に変わるまで続くので、変わらない人は書かない |
| `expression`（台詞の行） | 12種 | 話者の顔。各値の意味を書く。とくに `neutral` は「ふだんの落ち着いた顔」、`serious` は「張り詰めた・真剣な顔」と区別する |
| `voice_emotion`（台詞の行） | `neutral` / `happy` / `sad` / `angry` / `surprised` / `afraid` | 声に出る感情。感情が声に出ていなければ `neutral`。`calm` は声が `neutral` と同じなので、新しい依頼では選択肢から外す |
| `inner_emotion`、`delivery` | 日本語の短い文 | 日本語で書く（英語にしない）。言い方は、本文から読み取れる声の出し方だけ |
| `voice_source`、`voice_channel` | 今と同じ | 今の `VOICE_SOURCE_INSTRUCTION` のまま |

- `before` の長さはプログラムが決める（例: `pause_short` 500ms、`pause_long` 1,200ms。今の Gemma の間の中央値は500ms）。`timing` の3択はなくし、間と暗転は「行の前」に統一する（今の Gemma の間も、大半が行の始まり（`start`）に付いている）。
- 場面の最初の行は、スキーマで `blackout` を選べなくする（場面転換が暗転を処理するため。今は98件が効いていない）。
- `reactions` の `character_id` は、場面の登場人物から話者を除いた enum にする。その時点で舞台にいない人物は、今と同じく検証で落とす。

### focus の代わり

- 話者を明るくするのは今どおり自動。
- その場にいない声（`voice_source` が remote / recollection）の行では、今は全員が暗くなる。focus が効いていた53件は、ここで舞台の聞き手を明るくする使い方だった。これをプログラムの決まりにする（例: その行の直前に舞台で話した人物を明るくする。いなければ全員を暗くしたまま）。誰を明るくするかの決まりは「6. 決めること」。

## 4. 指示文の組み立て

今の指示文を次の順に組み直す。

1. 役割: 確定した本文に、声・表情・間を付ける。本文は変えない。
2. 行の種類: 地の文の行と台詞の行で、答える欄が違う（形が決めているので、説明は一言）。
3. 欄ごとの基準: 上の表の基準。選択肢の意味を短く。
4. 「迷ったら」の決まり: `before` は `none`、`reactions` は空、`voice_emotion` は `neutral`。本文に根拠がある時だけ他の値にする。
5. 声の出どころ: 今の `VOICE_SOURCE_INSTRUCTION`。
6. 自由記述は日本語。

- 「登退場はプログラムが処理します」など、プログラムが処理することは残す。
- 例文（作例）は入れない。特定の作品の失敗から写した例は使わない。
- 発話ごとの既定値（「未指定」「neutral」「空」）を入力に渡すのはやめる。空の欄が無くなるので、引きずられる元が無くなる。英語が増えた件（10/13の実験）は、日本語の明記で抑える。

## 5. 確かめ方

実装の後、指示文の文面を決める前に確かめる。

- 入力: 10/13の演出の実験と同じ5作品・17まとまり・140発話（`staging-context-probe-20261013.md`）と、Phase 2 の2作品の場面。
- モデル: Gemma 4 31B UD 推論なし（基準）、GPT-6 Luna 推論 `low`、Haiku 5.5 推論 `low`。
- 見ること:
  - 各欄の値の分布が、モデル間でどれだけ近いか（とくに表情の「ふつう」の値、`before` と `reactions` の数）。
  - `before` と `reactions` が付いた行が、モデル間でどれだけ重なるか。
  - 英語の混入、形の検証の失敗、出力トークン（focus がなくなる分、今より減る見込み）。
  - プレイヤーで数場面を見て、間と聞き手の表情が過不足ないか。
- 外部APIの費用は1回の確認で$0.05程度の見込み。

## 3a. シーンの途中の登場・退場

### 今の決め方

- **登場人物が3人までで、全員が話す場面**: プログラムだけで決める（`narrative._entrances`）。全員が場面の最初から舞台にいて、途中で退場しない。例外は、最初は電話などで声だけ聞こえる人物で、その場で初めて話す行で登場する。
- **4人以上か、話さない人物がいる場面**: 別の LLM の依頼（`narrative.central_cast`）で、中心の人物を最大3人選び、人物ごとに「その場に来る行」「去る行」を答えさせる。プログラムがそれを登場・退場・位置の移動に直す（`_stage_directions`）。

### 実際の台本

保存済みの台本192本・605場面で、場面の途中の退場は6場面・9件、途中の登場は14場面・17件だった。一方で、地の文で人物が去る・来ると書かれているのに、立ち絵が動かない場面がある。

- 「空白の転校生と静寂の境界線」s2: 「工作員は舌打ちをして影に溶けるように姿を消した」の後も、工作員の立ち絵が残る。
- 「不完全な今を生きる」scene-2: 「凪は軽く会釈をすると、ゆっくりと踵を返した」と改札へ去っても、場面の終わりまで立ち絵が残る。

3人までの場面には、本文に合わせて途中で登退場させる仕組みが無い。

### 案

行ごとの欄に `arrives` と `leaves` を加える。

| 欄 | 値 | 基準 |
|---|---|---|
| `arrives` | この行でその場に来る人物の `character_id`（場面の登場人物の enum、空も可） | 本文の流れから、その人物がこの行でその場に来たと読めるとき |
| `leaves` | この行の後にその場を去る人物 | 本文の流れから、その人物がこの行の後にその場を去ったと読めるとき |

- どちらも演出付けの依頼の中で LLM が本文の意味から判断する。言い回しの一致では決めない（地の文が無く台詞だけで去る場合や、「背後から声がした」の次の行で隣に立っている場合なども含む）。

- プログラムは、場面の最初から、一度も `arrives` が付かない人物を舞台に出す（今と同じ）。`arrives` が付いた人物はその行で登場させ、`leaves` の後に退場させる。去った人物が後で話したら、その行で戻す（今の、声だけの人物が後で来るときと同じ扱い）。
- 中心の人物を選ぶ `central_cast` は「誰を立ち絵にするか」だけを答える形にし、来る行・去る行は `arrives` / `leaves` から取る。これで、人数に関わらず同じ欄で登退場が決まる。
- `central_cast` と演出付けの依頼の順番（今は、どちらが先に呼ばれ、どちらの答えを使って立ち絵を決めているか）は、実装の前にコードで確かめる。

## 5a. あわせて整理できるプログラムの演出（LLMの指示文とは別）

場面の開始時の無意味な退場は、LLM ではなくプログラムが出している。`packages/narrative/script_conversion.py:103-108` が、場面ごとに最初の行の前で、立ち絵のある全員を退場させている。その後、場面の登場人物を登場させ直す。演出付けの依頼（`_staging`）の選択肢には退場が無い（「登退場はプログラムが処理します」）。

- 保存済みの台本で、退場2,288件のうち1,990件は画面に効いていない（`dead-directions-20261024.md`）。直後に同じ人物が登場し直す分と、もともと舞台にいない人物の退場。
- 背景の指定し直し181件も同じくプログラムによる（前の場面と同じ背景）。
- 害は無いが、台本・演出タブでは効かないチップになる（今は同じ行・同じ timing の退場を1つにまとめて表示している）。
- 整理するなら: 場面の開始時には、舞台にいて次の場面に出ない人物だけを退場させ、同じ背景は指定し直さない。続けて出る人物の位置や表情を場面の開始時に戻す働きがあるかは、実装の前にコンパイラで確かめる（表情は、場面の開始時に全員が通常の顔に戻る扱い。`packages/contracts/expressions.py`）。
- 10/24 に、focus の削除と一緒に対応するかもしれないとしていた（`dead-directions-20261024.md`）。

## 6. 決めること

- その場にいない声の行で、誰を明るくするか（例: 直前に舞台で話した人物）。
- `voice_emotion` から `calm` を外すか（既存の台本の `calm` はそのまま読める）。
- `pause_short` / `pause_long` の長さ。
- 既存の作品への届け方。新しい形は新しく演出を付ける章から使い、既存の台本は今のまま読む（focus は効かないので残っていても害は無い）。既存の作品にも新しい付き方を入れたいなら、演出だけ付け直す経路が要る。
- イベントCGの区間の中の表情（378件が効いていない）は、演出付けの時点で CG の区間が決まっていないので、この見直しでは扱わない。
