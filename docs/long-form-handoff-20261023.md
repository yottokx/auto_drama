## このセッションで分かったこと

### 章の範囲を守る設定（chapter_scope_guard）

- 10/17 のキャラ数の実験で作り、効果を確かめたまま、採否を決めずに実験用の設定として残っていた。長尺化の実験はその時の製品の計画オプションで走らせたので無効のまま進み、本体への実装計画（「実験用スクリプトが差し替えていた部分を移す」）の範囲にも入らなかった。実装したセッションは計画の直前にこの設定を grep で見ているが、採否を検討していない。
- 無効のままだと、章の場面計画が後の章の手順を細かいところまで見て先に演じ、次の章が言い直す。ひだまり4章は第3章が第4章の6手順のうち5つを取り込んだ。鉄と血6章は第5章で撤退を承諾し、第6章で2回演じ直した。
- 有効にすると、後の章は題名・役割・到達点だけで渡り、第2章以降の場面計画の前に前の章で済んだ手順を照合する。2作品とも、先取りと言い直しは消え、章の長さがそろった（詳細は実験記録）。
- 本体の章の作り直しは、計画を作ったときの設定を使う。既存の作品の途中の章からガードを付けることはできない（章の引き継ぎのチェックポイントが設定込みで検査される）。付けるには、STEP4で全体計画を再承認して第1章から制作し直す。

### 章の開始条件が古い（10/24 に修正済み）

- 長尺化のプロットで、各章の「開始:」が前の章の最後の手順ではなく、骨組みの最後の手順の結果になっている。ひだまりでは、第2章の開始が第1章の6手順の4番目、第3章が第2章の5手順の3番目、第4章が第3章の6手順の5番目の結果だった。
- 場所: `services/worker/generation/script_expansion.py` の `expanded_events`。肉付けした章の出来事の開始条件に、骨組みの連鎖の `events[0].start_condition` をそのまま使っていて、前の章で骨組みの最後の手順の後ろに足された手順を反映していない。
- 影響: 場面計画はこれを予定の開始条件（`planned_start_condition`）として受け取り、前の章の途中の状態から書き始める。ひだまりでは、第2章冒頭で第1章第3場の注意と仲裁を、第4章冒頭で氷室への誘いと断りを繰り返した。肉付けがあれば、どの作品でも起きうる。
- ユーザーに「直しますか？」と聞いたところで引き継ぎになった。直すなら、肉付けは章ごとに順に行うので、第N章の開始条件を第N−1章の肉付け後の最後の手順の結果にすればよいはず。保存済みの計画との互換（既存の作品の識別子が変わらないこと）を確かめる必要がある。

### ガードと関係なく残っている問題

- 話者の取り違え: 配役にいない人物の台詞を、その場の配役の誰かに寄せる。鉄と血では、諸侯の叫び→イゾルデ（元の版と10/22の書き直し）、兵士→アラリック、伝令→カシアン（fix3）。台本の外の声に話者を立てる仕組み（`voice-N`、`script_voices`）が、これらの場面では働いていない。
- 本文が場面計画より先へ進む（鉄と血の第5章の終わり）。ガードは場面計画には効くが、本文の勢いは止めない。
- プロットが同じ出来事を2章に持つ（鉄と血のカシアン、救護）。肉付けの「前の章と同じ役回りの禁止」が効いていない。
- 場面どうしの食い違い（猟師の隠し経路があるのに垂直の岩壁を登る、一緒に着替えたのに駅前で待ち合わせる）。どちらもプロットの手順が両方を持っている。
- 感情ラベルのずれ（敗北を認める台詞に〔喜び〕、嘲りに〔悲しみ〕、怯えに〔怒り〕）。英語の口調の注釈の混在。
- 演出注釈: 各章の第1場に登場が無い、場面の途中の「暗転」が多い、舞台にいない人物まで毎場面「退場」が並ぶ（10/22 の最初のレビュー。整形側か生成側かは未確認）。

## 実験の足場

- `scripts/story/rerun_product_chapters.py JOB... --output-dir DIR --option NAME [--shift N]`: 本体の章ジョブの依頼（`job-request.json`）を読み、指定した設定を有効にして、本体と同じ章ジョブのコードで新しいフォルダに書き直す。最初の章は本体のチェックポイントから始め、後の章は書き直した前の章から続ける。ジョブのフォルダは連続した章を章の順に渡す。本体のワーカーを止めてから実行する。例は実験記録の「方法」。
- 本体の作業フォルダ: `services/worker/cache/m2/jobs/<16桁>/<ジョブID>/`。章ジョブは `script/` の下に `plot.json`・`plot.md`・`chapter-allocation.json`・`experiment.json`（`script_options` が入る）・`chapters/chapter-NNN.plan.json`（場面計画）・`chapters/chapter-NNN.md`（本文）。全体計画（STEP4）のジョブも同じ形で `skeleton-plot.json` と `story-chain.json` がある。DB（`data/auto_drama.db`）を開く必要はない。
- 作品の探し方: `plot.json` の中では人物は ID で、名前は入っていない。章題は入っているので、章題で `Select-String` する。同名の作品（フォークやモデルの癖で同じ題名）が多いので、`job-request.json` の `payload.storyline_id` と `chapter_number` で区別する。音声・画像のジョブのフォルダはアクセス拒否になるが、無視してよい（`-ErrorAction SilentlyContinue`）。
- 前の実験の足場（`check_text_long.py`、`drop_last_chapter.py`、`probe_chapter_count.py`）は前の引き継ぎのとおり。`check_text_long.py --product` は今はガード付き。

## 作業上の注意

- 前の引き継ぎの「作業上の注意」はそのまま有効（日本語で、設計の相談中は実装を提案して終わらない、頼まれた範囲だけ、作品の例を指示文に書かない、長い生成は章ごとに報告、など）。
- 既存の作品・制作中の作品に効くかどうかは、変更を報告するときに一番目立つ所に書く。このセッションでは、ガードが既存の作品に付かないことを報告の中の一行にしか書かず、ユーザーは付いているつもりで鉄と血を作り直してしまった。
- 本体の変更は、新しい計画にだけ `script_options` の項目を入れ、項目のない計画は作ったときの設定のまま動かす作り。章のチェックポイントは設定込みで検査されるので、制作の途中で設定を変えると引き継ぎで止まる。
- Markdown の台本の整形はユーザー側で行っている（「AIオートドラマ台本エクスポート」はリポジトリのコードではない）。登場人物の欄が空の人物がいるのは整形側の事情かもしれない。
- テスト: `uv run python -m pytest tests/unit --deselect tests/unit/test_audio_files.py` と `tests/integration` を別々に（`python -m` を付けないと `scripts` を import するテストが落ちる）。
