# M1の保存境界と契約

制御サーバーだけがSQLiteと成果物ストアを更新します。ワーカーはHTTPで入力を取得し、完成したZIPを一度に返します。ReactはHTTP APIをpollし、再接続時もサーバーの保存状態を取得します。

| 保存対象 | M1の責務 |
|---|---|
| project | ユーザー指示、章数、設定版、schema版 |
| generation_run | 入力の版系列、生成方針、設定版、実行状態 |
| job / job_dependency | 入力脚本成果物、設定スナップショット、依存、優先度、上限、採用結果 |
| job_attempt | ワーカー、試行番号、一意なリース、期限、エラー区分、開始・終了 |
| artifact | 論理ID、追記する内容版、SHA256、ファイル参照、生成元ジョブ・試行、来歴 |
| worker | 名前、能力、最終通信 |
| schema_migration | SQL版、ファイル名、改行正規化後のSHA256 |

M1は一ジョブごとにgeneration_runを作成します。承認、生成プロファイル、モデル登録、chapter_build、複数章の物語状態は、それぞれを使用する後続工程でマイグレーションを追加します。使われない空の機能をM1のAPIとして公開しません。

## ジョブの一貫性

`BEGIN IMMEDIATE` で候補選択と試行作成を直列化します。ジョブ依存は新規登録時に既存の同作品ジョブだけを参照でき、後から辺を書き換えないため循環しません。完了済み前提を持つジョブのうち、対応能力と優先度で選びます。一ワーカーに有効な試行がある間は次のジョブを渡しません。

結果採用では、ジョブ・ワーカー・リースID・有効期限を照合し、入力から再計算したZIPと完全一致することを検証します。ファイル保存後にリースを再確認し、成果物行と完了状態を同じトランザクションで保存します。通信の再送は同じ成功試行と同じハッシュの場合だけ冪等に受け付けます。

再起動時に有効な試行を強制失敗にはしません。継続中のワーカーはそのまま結果を返し、消失したワーカーは期限切れで回収します。GPUモデルの停止・再開や複数PC認証の意味はこの段階では付与しません。

## 成果物と変換

成果物本体はSHA256で配置し、DBに参照がないファイルは取得できません。Windowsではファイルのfsyncを行い、POSIXではrename後のディレクトリもfsyncします。Windowsでの電源断に対するディレクトリエントリーの永続性はOS・ファイルシステムに依存し、配信時のハッシュ再検査で欠落・破損を検出します。

中間脚本は固定ID・話者・表示文・読上げ文・声の感情・話し方・音声参照を保持します。演出は発話IDと前/開始/後の位置へ紐付け、許可された背景、登退場、位置、強調、暗転、間だけを変換します。本文・タイトル・人物名をタグ属性へ挿入せず、ティラノの文字列規則に従ってエスケープします。バックログ側のHTMLも固定ヘルパーでエスケープします。

ZIPは順序・時刻・属性を固定し無圧縮で作るため、同じ中間JSONと素材から同じバイト列になります。異なる作品ID・素材成果物IDを与えた入力は異なるJSONであり、同一出力の対象ではありません。M1では入力の版と再現性を優先し、素材だけが同じ別作品のZIPを同一にする処理は行いません。
