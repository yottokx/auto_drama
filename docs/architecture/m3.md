# M3の制作・公開境界

## 承認と制作

`m3_production` は一つの `m2_approval` とその成果物に結び付きます。新規承認と最初の `m3_narrative` ジョブを同じトランザクションで保存します。過去の承認は明示的な開始APIで同じ経路に入ります。承認IDに一意制約があるため開始要求を再送しても制作は増えません。

以降のジョブは下書きではなく承認成果物のスナップショットを参照します。下書きを編集しても、既に制作中・公開済みの本文や採用素材は変わりません。M3では第1章だけを制作します。複数章の物語版の引き継ぎ・公開済み章からの改稿分岐はM4/M5の範囲です。

## プロットの明示表示

STEP4の折りたたみを開いた場合だけ、専用APIから採用済み本文の `outline` と人物名を取得します。全章の題名・役割・要約、結末、人物変化、伏線を表示し、本文や生成traceはこの応答に含めません。人物名は同じ制作版の承認設定と採用本文を参照し、後から編集した下書きとは混ぜません。

`narrative_artifact_id` が未設定なら待機表示とし、部分生成中のプロットは公開しません。開いたままの画面は2秒間隔の制作状況取得で採用を検知して表示を更新します。閉じた状態ではプロットを取得せず、プレイヤーにもプロットや未読章の情報を表示しません。この閲覧で追加の生成・承認は行いません。

## 原文と検査

シーン計画の人物IDは、承認済みメインキャラと生成済みサブキャラのIDをJSON Schemaの列挙値として渡し、候補から選択させます。本文生成前に、人物・場所の参照、人物・場所・シーン・必須イベントIDの重複、シーンID長、未使用の場所を検査します。不備があれば具体的な理由を渡して計画だけを一度再生成し、なお不正ならその計画要求をジョブの再試行開始位置にします。本文だけの再生成で不正な計画を使い続けません。新しい要求は旧形式の計画キャッシュとは区別し、同一要求の全体プロット・サブキャラ設定と完成済みZIPは引き続き再利用します。

LLMからの本文は `人物ID: 本文` または `NARRATOR: 本文` のプレーンテキストです。接頭辞と空行を構文として扱い、本文はプログラムで切り出して文字位置と安定IDを付けます。LLMによる演出・感情の付与は発話IDへの注釈です。

制御サーバーでも同じ解析を行い、話者・本文・読み上げ本文・順序・文字位置の完全一致を検査します。構造化結果で原文を欠落・複製・書き換えることはできません。レビューには各必須イベントの具体的な台詞と動作の根拠IDが必要です。形式上の正しさと意味上の物語品質は別であり、後者はLLMレビューと開発時の実読確認を併用します。

レビュー生成では台詞と地の文の根拠を別々の配列にし、実在する各種IDへ出力を制限します。根拠IDの取り違え・指定漏れは本文を保持してレビューだけ再試行し、内容そのものの不足が明示された場合だけ改稿します。修正前に採用可能だったレビューは入力・seed・schemaが完全一致するキャッシュから再利用し、正常なシーンの生成順序を変えません。

本文に人物IDの誤記やそのシーンに登録されていない話者が含まれた場合は、同じシーンを一度だけ形式修正します。この再試行ではGBNFで発話接頭辞を登場人物IDと `NARRATOR` に限定します。途中継続にも接続文字列を保持する文法を使い、本文を推測してつなぎ直すことはしません。正常な保存済み本文の要求は変更せず再利用します。

## 台詞とト書き

メインキャラ・サブキャラの代表台詞と自己紹介は、全体設計・本文生成・内容レビューの共通資料から除外します。人物設定と `voice` の口調・発話能力は引き継ぎ、場面に合う台詞を新しく生成します。サンプル文の転載や第1章での消化を要求しません。承認・試聴用の `sampleLines` / `selfIntroduction` は保持し、この方針変更で採用済み本文を再生成・修復しません。

人物行は実際に発声する台詞・鳴き声だけを生成し、動作・表情・無言の意思表示は自然な地の文へ分けます。人語を話さない設定はサンプル台詞の書式より優先します。M2の自己紹介・代表台詞とM3のサブキャラにも同じ生成指示を適用します。

本文生成後、人物行にある対応の取れた半角・全角の括弧部分だけを候補として分類します。実際に話す引用や補足はそのまま保持し、ト書きは主体を明示した `NARRATOR` の文へ、純粋な声の指示は非表示の `delivery` へ移します。動作・表情を含む指示が `delivery` に誤分類された場合は拒否して分類だけ再試行します。括弧の一律削除や台詞の書き直しは行いません。括弧の対応が崩れた部分は推測して切り取りません。

変換前の本文・候補位置・分類・変換後の本文・文字範囲の対応を生成traceへ保存し、その後で通常の解析・演出・内容レビューを行います。制御サーバーは変換後の本文と構造化結果の完全一致を引き続き検査します。地の文に音声は付けません。犬などの動作だけの行も地の文となり、実際の鳴き声だけが人物行に残る場合は音声の対象になります。`delivery` は演技情報として保持しますが、現在のTTS入力で直接制御するのは感情タグです。

公開済み章の修復CLIは、原文と演出・イベント根拠IDを対応付け直し、変更シーンの内容を再検査します。話者・台詞・感情・演技情報が完全一致する音声だけを再利用し、変更分だけを同じ承認済み基準音声で再生成します。採用時に元の制作版・全対象・素材のハッシュ・生成入力・参照音声を検査し、新しい本文と章buildを一つのDBトランザクションで登録します。旧build、元の本文・音声・ジョブ・承認版は保持し、変更前の対応表も監査成果物に保存します。

## 素材とジョブ

`m3_requirement` は章に必要な背景・人物画像・基準音声・発話別音声の対応表です。メインキャラの画像と音声は承認された版を参照し、サブキャラだけ設定から新規生成します。音声クローンは、基準音声成果物のID・ハッシュ・実際の原稿を固定します。

各素材を個別の永続ジョブで扱い、一件の結果ZIPを32MiB以内に制限します。背景は通常画像、人物は可視部分と透過背景を持つPNG、音声は完全なPCM WAVであることを確認します。台詞本文と声の感情、基準音声情報を生成記録と照合します。絵文字を含むTTS入力と表示本文は区別します。

M1のリース・heartbeat・再送・期限切れ管理を再利用します。生成完了の採用後、次のジョブを登録する直前に停止した場合は、制御サーバー再起動または状態取得時に未登録の工程を補います。

## 公開

立ち絵は元画像の縦横比を保持し、既定ではalpha 32以上の可視領域を基準に配置します。孤立した透過処理ノイズを除き、画像キャンバスの余白を人物の大きさに含めません。生成画像は全員768×1024でも、全身が個別に画面へ収められるため、画像のピクセル数だけでは実際の身長比を得られません。

M2とサブキャラの設定には `height_cm`（表示用の身長目安）と `body_type`（人型／人型以外／未判定）を保存します。明示された身長を優先し、未指定の人型は設定に合う目安を生成します。M2の外見確認で編集でき、外見ロックの対象です。身長だけの編集では素材を再生成しません。M3は人型を `framing=upper_body`、人型以外を `full_body` として中間脚本へ渡します。

人型の表示は本体の基準枠（未指定時は可視領域）の高さを設定身長へ換算し、章全体で同じpx/cmと足元座標を使います。背の高い人の頭頂に余白を設け、背の低い人の肩がメッセージ上端より上に来るよう、群全体の倍率を決めます。肩位置は頭頂から30%の近似で、姿勢や骨格を認識する処理ではありません。ウエスト位置を個別に揃えず、画像の頭身を維持します。人型と明示済みで身長だけ欠けた人物は170cmを目安とし、章内の身長が全員未設定なら旧表示を使います。群は章内で固定されるため、登退場で倍率が変化しません。

帽子や傘を含む輪郭で本体が小さくなる場合は、STEP4の「立ち絵の表示を調整」で本体の頭頂・足元・左右端を囲みます。任意の `body_bounds` は元画像全体に対する0〜1の四辺座標で、幅・高さはそれぞれ5%以上です。この枠を高さ換算、幅制限、水平中心、足元に共通使用し、設定身長は変えません。画像上の操作、四辺の数値入力、矢印キーによる移動で調整でき、「自動に戻す」で可視領域基準へ戻せます。枠は切り抜き範囲ではなく、元画像の帽子や持ち物もそのまま描画します。枠外の小物は画面外にはみ出すことを許容し、全体を収めるための再縮小は行いません。

旧設定の未判定キャラ（`framing=auto`）は、基準領域の幅／高さが0.60以下なら従来の上半身、それ以外なら全身を収める配置を継続します。これは種族判定ではありません。人型以外の明示設定は縦長でも全身表示とし、人型群の共通倍率に参加させません。

左右中央の配置と移動は基準領域の中心を揃え、幅の上限で隣接人物の本体への過度な重なりを抑えます。立ち絵の画像データは加工しません。表示方式を変更した版では保存領域も分け、旧配置の途中セーブを誤って復元しないようにします。

必要素材が揃うと、制御サーバーが原文対応と全素材の整合性を再検査し、`Script` を構成して決定的なZIPを作ります。章全体のZIPは個別ジョブの32MiB制限とは別です。組み立てに失敗しても既に採用した素材は保持し、再開時には組み立てだけをやり直します。

`chapter_build` の登録と脚本・ZIP成果物の登録を同時にコミットします。公開後のbuild更新はDBトリガーで拒否します。プレイヤーは公開buildのZIPに記録されたファイルだけを配信し、エンジンのみユーザー指定のV520から読み込みます。ZIPのmanifest、各ファイルのハッシュ、パス、音声のRange要求を検査します。

表示コードを更新した後は、公開済みの章を `rebuild` APIで組み立て直せます。承認版・採用本文・素材を再利用し、モデルの呼び出しや生成ジョブの追加は行いません。ZIPが変わった場合だけ新しいbuild版を公開し、制作画面は最新版へのリンクを返します。旧buildのURLとZIPは保持します。同じ出力の再要求は既存の版を返し、失敗時も既存の公開章を維持します。

`GET portraits` APIは公開済み脚本の人物・画像・構図・身長・本体基準枠を返します。`PUT portraits` APIは人物IDごとの表示設定を別の版付き成果物へ保存し、最新build IDの一致を検査して保存と再コンパイルを同じトランザクションで処理します。本体枠には元画像の `image_artifact_id` が必須で、保存時に現在の画像と照合します。後の組み立てで画像IDが変わっていた場合は古い枠を適用せず、自動の可視領域へ戻します。承認版・物語本文・画像データは書き換えません。新buildの検査記録に表示設定の成果物IDを残し、後の再組み立てでも同じ設定を使います。このAPIは指定した対応表全体を置換し、空配列で承認設定由来の表示へ戻せます。

公開ZIPには原文、構造化結果、公開用の承認設定、脚本、manifest、生成素材とアプリ所有のプレイヤー補助コードを含みます。ランタイム本体、モデル、API接続情報、生成機の絶対パスは書き出しません。

## 鑑賞操作

ティラノは舞台（背景・立ち絵・暗転）とシナリオの順序だけを受け持ちます。本文・話者名・音声・入力・ログ・設定・セーブは、アプリ所有の `player.js` が受け持ちます。ティラノのメッセージレイヤーは非表示のままで、ティラノ自身のクリック・キー処理は鑑賞画面が全面に重ねた層で受け止めて使いません。

シナリオ `first.ks` に著者の文字列は入りません。発話ごとに `[ad_line]`、`[ad_say]`、`[ad_wait]` という所有タグを出力し、`player.js` が発話IDで `script.json` から話者名と本文を引いて、テキストとしてDOMへ書き込みます。発話の前後の演出は従来どおりティラノのタグで、台詞の後の演出は `[ad_say]` と `[ad_wait]` の間で実行します。演出の待機はスキップと取り消しができるよう `[ad_pause]` にしています。

クリック・Enter・Spaceは、待機マークが出る前なら全文表示と待機マークの表示だけを行い、台詞音声は止めません。待機マークが出た後の操作で音声を止めて進みます。長い発話は文字の大きさに合わせて表示時に句点優先で改ページし、発話と音声は1つのままです。最後のページだけが音声の終わりを待ちます。

`data/others/auto_drama_states.json` に、各発話が始まる時点の背景・立ち絵・イベントCG・BGMを書き出します。ログの「ここへ戻る」、ロード、開始画面の「つづきから」は、この状態を舞台へ直接適用してから、その発話のラベルへジャンプします。その発話自身の登場演出や場面転換は通常どおり再生します。同じBGMの区間内へ戻るときは曲を鳴らしたままにします。ジャンプは本文の表示中・待機中・章末でのみ受け付け、演出や場面転換の最中には行いません。

セーブはティラノのセーブ機能を使わず、発話IDをブラウザーへ保存します。手動の1枠と、最も進んだ位置の自動記録を、章（公開版）ごとに持ちます。設定はブラウザー全体で共通です。

台詞音声はティラノ同梱のHowlerで再生します。録画ツールがHowlerの出力を取り込むためです。BGMは従来どおり `music.js` の独立した音量系統です。

公開済みZIPに入っている鑑賞画面は、公開時点のものです。制御サーバーの `/player/{build_id}/` は、ZIP内の `script.json` と画像から鑑賞画面用のファイル（`index.html`、シナリオ、設定、所有コード、状態データ）を実行中のコードで生成し直して返します。脚本・素材・公開文書はZIPに保存されたものをハッシュ検査のうえそのまま返します。このため、以前の鑑賞画面で公開した章も現在の画面で開きます。ZIPを直接ダウンロードした場合は、公開時点の画面のままです。

## API

| API | 用途 |
|---|---|
| `GET /api/m3/projects/{id}` | 制作状況、完成build、鑑賞・書き出しリンク |
| `GET /api/m3/projects/{id}/plot` | 採用済みプロットと人物名の閲覧用データ。未採用時はプロットなし |
| `POST /api/m3/projects/{id}/start` | 現在の承認版から冪等に開始／組み立て失敗の再開 |
| `POST /api/m3/projects/{id}/rebuild` | 公開章の採用済み本文・素材を使い、表示コードを更新して新しい版を組み立てる |
| `GET /api/m3/projects/{id}/portraits` | 公開版の人物・元画像・表示用身長・構図・本体基準枠を取得 |
| `PUT /api/m3/projects/{id}/portraits` | 最新build IDと枠の元画像IDを照合して表示設定を保存し、素材再生成なしで新しい版を組み立てる |
| `POST /api/jobs/{id}/retry` | 失敗した生成工程を、入力版を保って再試行 |
| `POST /api/m3/jobs/{id}/complete` | 有効なリースによる生成結果の検査と採用 |
| `GET /player/{build_id}/` | 指定ティラノ環境による公開章の鑑賞 |

現行のWeb画面は2秒間隔で状態を再取得します。再接続時も永続化した状態から復元します。SSE配信や停止・即時中断はM4以降の拡張です。
