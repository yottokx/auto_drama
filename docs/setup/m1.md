# M1：基盤・保存・最小の出力

M1では固定の短い脚本と図形の仮素材を使い、保存→ジョブ取得→変換→検証→ZIP取得を通します。GPU・モデル・外部APIの接続は不要です。サンプルに合成音声は含みませんが、中間脚本と変換器には音声参照があります。

## 起動

環境構築済みのリポジトリルートで、3つのPowerShellを開き、それぞれ実行します。

```powershell
.\scripts\start-coordinator.ps1
```

```powershell
.\scripts\start-worker.ps1
```

```powershell
.\scripts\start-web.ps1
```

[M1のWeb画面](http://127.0.0.1:5173/?view=m1)で「サンプルを作成して変換」を押します。ワーカー未起動なら「実行待ち」、正常に実行すると「完了」になり、ZIPを取得できます。中間JSONと固定素材も取得できます。画面の更新間隔は約2秒です。終了は各ターミナルのCtrl+Cです。ルートURLではM2のUIプレビューを表示します。

一件だけ処理する場合は `start-worker.ps1 -Once`。サーバーのポートを変更する場合は `start-coordinator.ps1 -Port 8001` と `start-worker.ps1 -Coordinator http://127.0.0.1:8001` を対応させ、Viteのproxyも合わせてください。通常は既定の8000を使用します。

保存先は既定でリポジトリの `data/` です。`start-coordinator.ps1 -DataDir 'D:\AutoDramaData'`、または環境変数 `AUTO_DRAMA_DATA_DIR` で変更できます。相対パスはリポジトリルート基準です。`config/environment.example.toml` は将来設定を含む参考用の雛形で、自動読込はしません。

APIとワーカー認証は同じPCでのローカル開発用です。ランチャーは127.0.0.1で待ち受けます。LAN向け登録・認証・素材キャッシュはM6で実装します。

## 出力の使用

ZIPには以下が含まれます。

- `script.json`: 変換元の中間脚本。
- `manifest.json`: schema版、素材参照、ファイルごとのサイズとSHA256。
- `data/scenario/first.ks` と `make.ks`: 決定的に生成したシナリオと初期化用ファイル。
- `data/bgimage/`、`data/fgimage/`、音声がある場合の `data/sound/`: 参照素材。
- `data/others/`: 鑑賞画面の固定コードと、各発話の開始時点の舞台状態。

ティラノ本体やそのサンプル、APIキー、ローカル絶対パスは含めません。既存のティラノ環境の作品用コピーを用意し、ZIPの `data/` をその作業領域へ配置して利用します。インストール先の原本を直接変更しないでください。サンプルは1280×720を前提にし、明示的な章末で停止します。Web UIからのプレイヤー起動・章の公開・次章への遷移はM3以降の対象です。

## 保存と復旧

`data/auto_drama.db` がメタデータ、`data/artifacts/objects/` がSHA256で配置する素材本体です。DBのマイグレーションは起動時にトランザクション内で適用し、適用済みSQLの改変や未知の新しいschemaは拒否します。SQLiteはWAL・外部キー・FULL同期を使用します。DBと素材ストアは同じ制御PCに置き、バックアップ時はサーバーとワーカーを止めて保存ディレクトリ全体をコピーします。

ジョブの状態は `pending → running → completed`。失敗・リース期限切れでは試行上限まで `pending` に戻り、上限で `failed` になります。「再試行」は履歴を消さず、もう一回分の試行を追加します。依存ジョブが完了するまでは後続を取得できません。M1のサンプルには変換ジョブが一件あります。

ワーカーのリースは既定60秒、通常のheartbeatは10秒間隔です。起動・ジョブ取得・状態取得時に期限切れを回収します。制御サーバーだけの再起動なら有効なリースは維持され、両方を停止した場合も期限後に再取得できます。完成済みジョブは再実行しません。期限切れの試行による結果は拒否し、同じ成功結果の再送は既存成果物を返します。

素材は一時 `.part` に書き込み、flush・fsync・ハッシュ確認・同じストア内のrenameを経てからDBへ登録します。変換ZIPは採用済み入力から再計算した期待値と比較し、成果物の登録とジョブの完了を一つのDBトランザクションで確定します。途中で停止して残った `.part` やDBに未登録のファイルは画面/APIへ公開しません。自動削除はM1では行いません。保存済みファイルの欠落・破損も配信時に検出します。

## APIと拡張点

[API仕様](http://127.0.0.1:8000/docs)から入力schemaを確認できます。

| API | 用途 |
|---|---|
| `POST /api/projects/demo` | 固定素材・脚本・ジョブを一括登録 |
| `GET /api/projects`、`GET /api/projects/{id}` | 作品・ジョブ・成果物の取得 |
| `POST /api/projects` | 作品を登録 |
| `POST /api/projects/{id}/scripts` | 検証済みJSONを新しい脚本版として保存 |
| `POST /api/projects/{id}/jobs` | 採用する脚本成果物ID・依存・優先度・試行上限を固定 |
| `GET /api/jobs/{id}`、`POST /api/jobs/{id}/retry` | 試行履歴の参照・失敗ジョブの再試行 |
| `GET /api/artifacts/{id}/content` | 確定済み成果物の取得 |
| `POST /api/workers`、`POST /api/workers/{id}/claim` | ローカルワーカー登録・排他的ジョブ取得 |
| `POST /api/jobs/{id}/heartbeat`、`fail`、`complete` | リース更新・失敗報告・ZIP返却 |

脚本schemaは `packages/contracts/script.schema.json`。現段階では素材を持たない脚本、または同じ作品に登録済みの固定素材を参照する改稿をAPIで保存できます。任意の新規画像・音声をアップロードするUI/APIは後続工程です。入力・公開設定と接続用秘密情報を混在させる機能は追加していません。

制御サーバーを実プロセスで起動し、ブラウザーから作った作品を、ワーカー専用venvの `start-worker.ps1 -Once` で変換することも確認しました。実行待ちでZIPを表示しないこと、完了を自動反映すること、JSON・ZIPのダウンロード、ページ再読込後の保存状態を確認済みです。デスクトップと幅390pxの画面で横方向のはみ出しはなく、API接続後のブラウザーコンソールに警告・エラーはありませんでした。確認用サーバーは終了し、検証データはGit対象外の `tmp/m1-browser/data/` に置いています。

Ruff検査・書式確認とWebのTypeScript・Vite本番ビルドも成功しました。M0のモデル生成はこの変更では再実行していません。
