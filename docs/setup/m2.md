# M2：世界観・キャラクター生成と初期承認

通常のWeb画面は制御サーバーに作品を保存し、ローカルワーカーで世界観、人物設定、透過立ち絵、基準音声を生成します。M0で固定したGemma / llama.cpp、Anima / Diffusers / isnet-anime、Irodoriの実環境を使います。外部LLM APIの接続はユーザー指定により後続作業です。

2026-09-22のユーザー判断によりM2は一旦完了です。生成結果の多様性と処理時間、用途別LLM設定は今後も調整します。次の作業への申し送りは [M2完了時の引継ぎと継続課題](#m2完了時の引継ぎと継続課題) を参照してください。

## 起動

プロジェクトルートで、別々のPowerShellから起動します。

```powershell
.\scripts\start-coordinator.ps1
.\scripts\start-worker.ps1
.\scripts\start-web.ps1
```

[M2画面](http://127.0.0.1:5173/)を開きます。ワーカーは起動時にモデルの配置を確認し、利用可能な生成処理だけを申告します。GPUライブラリは各専用環境の子プロセスに読み込み、同じPCのM2ワーカー間ではGPU使用を直列化します。モデルの準備は [M0の記録](m0.md) と各ランタイムの環境構築手順を参照してください。

通常ワーカーは連続する音声ジョブでIrodoriを再利用します。人物が変わっても参照音声・台詞・seedはジョブごとに渡し直します。保持中はGPUの排他ロックも維持し、キューが空になった時、非音声ジョブへ移る時、失敗・通信切断・終了時に子プロセスを終了してから解放します。連続保持が60秒を超えた場合も、処理中の台詞は完了させて次の台詞の前に再起動します。モデルのSHA256検証は起動ごとに行います。比較・診断時に以前の毎回起動方式を使う場合は `start-worker.ps1 -NoVoiceReuse` を指定してください。`-Once` は1件終了後に解放します。

M1の固定脚本出力は [既存画面](http://127.0.0.1:5173/?view=m1) で利用できます。M1だけを実行する場合は `start-worker.ps1 -ExportOnly` を指定できます。Webのみで結果の外観を確認する場合は [表示サンプル](http://127.0.0.1:5173/?demo=results) を開きます。サンプルの素材・設定は実作品と分離されています。

## 操作

1. **世界観とメインキャラを指示**：同じ画面で舞台・ジャンル・雰囲気と、1〜3人の人物像・関係性を入力します。人物の名前・年齢層・性別・役割はすべて任意で、自由記述だけでも進めます。指示をまとめて保存し、まず世界観だけを生成します。世界観生成は人物の希望も参照して舞台・制度を具体化し、未指定のメインキャラ設定を先に決めないようにします。
2. **世界観を確定**：完成結果を読み、直接編集や自然言語の修正指示で調整します。確定すると、その世界観と最初の人物指示を使って人物設定・立ち絵・声・関係性の生成が始まります。
3. **メインキャラを確定**：人物設定、自己紹介、代表台詞3つ、透過立ち絵、自己紹介の音声、全組の関係性を確認します。設定・外見・声の固定、人物全体／部分の修正、素材だけのリテイクができます。全員の設定・素材と関係性が揃ったら承認し、STEP4へ進みます。
4. **本編を制作・鑑賞**：承認後に始まる第1章の制作状況、失敗した工程の再試行、完成した章の鑑賞・書き出しを、この画面で扱います。

生成履歴と承認の記録は、各画面末尾の「生成履歴・承認の記録」を開いて確認します。初期設定の生成中や失敗時は、作業画面に進行状況と再試行ボタンを表示します。

立ち絵はクリックで拡大でき、閉じるボタンまたはEscapeで戻れます。ほかの人物が生成中でも、生成済みの人物は閲覧・拡大・試聴できます。関係性は人物単体の設定と分けて表示し、2人なら1組、3人なら3組を、未指示の組も含めて双方向で設定します。

最初の画面へ戻って指示を変更した場合は、世界観の確定を解除し、再生成・確認してからキャラ生成へ進みます。移動しただけ、または同じ入力を保存しただけでは確定を解除しません。制作済みの作品は、設定を再編集した後もSTEP4から完成した章を鑑賞できます。既存作品の入力・生成結果・素材・承認済みの版は保持され、旧「メインキャラを指示」の保存位置は統合した入力画面として開きます。

確認画面はHTMLの結果を先に表示し、編集フォームは操作したときだけ開きます。保存していない入力と生成済みの結果は別に扱います。入力変更が生成結果に未反映のまま承認されることを防ぎます。生成中は同じ作品への変更を止めますが、生成済みキャラの閲覧や別作品の閲覧は続けられます。

### 好きな台詞を同じ声で試す

声の欄の「この声で、好きな台詞を試す」を開き、台詞を入力して生成します。現在のサンプル音声をIrodoriの話者条件として使い、任意の台詞をボイスクローンで読み上げます。原稿は1,000文字以内で、モデルのトークン上限を超える場合は途中で切らずエラーとして通知します。

試した台詞と音声は各キャラの履歴に残ります。サンプル音声を置き換えず、承認済みの設定も変更しません。後でサンプル音声をリテイクした場合は、過去の試聴結果に「以前のサンプル音声で生成」と表示します。声が固定されていても台詞の試聴はできます。

自己紹介を編集すると、その本文を話すサンプル音声の再生成が必要になります。声を固定している間は、その音声に対応する自己紹介も維持します。代表台詞だけの編集はサンプル音声を変更しません。

### 関係性の調整

人物の設定欄は、その人自身の背景・性格・欲求などを扱います。主人公との関係や他のメインキャラへの感情は独立した関係性欄にまとめます。関係性の指示だけを修正して再生成する場合、人物設定・立ち絵・サンプル音声は維持します。人物設定やメンバーが変わった場合は、古い関係性を未反映として表示し、更新してから承認します。

追加前に作成した作品の設定と素材は保持されます。自己紹介・代表台詞がない既存キャラは、全体を再生成すると追加されます。設定または声を固定している場合は、先に該当の固定を解除してください。既存のサンプル音声も、実際の本文が記録されているものはボイスクローンの参照に使えます。

承認はM3に渡す設定・素材を確定する操作です。承認後はSTEP4「本編を制作・鑑賞」へ移り、第1章の自動制作が始まります。詳しくは [M3の使い方](m3.md) を参照してください。

## 保存・失敗時の再開

作品、設定、ジョブ、承認は既定の `data/` に保存されます。変更する場合は `start-coordinator.ps1 -DataDir <保存先>` を指定します。ブラウザーを閉じても生成は継続し、再度開くと作品ライブラリから再開できます。画面で保存していない編集中の文章はサーバーには保存されません。

処理失敗は画面に表示されます。ワーカーのログと対象ジョブのキャッシュを確認し、原因を解消して再試行します。同じジョブの再試行は乱数seedと入力スナップショットを維持し、保存済みのLLM応答・完成ZIPを再利用します。ユーザーが新しく生成・リテイクを指示した場合は別のジョブとseedになります。

ワーカーのキャッシュは `services/worker/cache/m2/jobs/<接続先の識別子>/<job_id>/` にあります。`job-request.json` が入力、`llm/` がLLM通信記録、`result.json` と `result.zip` が完了結果です。画像と音声の子プロセスログも同じジョブの下に保存します。`-WorkDir <保存先>` でキャッシュのルートを変更できます。入力や生成本文を含むため、キャッシュはGit対象外です。

ワーカーが中断した場合はリース失効後に再取得されます。古い試行や古い設定への結果を採用せず、完全なJSON・透過PNG・PCM WAVを検証してからDBの参照を更新します。完成前のファイルは確認画面の結果にはなりません。

## 生成設定と記録

`config/m2-generation.json` にLLMのモデルID・温度・出力長・推論設定、画像サイズとステップ数、声サンプルの本文などを指定します。現在の固定ローカルプロファイルは `reasoning_level: none` です。LLMと画像・音声モデルの取得元はM0のmanifestを引き継ぎます。

画像のモデル設定には `image.positive_prompt_prefix` と `image.negative_prompt` を用意しています。現在のAnima Baseには公式推奨の品質タグを接頭辞として設定し、ネガティブは公式推奨に立ち絵用の `cropped, text` を加えています。LLMは人物描写を作成し、品質タグはその後にプログラムが確実に付与します。いずれも任意の文字列へ変更でき、空文字で無効にできます。将来はモデル設定画面から編集する予定です。

設定は新しい生成ジョブの開始時に読み込み、再試行ではそのジョブに保存した値を使います。既存画像に適用する場合は「立ち絵だけリテイク」で新しいジョブを作成してください。生成記録の `provenance.image` に人物描写、適用した接頭辞、最終ポジティブ・ネガティブ、CFG・ステップ数を保存します。

世界観は、本文・設定・補足の指示があれば、それを土台に直接完成結果を生成します。それらが未指定の場合は、描写方針の候補・採用、具体案の候補・採用を経て舞台を具体化します。人物と関係性も、元指示と世界観・人物設定から直接生成します。指定された人物像や関係を、別の類型に選び直すための候補選択は行いません。候補選択がある場合は、LLMは必要に応じて整数乱数・一様抽選・重み付き抽選・重複なし抽選を呼び、実行はプログラムが行います。候補、採用理由、Tool引数・seed・結果を成果物に記録し、Toolの呼び出し数と引数を制限します。修正では既存結果を渡し、指定範囲外と固定済み項目をサーバー側でも保持します。

STEP1の明示指定・必須条件・禁止事項は、生成済みの世界観や候補より優先します。指定に矛盾しない肉付け・発展は許容し、後から明示された変更はその対象の要件だけを更新します。世界観・人物・関係性の生成と修正では、完成結果を元の指示と照合するLLM検査を行います。条件の欠落・矛盾・禁止事項への違反を検出した場合は最大2回修正して再検査し、解消しなければ結果を採用せず生成失敗として扱います。検査結果はtraceに残ります。

通常の確認は従来の総合検査1回とし、人物属性の専用検査や役割名の単語一致による追加の拒否は行いません。生成時に元指示の設定・行動・現在の状況を核とし、程度・頻度・確実性・時点も保って具体化します。候補のために新しい対立・弱点を作ることや、世界固有の制度を必須にはしません。文章化に元指示と適用済みの変更を直接渡し、生成途中の要約が元指示を置き換えることを抑えます。世界観は元の舞台と例外の範囲を保ち、人物は明示された振る舞いや好みを本文へ反映します。関係性は各方向の主体・相手の名前と役割を渡し、無主語の台詞ではなく人物名を用いた説明文で生成します。後からユーザーが明示した変更は、その新しい指定を優先します。

人物は設定・自己紹介・台詞を外見より先に生成し、創作した衣装の比喩を本人の肩書きに転用することを抑えます。関係性は入力された人物順を保ち、生成用のキーにも両者の名前を含めます。保存時のID整列では、従来どおり双方の関係文も同時に入れ替えます。目標は元指示を創作の土台として優先することであり、あらゆる入力の完全一致を保証するために拒否条件を追加することではありません。

適用に成功した修正指示と、結果を直接編集した項目は後続の生成・検査へ引き継ぎます。失敗した指示やAIが独自に追加した設定は、元の要件を上書きする根拠にはしません。
この引き継ぎ記録は更新後に採用した修正・直接編集から作成します。更新前の修正履歴は自動移行しないため、過去に変更した要件がある場合は現在の入力または新しい修正指示に明記してください。

生成品質はモデルの出力に依存します。M0で確認した音声の感情表現の制約は引き続きあります。承認前に実際の画像と音声を確認してください。

用途別にモデル・パラメータ・reasoningを設定できることは当初からの要件で、多様性や品質と生成時間の兼ね合いがその理由です。同じモデルを使う場合にも、メインキャラ、サブキャラ、本文、構造化、画像用変換などの用途で設定と生成戦略を選べる境界を保ちます。候補探索の段階数等は生成戦略、温度・出力上限・reasoning等はLLMの設定として区別し、重い設定をすべての用途に強制しません。

現状は `config/m2-generation.json` の共通 `llm` 設定を `M2Service._profile()` が各ジョブへ保存しています。用途別の設定解決と設定UIは未実装です。`LocalLLM` は `reasoning_level: none` 以外を拒否し、実リクエストにも `reasoning_effort: none` を送っています。現在の設定ファイルの値を変えるだけでreasoningを有効にできる状態ではありません。
