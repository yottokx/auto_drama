# M4：複数章の制作・停止・継続鑑賞

承認した章数に沿って本編を制作し、完成した章から鑑賞できます。前章の本文と終了状態が採用されると次章の本文生成を登録し、画像・音声は章ごとに揃えて順に公開します。制作途中の追加承認はありません。

## 起動と制作

M2・M3と同じローカルモデル、制御サーバー、ワーカー、Web UIを使います。更新後は制御サーバーとワーカーを再起動してください。起動時のDBマイグレーションで既存の制作・成果物・公開buildのIDを保持したまま章管理を追加します。

```powershell
.\scripts\start-coordinator.ps1
.\scripts\start-worker.ps1
.\scripts\start-web.ps1
```

1. [制作画面](http://127.0.0.1:5173/)で世界観・章数・メインキャラを指定し、世界観とキャストを承認します。
2. STEP4「本編を制作・鑑賞」で全章の進行を確認します。章ごとに本文の生成、素材の生成、鑑賞可能な状態を表示します。
3. 公開済みの章の「第N章を鑑賞する」を開きます。制作画面や鑑賞ページを閉じても、制御サーバーとワーカーが動いていれば制作は継続します。

次章の本文は前章の素材完成前に登録できます。一台のワーカーでは工程を順に実行するため、登録直後に次章生成が始まるとは限りません。前の章の素材ジョブを優先し、同一のサブキャラ画像・基準音声・背景要求には先行章の成果物を再利用します。

未読章の題名やプロットは章一覧と鑑賞ページに表示しません。「プロットを確認」と「制作の詳細を表示」には物語の内容が含まれます。

## 停止・中断・再開

| 操作 | 動作 |
|---|---|
| 工程を保存して停止 | 新しい工程の割り当てを止め、実行中の工程が完了するまで待ちます。完了した結果を保存して停止します。 |
| 今すぐ中断 | 実行中の試行のリースを失効させ、その結果を採用しません。ワーカーは次のリース確認で中断を検知し、その試行が起動したモデルプロセスを停止します。 |
| 制作を再開 | 保存した入力版・完成済み成果物を使い、未完了の工程から続けます。 |
| 第N章の工程を再試行 | 失敗したジョブを同じ入力版で再試行します。別の完成済みジョブは再実行しません。 |

「今すぐ中断」はボタンを押した瞬間のGPU停止を保証する操作ではありません。通常のリース確認間隔は10秒で、通信断がある場合は検知が遅れます。サーバー側では中断したリースの結果を直ちに拒否するため、遅れて届いた結果が再開後の版を上書きしません。

停止状態は制御サーバーの再起動後も保持します。実行中にサーバーやワーカーが終了した場合は、リース期限切れの処理と再取得で未完了ジョブを復旧します。完成済み成果物、公開ZIP、採用済みの原文は再生成しません。中断された工程の内部でも、条件が一致する保存済みLLM応答や完成済み結果があれば再利用します。

生成失敗と、完成素材の検査・組み立て失敗は区別します。前者は対象工程を再試行し、後者は「章の検査と組み立てを再試行」で保存済み素材から再検査します。

「変更履歴・元に戻す」で復元した途中状態は自動再開しません。その後に作られた章や素材がある場合、過去の状態からの再開を拒否します。制作を続けるには新しい履歴を選んでください。詳しくは[履歴の使い方](history.md)を参照してください。

## 章末の待機と保存

鑑賞中は、開いたbuild IDの本文・素材を使い続けます。後続章の完成や表示設定の更新によって、現在の章の内容は切り替わりません。

章末ではオート送りを止め、閲覧位置をブラウザーに保存します。次章が未完成なら、その位置で公開を待ちます。公開確認は5秒間隔で、通信に失敗しても現在の章を保持して再確認します。完成すると「次の章へ」が表示され、押した時点で接続できる公開版を再確認して進みます。最終章では終了を表示します。

途中の「途中保存」「続きから」と開始画面の再開ボタンも利用できます。保存データは作品・物語系列・章の制作ID・公開build ID・脚本上の位置を照合し、別の章や別の版の保存データを読み込みません。ブラウザーの保存領域を削除した場合や別のブラウザーを使った場合、保存位置は引き継がれません。旧M3の保存データを新版へ自動移植する機能はありません。旧公開版のURLは引き続き保持します。

音声再生、全文表示、バックログなどの基本操作とティラノ環境の指定は[M3の使い方](m3.md)を参照してください。

## 既存のM3作品を続ける

コードを更新した後は、旧制御サーバーと旧ワーカーをそれぞれの端末で `Ctrl+C` により終了してから起動し直してください。Web画面の自動更新だけではPython側は更新されません。`/api/health` が `stage: "m4"`、`schema_version: 4` を返すことが新版の目印です。旧サーバーが動いている場合は、制作画面に再起動の案内が表示されます。

起動時の `WinError 10048` は、指定したポートを既存のプロセスが使用していることを示します。起動スクリプトはアプリやDBを開く前にポートを検査し、旧サーバーの停止を案内します。別のアプリが使用している場合は、制御サーバーの `-Port` とワーカー・Webの接続先を合わせて変更します。

M3で完成済みの第1章は、アプリを更新しただけでは第2章以降の制作を始めません。STEP4の「制作を再開」を明示的に操作すると、承認時の章数に沿って続きの制作を始めます。

旧M3の本文には構造化した終了状態がありません。継続ジョブで採用済みの第1章本文から人物の状態・知識・伏線だけを抽出し、第2章の開始状態として検査・保存します。第1章の本文・画像・音声・旧ZIPは変更しません。旧版プレイヤーの章末には新しい次章待機UIがないため、続きはSTEP4の章リンクから開いてください。表示コードの再組み立てを行う場合も旧公開版を保持します。

旧サーバーを起動したまま更新し、その後に作られた公開版では、旧HTMLと新JavaScriptが混在して鑑賞画面が読み込み中のままになる場合がありました。この場合は再起動後に `POST /api/m3/projects/<作品ID>/rebuild` で既存素材から新しい公開版を作成し、制作画面の新しい鑑賞リンクを開きます。現在はプレイヤー資材をサーバー起動時に固定して版の混在を防ぎ、読み込み失敗や準備待ちの長期化も画面に表示します。

## 書き出し

STEP4の「第N章を書き出す」は、その公開版の中間脚本・原文・設定・素材・manifest・ティラノ用ソースを含む章単位のZIPです。ティラノ本体、モデル、接続用の秘密情報は含みません。

STEP4の「公開済みの章をまとめて書き出す」から、接続可能な公開済み章をまとめて取得できます。対応するAPIは、公開buildを起点に次の章をたどります。

```text
GET /api/m3/builds/<起点のbuild ID>/export
```

取得した `chapters.zip` には `chapter-001.zip` などの章別ZIPと、章順・build ID・SHA256・書き出し終端を記録した `chapters.json`、配置案内の `README.txt` が入ります。起点から連続して接続できる章だけを、その取得時点でまとめます。

この書き出しは章別ソースの集合です。複数章を自動で連結する静的プレイヤーは含みません。各章を `chapters.json` の順に配置・再生してください。静的配置された章の末尾には書き出し範囲の終了を表示し、制御サーバーへの次章確認は行いません。

## LLMのコンテキストと本文の保持

既定のコンテキストは16,384トークンのままです。状態抽出と章全体検査では本文を要約せず、同じ台詞の表示用・音声用の二重送信や、原文位置・音声注釈などの検査に不要なメタデータを取り除きます。全発話、話者、順序、根拠ID、人物別の知識、伏線は保持します。旧M3の前章から状態を推定する場合は、その状態と前章本文の照合を独立して行い、当章全文と一度に送信しません。

送信前に実モデルのトークナイザーで入力を測定し、設定された回答用トークン数と128トークンの余裕まで含めて枠内か確認します。なお超過する場合は工程名と内訳を表示して停止します。コンテキスト拡大、本文の切捨て、回答枠の縮小は自動では行いません。長い章や蓄積した状態でまだ収まらない場合は、その工程の分割を追加する必要があります。

成功済みの応答は入力が完全一致する場合に再利用します。状態の章番号や根拠の形式だけが不正な場合は状態抽出から再試行し、検査済み本文を作り直しません。実際の本文・状態の意味に矛盾が見つかった場合は、本文の修復が必要になることがあります。

## 検証範囲と残る確認

M4の実装は模擬ワーカー・固定の物語データ・プレイヤーのテストで検証します。対象は三章の連続制作、前章の版・状態の固定、通常停止、即時中断、再起動、失敗後の再試行、完成済み成果物の再利用、未完成次章の待機、保存位置の照合です。実装の保存境界とAPIは[設計資料](../architecture/m4.md)を参照してください。

2026-09-24の検証でPythonテスト718件、Webテスト31件、TypeScript・Viteビルド、Ruffが成功しました。旧M3互換・履歴・章境界プロンプトの追加テストもこの全体検証に含みます。

固定データを使う独立した検証用保存先で、実Edgeブラウザーとインストール済みティラノによる操作も確認しました。第1章公開後の通常停止・再開・即時中断でも鑑賞を継続でき、章末待機で保存してページを再読込すると同じ待機位置へ復元できました。第2・第3章の完成後も第1章のbuildとZIPを保持し、「次の章へ」を押して第2章へ移動できました。記録はGit対象外の `tmp/m4-browser-qa/report.json` です。通常のユーザー作品で新たな生成や再公開は行っていません。

その後の実作品の第2章で、状態抽出の入力18,421トークンによる16k超過を再現しました。重複除去と検査の分離により、最終版は状態抽出9,294・整合性検査10,062トークンとなり、実モデルで両方を通過しました。全96発話と既存の演出・シーン検査は再生成せず完全一致を確認し、完成済み第1章の124成果物も保持したまま、第2章の素材制作と第3章ジョブの登録へ進みました。記録は `tmp/m4-context/report.json` です。修正途中の全体検証740件に加え、最終変更後の関連108テストとRuffが成功しました。

三章を通した物語品質の読解・試聴は未実施です。知識漏洩や伏線の内容判断にはLLMレビューを使うため、機械的な参照検査だけで物語の正しさを保証するものではありません。より長い章や知識項目の多い作品では、入力予算の検査結果を見て追加の工程分割が必要になります。

軽量検証はプロジェクトルートで実行します。モデルは起動しません。

```powershell
.\.venv\Scripts\python.exe -m pytest -q --basetemp (Join-Path 'tmp' ('pytest-' + [guid]::NewGuid().ToString('N')))
.\.venv\Scripts\python.exe -m ruff check services packages scripts tests
Push-Location apps/web
npm.cmd run build
Pop-Location
```
