# 現行台本エンジンをアプリで使う

2026-09-26。統合前の状態は Git `327a84f` に保存した。

## 開始方法

制御サーバーとワーカーを終了し、通常の `scripts/start-coordinator.ps1` と
`scripts/start-worker.ps1` で起動し直す。ブラウザーも再読み込みする。
開発用Webサーバーは通常どおり起動する。

新しく作品を作るか、設定を編集してキャストを再承認し、新しい制作版を開始する。
今回から、新しい制作版の台本ジョブには `script_continuation_v1` を保存する。
同じ承認版の「再開」「再試行」は元の制作を続けるため、旧エンジンからは切り替わらない。
既存の本文、素材、鑑賞ページ、書き出しは保持される。

メイン1人の制作で発生していた `relationships` の参照エラーと、プロットの
`Plot core must identify the approved main cast exactly once` は修正した。
後者は人物IDだけでなく、生成する人物配列の件数も承認メイン人数に合わせる。
これらで停止した制作は、ワーカーを再起動して失敗工程を再試行する。再承認は不要。
旧プロットの人物配列エラーで再試行枠を使い切っている場合だけ、元の応答・使用量を残し、
修正版の形式で同工程を一度限り再開する。すでに採用したキャストと正常なプロットは再利用する。

章計画の `Only locations used by this chapter belong in its plan; unused: ...` については、
場面から参照されない場所定義を自動で除外する。元のLLM応答と除外記録は保存し、
使用中の背景や場面内容は変更しない。今回の失敗ジョブは、ワーカー再起動後の再試行で
保存済み章計画を再利用できる。未知の場所・人物への参照や、使用中のID重複は引き続き検証する。

## 生成と章の引き継ぎ

- 現行r14のプロット・キャスト計画、章計画、話者ID付き台本、発話分離、演出の処理を共有する。
- Gemma単独、reasoningなしを既定とする。細かな意味検査・修復ループは追加しない。
- 次章へ渡すのは全体プロット、保存済み実台本、出典付きメモ、導入済み人物・場所、使用量と執筆量の見積もり資料。
- チェックポイントは採用済み本文の成果物とともに保存し、次のジョブへ渡す。別ワーカーでも前章の作業ディレクトリは不要。
- 同じ章の中断・再試行では、ジョブの作業ディレクトリにある工程記録・応答・原稿を使う。完成済み工程を再生成しない。
- 台本の後は従来の背景・立ち絵・音声生成、Script組み立て、Tyrano公開へ進む。実験用の仮素材は使わない。
- 形式、話者、素材対応、章の参照元等は検証する。物語内容の合否は自動判定せず、公開記録にも「内容未評価」と残す。

3章の作劇を中心に調整したエンジンであり、章数を増やした場合の作品品質は別途評価する。
本文約4,000字・台詞約2,000字の目安を維持する。長さや内容を理由に自動で生成を繰り返す処理はない。

## コンテキスト設定

既定値は `config/m2-generation.json` の `llm.context_size`（16,384）。
32k・64kで試す場合は、新しい制作を始める前に同値を変更し、サーバーとワーカーを再起動する。
`max_context_size` / `model_context_size` を明示している環境では、それらも使用するモデルとGPUの容量に合わせる。
章計画・執筆などの出力上限は現行エンジンの工程別設定を使用し、M2の共通3,072 tokens制限では上書きしない。

制作途中でモデル・設定・プロトコルを変えた場合は、互換性のない履歴へ黙って継ぎ足さず停止する。
別設定を比較する際は、新しい制作版で試す。

## 検証範囲

LLMをスタブに置き換え、実ワーカー入口で3章を別ディレクトリへ生成し、プロット・本文・参照元・予算の持ち越し、
中断後の原稿再利用、成果物の再送、入力不一致の拒否、32k設定の適用を確認する。
API統合テストでは台本採用後の素材生成・3章公開・Tyrano ZIP・停止再開・旧方式の継続を確認する。
画像・音声を含む実モデルの通し生成は、この統合では実行しない。

統合時の結果：Python単体テスト1,400件、API統合テスト183件、Webテスト33件が成功。
Webビルド、変更したPythonファイルのRuff、実ワーカー環境でのimportも成功した。
