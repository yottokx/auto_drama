# Qwen Image 2.1 キャラクター画像テスト

プロジェクトルートの `qwen-image-test-gui.bat` をダブルクリックして起動します。Stable Audio実験と同じ独立Windows用Tkinter GUIです。画像生成は専用環境のDiffusers `QwenImage21Pipeline` と公式公開重みを使います。

## 準備

「環境・モデル準備」で「① 専用環境を準備」「② モデルを取得」の順に実行します。Python・PyTorch・Transformers・Diffusersは `services/worker/runtimes/qwen_image_edit/` に分離し、既存のAnima・音声環境と独立しています。モデルだけで約33GBあり、専用環境や生成画像の保存にも空き容量が必要です。ダウンロード途中のモデルは同じ保存先のステージへ置き、検証後に移動します。

このPCのRTX 5090・32GB VRAMでの初期設定はBF16・40ステップ・CPUオフロード有効です。視覚生成部以外にテキスト・画像エンコーダーとVAEもあるため、パラメーター数だけから全体がVRAMへ収まるとは判断しません。最初は立ち絵768×1152、一枚絵1024×576を使います。幅・高さは32px単位で指定します。

環境準備はCLIからも実行できます。

```powershell
.\scripts\setup-qwen-image-edit.ps1
```

モデルは公式リポジトリの確定リビジョンを取得し、全ファイルのSHA256と必須構成を検証した後に公開します。生成はオフラインで、その固定済みモデルだけを読み込みます。既存のモデルや実験結果を上書きしません。Hugging Faceの既存ログインは参照できますが、トークンを設定・生成記録に保存しません。利用条件は[公式モデルページ](https://huggingface.co/Qwen/Qwen-Image-2.1)で確認できます。

## 立ち絵の差分

1. 「立ち絵の差分」でPNG・JPEG・WebPを1枚追加します。
2. 表情・ポーズ・衣装のプリセットを選び、「テンプレートを入れる」を押します。
3. 最終の生成指示を編集し、生成します。例: 笑顔、怒り、腕を組む、手を振る、冬服。
4. 「比較・評価・履歴」で元画像と出力を比較します。透明部分は市松模様で表示します。

参照画像はEXIF方向を反映し、RGBAへ正規化して実験フォルダーへ固定します。元の立ち絵にRGB変換や背景除去を上書きしません。透明背景はモデルへの指示で、生成物のアルファ値を記録します。不透明な出力や全画素が透明な出力には警告を表示します。

生成結果を差分の参照にすると、現在の基準画像をその結果に置き換えて連続編集できます。各出力の親画像・実験・Seedを保存します。一貫性を比較するときは、元の立ち絵から毎回生成する条件と、生成物を続けて編集する条件を区別してください。

## 場面の一枚絵

「場面の一枚絵」で1〜10枚を追加します。参照画像は一覧の上から画像1・画像2…の順番です。人物名を付け、順番を変更できます。例: 「画像1の詩織は左、画像2の陽葵は右。夕方の喫茶店で同じノートを覗き込んでいる」。構図・動作・背景・人物ごとの役割を明示すると比較しやすくなります。

ローカル画像だけで実験でき、作品サーバーは不要です。作品から選ぶ場合はcoordinatorを起動し、作品一覧を更新します。実験専用の読み取りAPI `/api/image-experiments/projects/{id}` が、現在選択した制作版・調整版・凍結履歴の全章を一つのスナップショットとして返します。公開された後続章の脇役も一覧に含まれます。立ち絵と本文は公開版の参照へ固定し、閲覧に伴う制作再開・ジョブ追加・素材差し替えを行いません。

実装前から起動していたcoordinatorには新APIがないため、作品一覧でHTTP 404が出た場合はcoordinatorを起動し直してください。未公開素材はローカル画像から追加できます。

場面と登場人物の立ち絵を選び、「LLMで指示を作成」を押します。LLMが台本・場所・場面の目的を読み、一枚に描く瞬間を選んで、人物の動作・表情・視線・位置、背景・光・カメラの構図を英語の画像生成指示へ変換します。人物は参照画像の番号へ対応させ、元の顔・髪・衣装を参照で保つよう指示します。選択した参照人物のうち、その瞬間に登場しない人物を無理に画面へ入れないようにしています。

「LLMへの追加指示」で、例「リナを左、アイリスを右。操縦桿を握り直す瞬間。腰上の構図」などを指定できます。日本語の「LLMの場面解釈」と最終の英語指示を確認し、必要なら手直しして生成します。台本の本文・台詞・制作上の字数指示を画像モデルへ転載しません。LLMが有効な指示を返さない場合は一度再試行し、失敗を表示して現在の入力を保持します。

既定のLLMは「LLM設定」の `llama_cpp` です。本体で登録済みのGGUFモデルとllama-serverを再利用し、プロンプト作成だけの専用プロセスで読み込みます。本体のGPUロックを共有し、LLMを終了してGPUメモリーを解放した後で画像生成へ進めます。Ollama・OpenAI互換APIも選択できます。画像生成用のDiffusers環境へLLMをインストールする必要はありません。

場面を変えただけで生成指示を上書きしません。LLMの作成中に場面・参照・入力を変えた場合、その古い結果は画面へ適用しません。またLLM作成後に場面や参照順を変えた場合、未編集のLLM指示で生成する前に作り直しを案内します。自由入力だけで使うときは「参照番号を追加（手入力用）」で参照と人物名の対応を付けられます。

## 比較・評価

「Seed 0・1・2で比較」を選ぶと、同じ参照・指示・条件で3枚を順に生成します。全結果を残し、良い1枚だけから品質を判断しないようにします。KVキャッシュや前処理も出力に影響するため、同じSeedの比較ではこれらの設定を揃えます。

元画像と生成画像を並べ、拡大して、全体および参照人物ごとの評価とメモを保存できます。顔・目、髪、体格、衣装、画風、指示への適合、人物の混同、人数・手足を確認します。衣装変更の試験で衣装保持が対象外になる場合はN/Aを使います。生成成功・PNG保存・透明背景の有無は、キャラの一貫性を証明する評価ではありません。

最初の比較は、同じキャラの表情・ポーズ・衣装を別々に変える試験、2〜3人の場面で顔・衣装が混ざらないかの試験、連続編集で元のデザインから離れないかの試験を行います。

## 保存・停止

既定の保存先は `outputs/image-edit-tests/`、GUI設定は `private/image-edit/gui-settings.json` です。

| 保存物 | 内容 |
| --- | --- |
| `request.json` | 画面から確定した指示・設定・人物と場面の出典 |
| `inputs/reference-01.png` など | 実際に参照したRGBA画像の固定コピー |
| `outputs/image-01-seed-….png` | 各Seedの完成画像 |
| `generation.json` | 元画像と正規化画像のハッシュ、参照順、実Seed、モデル版、ライブラリ版、時間、VRAM、アルファ情報 |
| `status.json` / `result.json` | 処理の進捗と結果。中断時の完成済み画像も残す |
| `process.log` | モデル読込・推論・失敗の詳細 |
| `review.json` | 出力別・人物別の評価とメモ |

LLMによる指示作成も `scene-prompt-…/` に依頼・結果・ログを保存します。画像生成の `request.json` の `context.prompt_generation` に、その依頼の出典・場面解釈・モデル・LLM解放の確認を記録します。台本は出典として記録し、画像モデルへ送る `prompt` は変換後の画像指示だけです。

本体のGPUロックを共有して、他のローカル生成と順番に実行します。「停止」は実験自身の処理だけを中止します。バッチの途中で止めた場合、完成済み画像は「中断・一部」の履歴として読み込めます。推論・後片付けを終えてからGPUロックを解放し、生成プロセス終了でモデルを解放します。環境の依存インストール中に閉じる場合は、インストール完了まで待ちます。

## このPCでの実生成確認（2026-10-03）

専用環境とモデルは準備済みです。モデルはリビジョン `d26bb61231c349cf6b7896fa83353113880e1ba3` の26ファイル、合計33,131,615,131バイトを取得し、全ファイルのハッシュを検証しました。

公開済みの詩織・陽葵の立ち絵を読み取り、BF16・CPUオフロード・KVキャッシュ・40ステップで次を実行しました。元の素材や作品の制作状態は変更していません。

| 試験 | 解像度 | Seed | 推論時間 | 結果フォルダー（`outputs/image-edit-tests/` 内） |
| --- | --- | --- | --- | --- |
| 詩織の笑顔 | 768×1152 | 0 | 43.2秒 | `smoke-20261003-smile` |
| 詩織の腕組み、本とペンを除く | 768×1152 | 0 | 40.3秒 | `smoke-20261003-pose` |
| 詩織の冬服、クリーム色コートと赤マフラー | 768×1152 | 0 | 40.9秒 | `smoke-20261003-outfit` |
| 詩織・陽葵の夕方の喫茶店 | 1024×576 | 0 | 37.8秒 | `smoke-20261003-scene` |
| 詩織の笑顔を3枚比較 | 768×1152 | 0・1・2 | 42.9・28.5・26.1秒 | `smoke-20261003-smile-batch` |

時間はモデル検証・読み込みを除く推論部分です。笑顔3枚の実験全体は133.2秒でした。GPUメモリーの最大割り当ては約19.1〜19.6GiB、最大予約は約20.6〜21.6GiBです。完了後はプロセス終了とGPUメモリー解放を確認しました。笑顔のSeed 0は単独実行と3枚比較で同一のPNGハッシュとなり、この条件で再現しました。

目視では、差分の黒髪ボブ・青い目・衣装の特徴を保ち、透明背景も市松表示で確認できました。2人の場面でも髪・目・襟の特徴の混同は見当たりません。ただし陽葵の視線は本より観客側を向き、場面画像では下半身が写らないため衣装全体の保持は評価できません。背景のアルファは250〜255で、厳密な全画素255ではありません。少数の試験であり、大きなポーズ変更・3人以上・連続編集での一貫性は今後の比較対象です。

GUIの各タブと実結果の比較表示を確認し、関連テスト76件とRuffを通過しました。GUI画像は `outputs/image-edit-tests/ui-verification/` に保存しています。上記の実生成は「保存先から履歴を読込」で比較できます。

## 台本からのLLM変換の実生成確認（2026-10-04）

台本をそのまま入れて文字画像になった、リナ・アイリスの巡視艇コックピットの場面を同じ2枚の参照で再検証しました。GUIの「LLMで指示を作成」から、登録済み `gemma-4-31B-it-UD-Q4_K_XL` を使い、追加指示なしで作成しています。

LLMは「アイリスがホログラムで非効率な航路を指摘し、リナが不敵な笑みで操縦桿を握り直す瞬間」を選びました。台本を転記せず、人物を画像1・画像2に対応させた英語の画像指示と日本語の場面解釈を返しています。LLMの終了・GPU解放まで20.3秒でした。

そのまま同じGUIから1024×576・Seed 0・40ステップで生成し、コックピットで航路を指差す銀髪・紺制服のアイリスと、操縦桿を握る赤髪・緑制服のリナを確認しました。台本全体を描いた文字画像にはなっていません。画像の推論は40.4秒、モデル検証・読み込みを含め79.9秒です。終了後のGPUメモリー解放も確認しています。

LLM記録は `outputs/image-edit-tests/scene-prompt-20261004-002355-38ca5f62/`、生成結果は `outputs/image-edit-tests/scene-20261004-002416-5d043050/` です。画面と検証記録は `outputs/image-edit-tests/ui-verification/ui-llm-*.png` と `llm-scene-smoke.json` に保存しています。別の場面・参照でも同じ変換結果になる保証ではなく、各場面の解釈は生成前に確認してください。

関連テスト128件とRuffを通過しました。台本が画像指示へ入らないこと、不正なLLM回答の再試行と停止、GPU解放後の反映、入力変更やキャンセル時の保護、透明背景の指定後でも参照順の変更を検知することを確認しています。既に起動しているGUIは閉じて、ランチャーから開き直すとLLM機能が使えます。
