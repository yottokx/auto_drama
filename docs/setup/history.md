# 変更履歴・元に戻す

作品の設定、素材、本編を、保存済みの状態へまとめて戻せます。設定の保存・修正、素材のリテイク、本編制作、立ち絵の表示調整などを、操作ごとの履歴として残します。

## 利用前の準備

更新したコードを利用するには、制御サーバーを再起動してください。起動時に履歴用のデータベース構造を追加します。起動方法は [M2の手順](m2.md) と同じです。

```powershell
.\scripts\start-coordinator.ps1
```

履歴を初めて利用する既存作品は、その時点の状態を「履歴の保存を開始」として記録します。導入前の操作を推測して過去の履歴に追加することはありません。

## 操作方法

1. 作品を開き、STEP1〜STEP4のページ下部にある「変更履歴・元に戻す」を開きます。
2. 操作名と保存日時を確認します。「現在の状態」以外の履歴で「この状態に戻す」を選びます。
3. 画面内の確認欄で対象を確認し、「この履歴の状態に戻す」を実行します。世界観・人物・関係性・承認状態・立ち絵・音声・本編・表示設定を、選んだ時点へまとめて戻します。
4. 復元自体も新しい履歴に追加されます。後から行った変更の履歴は削除されません。戻しすぎた場合は、その後の履歴を選び直せます。

履歴は折りたたみを開いている間だけ更新します。STEP4で立ち絵の表示を保存した場合も、履歴を開いたままなら一覧に反映されます。復元には画像や音声の生成は伴いません。完成済みの章へ戻した場合は、STEP4の鑑賞・書き出しリンクも選んだ版へ切り替わります。

作品全体を戻すため、特定の人物だけ、立ち絵だけ、音声だけを戻す操作ではありません。復元直前に保存されていた変更は後の履歴から再び選べますが、画面上の未保存入力は先に保存するか取り消してください。立ち絵の枠を編集中の場合も、表示を保存するか「変更を取り消す」を実行してから復元します。

## 実行中・失敗時の扱い

- 生成ジョブが実行待ちまたは実行中の作品は復元できません。処理の完了または失敗を待ってから操作します。
- 一度の生成操作が複数の設定・画像・音声ジョブを含む場合も、ジョブが進むたびに履歴を増やしません。操作の完了、または途中での失敗時に状態を記録します。設定生成側と本編制作側は、それぞれの操作を独立してまとめます。
- 確認中に作品や履歴が更新された場合は、最新の状態でもう一度確認します。復元に失敗しても、画面で選んだ履歴や入力は保持します。必要な素材を確認できない場合は、現在の作品を変更せずエラーを表示します。

制作途中の履歴へ戻すと、その時点の状態を固定して表示します。画面を開くことや制御サーバーの再起動だけで、生成が自動再開されることはありません。完成した版を鑑賞したい場合は、後の完成済み履歴を選んでください。

制作途中の履歴を保存した後に同じ制作の本文や素材が変わっている場合、その古い途中状態から直接再開することはできません。再試行時には新しい履歴を選ぶ案内が表示されます。作業を続ける場合も、その後の履歴へ戻してから確認してください。

## 保存容量と保持されるもの

履歴には設定などの小さな状態データと、素材・公開済みの章を指す参照を保存します。履歴を追加したり復元したりするたびに、画像・音声・書き出しZIPをコピーすることはありません。同じ素材は各履歴から共有します。

履歴が増えると設定データと参照情報の容量は増えます。通常の生成やリテイク、章の組み立て直しで新しい成果物を作った場合は、その成果物分の容量が別に増えます。

公開済みの古い章やZIPは保持します。復元で作品の最新リンクが変わっても、既存の公開版URLは維持します。プレイヤーの途中保存・読書位置と、ここで扱う作品の変更履歴は別の機能です。

現在は一本の履歴から作品全体を戻す機能です。履歴の分岐、素材単位の復元、STEP2での作品複製は対象外です。

実装とAPIは [変更履歴の設計](../architecture/history.md) を参照してください。
