# 章の継続を優先する計画への立ち戻り

2026-09-26。ユーザーの「M3を3章出力した時の本質的な問題への対策に戻る」という指示を反映。

状態：直接場面計画を実装済み（prompt 11 / implementation 12 / contract revision 10）。実生成は第2章まで完了し、第3章本文の送信前に容量不足で停止した。[レビュー](experiments/script-continuation-r11-review-20260926.md)を受け、次は[コンテキスト配分と章間接続の改善計画](context-and-chapter-connection-plan.md)を適用する。この文書は、過去の計画のうち番号付き行動の配置・厳密な照合を優先する方針に代わる。

## 解く問題

M3の台本生成を複数章へ拡張した初期の作品では、章が進んでも前章の経験を受け継がず、導入を繰り返していた。[当時の調査](../tmp/m4-quality-audit/report.md)で確認したのは次の点。

- 同じ教室の導入と噂話を、各章の場面計画から繰り返している。
- 第1章末の7発話を第2章へ転載している。
- 第2章で回復した身体が、第3章で原因の説明なく悪化している。
- 前後の状態データは一致していても、その要約がプロットの写しで、実台本にある回復や約束を落としている。

主な対策は、次章の計画と執筆へ何を渡すかを直すこと。計画の形式検証を通過することを、章が進んだ証拠にはしない。

## 既に得られた足場

[台本継続PoCの初回レビュー](experiments/script-continuation-review-20260925.md)では、人物ID付き台本・演出・Tyrano出力を維持して3章を完遂し、導入の再演を避け、前章の結果から次章の行動が変わっていた。人物の過去の立場を誤って説明することや、後続場面の先取りは残ったため、作品品質の達成とはしない。別設定での再現性も未確認。

この時点の直接的な場面計画を土台にする。その後に加えた行動配置の表は、今回、第1章の本文に到達する前の停止原因になった。番号を修正し続けることを次の主課題にしない。

## 生成の流れ

1. **作品全体**：承認設定・キャストと関係を使い、全3章の具体的な展開と結末を一度定める。各章が何を受け取り、何が起こり、どんな結果を次章へ残すかを短く記す。現在の短いプロットの仕組みを利用し、ここを再び作り直すことは今回の主題にしない。
2. **第1章**：承認設定と第1章の予定から、M3同様に場面計画を直接作る。前章本文は存在しないため、過去本文の実施済み判定・差異修正を初章の必須回答にしない。
3. **第2章以降**：前章までの実台本と当章の予定を渡す。「今どこにいるか」「既に何が起き、何が変わったか」「その結果を受けて当章で何をするか」を短く整理し、そのまま場面計画へ進む。整理は章計画内の短い自然文とし、独立した検査・承認工程を加えない。
4. **場面の執筆**：当場面の人物・場所・予定する出来事・終了地点に加え、同章で既に生成した実台本と後続場面の担当を渡す。既出の会話や導入を転載せず、実際の直前の結果から続ける。後の場面の決着まで先取りしない。
5. **章の保存**：実台本、人物・場所の定義、発話・演出・Script/Tyrano出力を既存経路で保存する。その実台本を次章の過去資料にする。

未来はプロットから、過去は実台本から構成する原則を維持する。予定と違う出来事が本文に出た場合は、実際に起きたことを引き継ぎ、当章の未執筆部分でプロットの目的へ接続する。予定を実績として上書きしない。大きな逸脱時の全体プロット再編は今回の対象にしない。

## 章計画を簡単にする

- 場面計画そのものを、執筆する内容の唯一の直接指示にする。M3の `ScenePlan` にある場所・人物・目的・開始状態・`required_events`・終了状態を土台とする。
- `placements`、`step_number`、`handling` と別の場面説明を同時生成させる経路を外す。プロット行動の全件・一対一・順序の照合を本文開始の条件にしない。誤った番号をコードで推測して修正する対応もしない。
- 主筋の内容はプロットを資料として直接渡し、場面で描く出来事へ具体化させる。プロット通りに進んだかは、生成後の通読で評価する。
- 会話のための場面にも、独自の主筋の進展や対応するプロット番号を求めない。会話材料と場面の分量配分は保ち、場面の目的・出来事・終了状態の中で扱う。
- `current_facts`の細かな分類、人物別行動表、未来経路の置換表、未達一覧を全部そろえることを章計画の必須条件にしない。章間接続に必要な短い整理と場面計画にまとめる。既存の複雑な別経路へ切り替えるだけで済ませない。
- プロット・本文・引き継ぎを同じ出来事の独立した正本として増殖させない。詳細な引用ID・全件照合・常設の意味採点・修復ループを追加しない。

## 引き継ぎと検証

第2章以降は、収まる限り実台本の全文を一次資料として渡す。前章末8行だけ、またはプロット由来の状態要約だけには戻さない。前章の約束・既知の情報・回復や悪化・関係の変化も、実台本の内容から継承する。

古い章を省略する場合だけ、既存の本文由来メモを補助に使う。原文が入る場合は競合する要約を重ねず、直近の原文を優先する。メモに今後の展開案を混ぜない。16kは既定の目安とし、既存の設定に応じた拡張と記録付きの履歴選択を使う。本文・会話材料を任意の文字位置で切り取って続行しない。

生成中に必要な確認は、壊れた出力を防ぐ人物・場所参照、台本と発話の対応、演出・Script/Tyrano契約、保存済み成果物の同一性などに絞る。物語の進展を細かな検証項目へ分解して全合格を待つ構成に戻さない。技術的な修正回数の上限と具体的な失敗記録は維持する。

## 維持する体験と作業範囲

- 会話中心のビジュアルノベル、人物ID付き台詞とNARRATOR、発話分離、演出、人物・背景の素材要求、Script/Tyrano出力。
- 1話約10分、各話の本文約4,000字・台詞約2,000字という補助目安。短くなることを改善とは判定せず、M3当時の分量も比較する。
- プロット前のサブキャラ設計、気楽な掛け合いや日常場面、章に応じた出演者・場所の選択。場面に使った人物だけ素材要求へつなぐ。
- Gemma・reasoningなし、画像・音声なしの実験。既存の保存・明示的な再開、プロットだけの実行。

次の実装は実験用の章計画と、その前後の受け渡しを中心にする。`script_realization.py`の番号配置経路、`script_continuation.py`の章計画・執筆入力と保存、対応テストとprotocolが主な対象。既存の作品・失敗ログを変更せず、新しい実験で区別する。大規模な台帳、モデルによる自律的な工程管理、長編対応、素材の全面改修へ広げない。

## 次の評価

同じ「境界線のエクリプス」の承認設定・seed 1を使う。別設定への切り替えで効果を判断しない。最初の小規模確認では第1章の台本・会話量・技術出力を確認し、3章通し生成の前で一度報告する。

本質的な改善の判定は、指示を受けて生成した3章を通読し、次を確かめて行う。

1. 第2・3章が、同じ導入や初対面・既知の説明をやり直していないか。
2. 前章で交わした約束や決断、回復や悪化、関係の変化が、次章の行動へ反映されているか。
3. 前章末を転載せず、その後の展開を描いているか。
4. 第3章が積み重ねの結果として決着し、会話と各話の内容量も確保されているか。

これは生成後の通読評価であり、生成を止める新しいLLM検査ではない。第1章の成功や構造化出力のテストだけで、章間の問題が解決したとは報告しない。完了・失敗で停止したら、生成済み範囲と理由を報告し、コード変更と再実行を連続で重ねない。
